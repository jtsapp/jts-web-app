# CLAUDE.md — jts-web-app

Веб-версия Just to Study («раздел Практики»): Next.js-приложение с уроками,
IELTS-модулем и голосовым AI-тьютором. Это тот самый проект, куда идут
клиентские правки «Практики» (не mobile-app).

## Ветки

- **`develop`** — рабочая ветка: полная версия приложения (Обучение, Практика,
  IELTS, Словарь, Тьютор). Фичи и фиксы идут PR'ами сюда.
- **`main`** — прод. В `src/config.js` флаг `TUTOR_ONLY = false` (проверено по коду
  22.09.2026: `main` и `develop` побайтово совпадают; прежняя запись «main =
  только тьютор» устарела). Режим «только тьютор» включается той же строкой,
  если понадобится; при мерже develop → main конфликтов по этой строке нет.
- В тьютор-онли скрыты сайдбар-разделы и навигация на всё, кроме тьютора,
  входа и профиля; сами экраны и код остаются и открываются диплинком
  `?screen=…` для отладки.

**Деплой — GitLab CI, пайплайн рождает зеркало.** GitHub Action
`.github/workflows/mirror-to-gitlab.yml` на каждый push в `main`/`develop`
пушит ref в GitLab, там отрабатывает `.gitlab-ci.yml` (test → deploy). С
14.10.2026 `develop` катится на раннер `jts-dev` нового сервера, `main` — на
прежний `justtostudy.kz` (`GITLAB_RUNNER_TAG` в `workflow.rules`). Кнопка Retry
у нашего аккаунта GitLab не работает (не верифицирован), поэтому упавший
пайплайн перезапускается только новым коммитом в ветку. `Canceled` — не
поломка: новый push гасит ещё не начатый пайплайн той же ветки, деплоит
последний, в нём все коммиты. `fatal: … returned error: 500` при клоне в джобе —
это gitlab.com не отдал репозиторий раннеру (смотри status.gitlab.com), а не
зеркало: зеркало проверяется `gh run list --workflow mirror-to-gitlab.yml` и
сверкой `git ls-remote` обеих сторон.

## Временное скрытие разделов ученика на проде (28.10.2026)

`isStudentSectionHidden` в `src/config.js` закрывает на `ai-tutor.justtostudy.kz` токены,
призы, Feedback, уведомления, договоры и подбор учителя (включая мастер и шаг выбора).
Тот же список применяется к меню, прямым ссылкам, карточкам главной/уроков и профилю.
На dev и localhost эти разделы остаются доступны. При переносе новых кабинетов в main
сохранять эту проверку до отдельного решения владельца открыть разделы ученикам.
Перенаправление прямой ссылки выполняется после восстановления сессии, чтобы ученика
с действующей сессией не выбрасывало на приветствие при перезагрузке.

## Команды

```bash
npm run dev     # локальная разработка (next dev)
npm run build   # прод-сборка — гоняй перед PR, ловит ошибки импортов/SSR
npm run lint    # eslint 9 + eslint-config-next
npm test        # vitest run — юнит-тесты рядом с кодом (*.test.js/.jsx)
npm run test:e2e  # playwright — tests/*.spec.js, порт 3100 (override E2E_PORT)
```

Тест-раннер ЕСТЬ (эта строка раньше утверждала обратное): vitest для чистых
модулей и playwright для экранов. Проверка изменений = `npm run build` + `npm
run lint` + `npm test` + ручной прогон затронутого экрана (`npm run dev`,
диплинк `?screen=…`).

Моки POST-ручек бэкенда в e2e — регэкспом или глобом со `**` на конце
(`'**/auth/login**'`): с 18.10.2026 к каждому такому адресу дописан
`?jts_app=student` (`APP_PARAM` в api.js), и глоб `'**/auth/login'` молча не
срабатывает — запрос уходит на настоящий dev-server.

## Архитектура

**SPA внутри Next.js.** App Router используется только как оболочка:
`src/app/page.jsx` рендерит `src/App.jsx`, а навигация — это state-машина
`screen` внутри App.jsx (никакого Next-роутинга между экранами). Диплинк
`?screen=<name>` открывает экран напрямую — применяется эффектом ПОСЛЕ
гидратации, чтобы не ловить hydration mismatch (см. комментарий в App.jsx).
Новый экран = файл в `src/screens/` + импорт и ветка в App.jsx.

**JavaScript, не TypeScript.** Весь код — .js/.jsx (`jsconfig.json`). Не
добавлять TS-файлы.

**Слои:**
- `src/screens/` — экраны (Welcome/Otp/Learning/Ielts*/Tutor*/Kingdom* и т.д.)
- `src/components/` — общие компоненты (Shell, Sidebar, LearningLayout…)
- `src/tutor/` — компоненты и данные раздела «Тьютор» (tutors.js, scenarios.js)
- `src/practice/` — движки практики (fairytale, situations)
- `src/lib/` — серверные и общие утилиты; `src/lib/db/` — модули Neon
- `src/app/api/` — серверные роуты (auth, profile, voice, livekit, ielts, hl…)
- `src/api.js` — клиентский REST-обёртка к JTS-бэкенду
- `agent/` — отдельный Python-воркер LiveKit (Gemini Live), деплоится отдельно
- `scripts/` — генераторы данных (extract-fairytale.js, build-situations-data.js)

**Уроки «Обучения» — один плеер, два источника данных.** Урок в макете — это
очередь экранов (одно задание на экран, прогресс и сердца сверху), поэтому
рисует его `src/learning/CourseStepPlayer.jsx`, а источники только готовят ему
шаги:

- A0–B2 — self-study курс НОВОГО поколения: единый HTML-файл уровня
  (`jts-a0-course.html`, `jts-b1-intermediate.html`, `jts-b2-complete.html`),
  где урок объявлен как `LESSONS[n] = {…groups:[…]}` (у A-уровней — IIFE), а
  все записи лежат в base64 внутри файла. Режет его
  `scripts/extract-selfstudy-course.js` сразу в шаги плеера:
  `public/course/<level>/{index.json,steps-<n>.json,steps-T<u>.json,steps-X<id>.json,audio/}`.
  Разметку и движок курса не выгружаем — плееру они не нужны.

  Файл читается не регулярками, а выполняется в `node:vm` с заглушкой DOM
  (`scripts/selfstudy/read-course.js`): урок — не литерал, а IIFE, и внутри
  ссылается на локальные константы (INS, BANK, персонажи). Аудио уровни хранят
  по-разному — A0/A2 в `BLOBS`+`BANKS`, A1 в `<script type="text/plain">`,
  B1 в `BANK1…BANK12` (по банку на юнит), B2 в `AUDIO`, — и читатель сводит это
  к одному словарю. Раскладка «одно задание = экран» берётся из самого файла
  (`PER_ITEM`), кроме карточек слов: в плеере стадия словаря — одна сетка, а не
  стопка экранов по слову.

  Тесты уровни объявляют тремя способами: A0 — уроками `LESSONS[101…108]`,
  A2 — ревью `r1…r12`, B1 — отдельным `TESTS[юнит]` (инструкция задания там
  берётся из общей таблицы `T.ins[тип]`, иначе экран остаётся без задания),
  B2 — уроками `LESSONS[101…105]` плюс `MENU.tests` с полем `after`. Первые три
  дают узел тропы `T<u>`, последний — `X<id>` (после юнитов 3/6/9/12 и
  финальный, поэтому у одного юнита их бывает два).

  Вопрос к тексту в файле курса не несёт самого текста: движок печатает текст
  на каждом экране. У нас экран самостоятельный, поэтому экстрактор тащит
  материал в html вопроса — по ссылке `text:"t1"` (тексты лежат при уроке) и
  «эстафетой» с предыдущего экрана чтения (`MATERIAL_TYPES` в steps.js). Без
  этого 109 вопросов B1 и весь разбор тредов проверяли бы память, а не чтение.

  Флаг `keep` у задания значит «порядок вариантов осмысленный» (шкала, числа):
  плеер такие варианты не перемешивает.

  Поле `cue` (like / dislike, только A0 урок 1) — знак «да / нет» над
  заданием, где ключ зависит от отношения: «I ___ rain.» с like / don't like.
  Плеер значков курса не рисует, поэтому экстрактор ставит 👍/👎 первым в
  строку условия (`CUE_SIGNS` в steps.js); без него ученица, любящая дождь,
  получала «Неверный ответ». Где курс знака не поставил, а строка ключ не
  решает (A1 урок 1: «I ___ at university in 2015.» — was / wasn't), знак
  берётся из таблицы `scripts/selfstudy/cue-fixes.js`; правка, не нашедшая
  задания, останавливает сборку. Перебор A0–B2 (12.10.2026) других таких
  заданий не нашёл: остальные пары «да / нет» решает контекст строки.

  **Чтение — из оригинального курса, а не из self-study редакции** (29.09.2026,
  по просьбе методиста). У self-study свои, переписанные тексты, а у двух уроков
  чтения не было вовсе (A2-32, B1-13). Стадию Reading (у A1 — Read) оригинальных
  файлов (`A1_Elementary_final`, `A2_pre_inter_fixed`, `B1_inter_fixed`,
  `jts-b2_course_v5`; у A0 чтения нет) выгружает `scripts/import-course-reading.js`
  в `data/course-reading/<level>.json` — разметкой, только режим self; номер урока
  сверяется с темой урока сайта. При сборке `scripts/selfstudy/reading-steps.js`
  режет её в шаги (текст экраном, вопрос на экран с текстом над ним, стадия
  «Чтение»), а `lessonSteps` подменяет ими блок чтения self-study: от прогноза
  до первого экрана с записью; аудирование урока остаётся, объяснения навыка
  (`rule`/`expl`) тоже. Задания оригинала после записи учебника («Now listen…»)
  пропускаются — записей нет. «Отметьте все верные» — шаг `multi` в плеере.
  Итог: 68 уроков (A1 14, A2 17, B1 13, B2 24). Стадия «The model» (образцы
  писем) пока своя, self-study.

  Картинок слов в этом источнике нет вовсе (только имена иконок), поэтому фото
  карточек берутся из прошлой выгрузки — `public/course/<level>/img-index.json`
  плюс `img/`. Поиск — `scripts/selfstudy/card-photos.js`: не только точное
  слово («do homework» ↔ «homework», «rom com» ↔ «romcom»), но на снимке не
  должно быть слов, которых нет на карточке, — групповые постеры старого A0
  («Black, blue, brown, green», подпись вшита в картинку) на карточки одного
  слова не ставятся. Снимок чужого уровня берётся только при совпавшем
  переводе («suit» у B1 — «подходить», у A1 — «костюм»). Сами фото живут в
  файлах курса ПРОШЛОГО поколения (карта `IMG` у каждого урока) и докладываются
  в `img/` + `img-index.json` скриптом `scripts/import-course-images.js`
  (A1 — 417 картинок из `A1_Elementary_final_.html`, 28.09.2026). Он же кладёт
  перевод каждого снимка из строки словаря файла в `data/course-photos/<level>.json`
  — по нему снимок, чьё слово выпало из нового курса своего уровня, встаёт на
  карточку другого (так A0 получил картинки A1). Пары, которые правилами не
  поймать («work full-time» ← «full-time»), — в `ALIASES` там же, каждая
  сверена глазами. Итог: фото у A0 96/267, A1 279/344, A2 406/457, B1
  713/718, B2 716/716, остальные карточки — с иконкой курса. Не удаляй `img/`
  и `img-index.json` при пересборке; после импорта картинок пересобери все
  уровни — снимки ходят между ними.

  Задание «Послушайте. Выберите картинку.» (`pic`, и `listen` с `pics`) держит
  в вариантах как раз имена иконок (door, sun, clock) — без картинок оно теряет
  смысл. Набор иконок `I` курс везёт в себе же: читатель отдаёт его

  `optionIcons` параллельно `options`, а плеер рисует плитки без подписи —
  связывая иконку с вариантом по значению, потому что варианты перемешаны.
  Те же иконки стоят на карточке слова без фото (`icon`) и в «Match the words
  and the pictures» (`rightIcons`, пара сверяется по имени иконки) — но только

  национальности» случайны.
- Видео B2 в файл курса не вшито: задание ссылается на внешний

- C1 — остался на старом `LessonPlayer` (свои типы chips/watch, под шаги не

`KingdomInteriorPage` выбирает источник по каталогу: есть
`public/course/<level>/` — и тропа, и урок берутся оттуда (`steps-<n>.json`,
`steps-T<u>.json`), иначе работает старый путь через `public/learning/`
(`nativeLessonSteps`, остался у C1). Раньше у A0/A1 содержимое урока
подменялось нативным json, даже когда каталог курса был на месте, — из-за
этого правка в `steps-<n>.json` до экрана не доезжала (так 452 слова A1 три дня
читал браузерный синтез). Курс нового поколения подробнее нативных данных,
поэтому подмены больше нет. Старый экстрактор
`scripts/extract-kingdom-lessons.js` (hosted-Speakout с админки) остался
только под C1 — его прогон чистит весь `public/learning`, поэтому не
возвращай в его LEVELS ни A0/A1 (у них свой источник), ни A2/B1/B2 (они в
`public/course/`): он тихо положит Speakout поверх нового курса.

Озвучка словаря и связного материала генерируется отдельно
(`scripts/make-lesson-audio.js`, слова — Soniox, связные куски — Gemini или
`--narration soniox`, если service account Cloud TTS недоступен). Файлы лежат в
`public/learning/audio/<level>/`, имя — хэш самого текста. Привязка к заданиям
идёт во все источники: нативный json — `scripts/link-lesson-audio.js` (скрипт
генерации зовёт его сам), шаги курса — `scripts/extract-selfstudy-course.js`
(он ищет файл по слову и
ставит его и на карточку словаря, и на задание «слово на слух»: одно слово —
одна запись). Забыть привязку теперь не выйдет тихо:
`src/learning/nativeAudio.test.js` падает, если mp3 на диске есть, а задание
про него не знает.

Записи самого курса (диалоги, задания на слух) приезжают в файле уровня и
выгружаются в `public/course/<level>/audio/<хэш>.mp3` — их генерировать не
нужно.

Привязку этих записей файл курса местами делает неверно: клипы — нарезка
треков учебника по паузам, и у A0 задание получало соседний кусок трека
(«Когда Женский день?» — а звучит высадка на Луну) или клип, обрезанный до
ответа. Движок курса играет то же самое, так что это ошибка источника, а не
выгрузки. Чинит её экстрактор по таблице `scripts/selfstudy/clip-fixes.js`:
другой клип того же урока, кусок из целого трека прошлой выгрузки
(`data/course-clips/`, режет `scripts/selfstudy/cut-clip.js`) или озвучка
текста (`make-lesson-audio.js` берёт тексты оттуда же). Правка помнит хэш
клипа, который ставит курс: поменяется файл курса — пересборка остановится с
ошибкой, а не наложит правку вслепую. Ищется такое сверкой распознанного текста
записи с ответом задания; перед распознаванием подкладывайте тишину, иначе оно
глотает первое слово и целая запись выглядит обрезанной. Но каждое «обрезано»
перепроверяйте пословным распознаванием без подкладки: у коротких клипов она
местами съедала хвост, и три «пропажи» оказались ложными.

(его движок курса читает синтезом) — тоже через `voice-course-dialogs.js`.

**Финальный экзамен уровня — последний узел тропы «Обучения».** Источник
правды — standalone-тесты методиста `data/jtsexam-<level>.html` (есть A0, A1,
A2, B2; у B1 и C1 исходника нет — нет и узла). `node
scripts/extract-level-exams.js` исполняет прототип в `node:vm` и пишет
`public/exam/<level>/exam.json` — не в `public/course/<level>/`, потому что
`--prune` курса стирает там всё чужое. Рисует свой экран
`src/learning/LevelExam.jsx` на месте плеера урока (узел `EXAM`, юнит 0 —
открыт, когда в каталоге пройден весь курс уровня); подсчёт —
`src/learning/levelExam.js`, он сверяется с оракулом, который снимает сам
прототипный `showResults` (`src/learning/__fixtures__/level-exam-oracle-*.json`).

Берём только 50 авто-вопросов: говорение и письмо в оригинале проверяет
преподаватель вживую, и балл там считается без них. Варианты перемешаны
(`optionOrder`, стабильно по id): у методиста правильный ответ почти всегда в
одной позиции — у A1/A2 все ответы «Слов» первые. Записей аудирования в
исходниках нет, их делает `node scripts/voice-level-exams.js` (Soniox по
ролям, пауза — тихими кадрами в формате самой записи; имя — хэш стенограммы,

**«Чтение» в Практике — один прототип, 80 текстов, всё офлайн.** Источник
правды — `data/jtsreading.html` (standalone-прототип) — до заливки пакета на
стенд; после неё тексты живут в админке (см. «Материалы Практики переезжают в
админку» ниже). Данные режет `node scripts/extract-reading.js` в
`public/practice/reading/{<level>,dict,meta}.json`; рисует их экран
`?screen=reading` (`src/screens/ReadingPage.jsx` + `src/screens/reading/`),
движок — `src/practice/reading/`.

Текстов 80: пять уровней A1–C1 по шестнадцать, восемь жанров по десять.
Упражнений тринадцать типов, но механик всего пять (`engine.js`:
CHOICE/MATCH/ORDER + gap + reflection) — экраны ветвятся по механике, а не по
типу. Правильная пара и правильный порядок задаются СОВПАДЕНИЕМ ИНДЕКСОВ:
данные лежат в верном порядке, перемешивает их `initExercise`, поэтому
`shuffledIdx` обязан не оставить ни одного элемента на месте — иначе задание
иногда открывается уже решённым.

Порт сверяется с оракулом, который считает сам прототип
(`__fixtures__/oracle-<level>.json` — экстрактор выкусывает из html функции
`wordCount/readMin/sentences/exTotal` и гоняет их): красный `engine.test.js`
значит, что порт разъехался с исходником, и чинить надо порт. Резать html
регулярками нельзя — `exTotal` сам содержит `/\{[^}]+\}/`, поэтому выкусыватель
пропускает строки, комментарии и регэкспы (`sliceFunction`).

Свободный ответ (`reflection`) проверяется ЛОКАЛЬНО по ключевым идеям, без
LLM: раздел должен работать офлайн, а оценить язык — это к «Письму».
Тап по слову идёт тремя слоями: ключевые слова текста (там транскрипция) →
офлайн-словарь раздела (3799 статей с ru И kz, грузится с первого тапа) →
общий `src/lib/wordTranslate.js`. Казахского в сети не спрашиваем — портит.
Озвучка — голос воркбука (`src/practice/workbook/voice.js`: Soniox, запасной —
синтез устройства), по предложению за раз ради подсветки.
Карточка перевода лежит ВНУТРИ статьи (`position: absolute`), а не в окне: с
`fixed` её приходилось закрывать на скролле, и доводочный скролл браузера сразу
после тапа сносил её раньше, чем она успевала показаться.
XP прототипа не переносили (в приложении нет системы очков), свой переключатель
языка и тумблер тёмной темы — тоже: и то, и другое в приложении общее.

**«Слова в картинках» в Практике — визуальный словарь, всё своё и офлайн.**
Источник правды — `data/jtswords.html` (standalone-прототип). Данные режет
`node scripts/extract-words.js` в `public/practice/words/{meta,<section>}.json`,
картинки и записи забирает с чужого CDN `node scripts/fetch-words-assets.js`;
рисует их экран `?screen=words` (`src/screens/WordsPage.jsx` +
`src/screens/words/`), движок — `src/practice/words/`.

562 слова в пяти секциях (животные, еда, одежда, дом, тело) и 52 сцены.
Механика одна: голос называет слово по-английски, студент тапает картинку.
Пул сцены — её домашние слова плюс гости из соседней (`also`) — режется на
раунды по восемь (в портрете по шесть), визуально путаемые пары
(frog/toad, bee/wasp) разводятся по разным раундам.

Раскладку спрайтов считает `layout.js` — порт солвера прототипа: слоты
типизированы (g земля · b ветка · w вода · f воздух), совместимость только
вниз (`f→b→g`, `w→g`, `b→g`), перекрытия разводятся шестнадцатью проходами.
Солвер НЕ читает `document`: ориентация и случайность приходят аргументами —
иначе его нечем накрыть тестом. Порт сверяется с оракулом, который считает сам
прототип (`__fixtures__/oracle-<section>.json`, 52 сцены): красный
`layout.test.js`/`session.test.js` значит, что порт разъехался с исходником.

Два поведения прототипа зафиксированы как есть, а не «исправлены»:
разведение путаемых пар пасует на кластерах (у mouth четыре путаемых соседа),
и в маленьких сценах остаются mouth~teeth и hand~thumb; наземное слово при
нехватке земляных слотов садится на любой свободный.

Ассеты — свои: прототип ходил в CloudFront чужого аккаунта Higgsfield, где
один спрайт весит 4.3 МБ. Скрипт качает и пережимает (спрайты WebP 640px с
АЛЬФОЙ — они лежат поверх фона, фоны 1600px, обложки 800px, mp3 как есть):
1.1 ГБ → 42 МБ. Идемпотентен по `assets-manifest.json`.

Синтеза в разделе НЕТ: слово звучит только своей записью. Автоплей до первого
касания страницы браузер не пускает — это не сломанный файл, и кнопку «нет
записи» на `NotAllowedError` красить нельзя. Слова без картинки экстрактор
отбрасывает сам (donkey, clownfish), как это делает `hasArt` прототипа.

Перевод слова — только ru и kk, из данных; при английском интерфейсе перевода
нет вовсе (картинка и есть значение), а переключатель RU/KZ внутри раздела
работает при любом языке интерфейса. Прогресс — `{scenes: {<id>: {found,
done}}}`, найденные копятся между заходами; в домашнюю работу раздел не
отчитывается: у сцен нет CEFR-уровня.

**«Неправильные глаголы» в Практике — глава из трёх частей, всё офлайн.**
Источник правды — `data/jtsverbs.html` (прототип «verb-rap», 3.7 МБ, из них
3.5 МБ — записи форм в base64). Режет его `node scripts/extract-verbs.js` в
`public/practice/verbs/verbs.json` (90 глаголов в восьми группах, 60
предложений, 60 исправлений, созвучия распознавания, словарь тапа) и
`public/practice/verbs/audio/<форма>.wav` (210 записей); рисует экран
`?screen=verbs&part=learn|table|practice` (`src/screens/VerbsPage.jsx` +
`src/screens/verbs/`), движок — `src/practice/verbs/`.

Порт сверяется с оракулом, который считает сам прототип
(`__fixtures__/oracle.json`: схемы, `checkForm`, `scoreTargets`, очереди на
всех сочетаниях режим × формы × уровень × набор, фильтры таблицы). Странности
прототипа сохранены: распознанное сверяется ПОЗИЦИОННО («um be was been» — 0
из 3), gotten за got засчитывается только как V3.

Ритм держат часы AudioContext, а не таймеры (`beat.js` — порт `audio`
прототипа): удары и формы тьютора планируются на `ctx.currentTime`, таймер
только подкладывает порцию. Записи — WAV 16 кГц, не mp3 (задержка кодера
сдвинула бы форму с доли), разбираются своим `parseWav` и строятся в
AudioBuffer того же контекста. Машина попытки (`drill.js` — порт состояния
`P`) живёт вне React на жетоне: любой колбэк сверяет жетон и молча
отваливается, если попытка уже другая; экран подписан через
`useSyncExternalStore`. Контекст будится синхронно в клике (`beat.wake`,
`clips.wake`) — иначе iPhone молчит; бит и записи — одни на вкладку
(`sound.js`), и уходя с экрана раздел усыпляет контекст (`suspendAudio`):
разбуженный, он гнал бы аудиопоток по всему приложению. Таблица звучит теми же записями, а не
браузерным синтезом (выбор голоса и скорость прототипа сознательно убраны).
Микрофон — Web Speech API, как в грамматике; без него `repeat` остаётся
самопроверкой, `gap` — «показать ответ». Есть ли чем слушать, машина знает ДО
нажатия (`snap.canListen`) — без распознавания кнопок микрофона на экране нет
вовсе. Тумблер бита — настройка `beat`, а не «звучит ли сейчас» (прототип в
покое писал «выключен» при включённой настройке); послушать бит —
отдельная `togglePreview`. На телефоне настройки практики свёрнуты в
строку-сводку, а таблица перестроена в карточки — это CSS по ширине, разметка
одна.

Свой «Мой словарь» прототипа не перенесён: слово из предложения тапается,
перевод берётся из офлайн-словаря раздела (ru и kk), иначе из
`lib/wordTranslate.js` (только ru), и сохраняется в общий «Словарь» через
`saveReadingKeyword`. Прогресс — `{saved, progress}` в ключах прототипа
(`practice-v4-<режим>-<формы>-<уровень>`), синкается как `verbs` (replace);
настройки (темп, громкости, часть) — localStorage устройства. В домашнюю
работу раздел не отчитывается: area `verbs` бэкенду неизвестна.

**«Ситуации» в Практике — пять уровней, свой экран, разбор речи нашим стеком.**
Раздел A1–C1 по десять сценариев: видео-сценка, разбор реплик, задание и
устный ответ с разбором. До 20.09.2026 уровень открывался оверлеем с iframe на
`public/practice/situations/<level>.html` — приложение не знало, что внутри
(прохождение считалось по факту «открыл уровень»), оценка речи работала только
в Chrome (браузерный `webkitSpeechRecognition`), а грамматика уезжала на
публичный `api.languagetool.org`. Теперь экран нативный, как у «Чтения» и
«Глаголов».

Данные режет `node scripts/build-situations-data.js` — из тех же уровневых
страниц в `public/practice/situations/<level>.json`. Страницы остаются в репе
источником: исходного «ситуаций.html» (62 МБ с base64-видео, его резал
`scripts/extract-situations.js`) в репозитории нет. Схемы уровней РАЗНЫЕ —
прототипы писались в разное время: A1 — диалог и вопросы, A2/B2/C1 — сцена с
ролями (`who: scene|you|them`) и «миссией», B1 — своя смесь, B2/C1 добавляют
блоки critical/roleplay/followup. Экстрактор сводит пять форм к одной, чтобы
экран не спрашивал уровень. Промпт генерации видео (`higgsfield`) в данные не
переносится. У C1 страница пререндеренная, и в данных вместо путей стоит
`video: 1` — пути берутся из разметки по порядку.

Рисует `?screen=situations&level=<a1..c1>[&item=<1..10>]`
(`src/screens/SituationsPage.jsx` + `src/screens/situations/`), медиа (50 mp4 +
50 jpg, 45 МБ) лежит файлами. Переключателя уровней внутри экрана НЕТ
намеренно: уровень — единица квоты `PRACTICE_SITUATIONS`, её проверяет
Практика перед переходом (`openSituationsLevel`), а экран лишь отмечает
уровень открытым. Прохождение отдельных сценариев — отдельный локальный ключ
`jts_situations_items`: смешать его с ключом уровней значит списать студенту,
прошедшему 10 сценариев A1, десять уровней из квоты.

Разбор устного ответа — `POST /api/practice/situations/assess`: WAV 16 кГц
(до пяти минут) → параллельно `assessPronunciationChunked` (Azure, по аудио,
кусками по минуте с разрезом в паузах) и текст (`transcribeWavFast`; в регионе
без Fast Transcription — текст самой оценки произношения, фолбэк Soniox) →
грейдер на Sonnet (четыре оси, ошибки, советы; уровень идёт в промпт меркой —
ответ A1 нельзя судить планкой C1). Параллельно и кусками — потому что прод
стоит за Cloudflare, который рвёт запрос (524) после 100 секунд молчания:
цепочкой «потоковый текст → произношение» пять минут речи разбирались ~3
минуты, теперь ~25 с. Чем реально разбирали, пишет поле `engines` в ответе и
строка `situations_assess` в логе стенда; есть ли ключи Azure, без входа видно
в `GET` (`azure: true`). Итог собирает
`lib/situations/score.js` весами прототипа; без произношения вес оси
распределяется по остальным, а не обнуляется. Лимит — 20 разборов в сутки,
демо-аккаунту 5 (`lib/db/situationsBudget.js`, миграция 0010), списание ДО
платного вызова и возврат, если разбирать было нечего. Гостю разбор недоступен
(по device-id лимит обходится рестартом браузера), запись и самопроверка —
доступны. Зачёт сценария вешается на ЗАПИСЬ, а не на досмотренное видео: оно
может не проиграться, и студент остался бы без отметки.

**«Слушай и выбирай» в Практике — слышишь описание, выбираешь из четырёх фото.**
Источник правды — `data/jtslistenchoose.html` (прототип «Listen & Choose», 3.1 МБ,
из них 3 МБ — картинки в base64). Режет его `node scripts/extract-listenchoose.js`
в `public/practice/listenchoose/questions.json` (13 сцен по четыре подписи фото,
150 заданий — по 50 на easy/medium/hard) и `img/<сцена>-<n>-<320|512>.webp`
(104 файла); рисует экран `?screen=listenchoose&difficulty=easy|medium|hard`
(`src/screens/ListenChoosePage.jsx` + `src/screens/listenchoose/`), движок —
`src/practice/listenchoose/`.

Озвучка — ТОЛЬКО записи, голоса устройства нет вовсе: браузерный синтез в
приложении лотерея (eSpeak на Windows и Android), а запись даёт точную
длительность и перемотку. 150 mp3 (15 МБ) делает
`node scripts/make-listenchoose-audio.js` через Soniox (голос Owen, темп 0.95);
имя файла — хэш текста, поэтому правка описания в прототипе перегенерирует ровно
одну запись. `--dry` показывает план без запросов, существующие файлы без
`--force` не трогаются. Записи нет или она не загрузилась — плеер показывает
«Try again», молча заговорить синтезом раздел не может; `data.test.js` красный,
пока у какого-то задания записи нет.

Порт сверяется с оракулом, который считает сам прототип
(`__fixtures__/oracle.json`: очереди `sampleQuestions` на сетке сложность × размер
набора × «уже было» × предыдущая сцена и трассы событий `ListeningPlayer`).
Главная причуда — «дослушал» считается по РЕАЛЬНО проигранному (`player.js`):
перемотка вперёд, громкость 0 и «быстрее реального времени» диапазон не
наращивают, а запись засчитывается, когда на `ended` покрыто не меньше
`duration − 0.32 с`. Выбирать картинку нельзя, пока не дослушано и не
загрузились все четыре; попыток две, после первой ошибки верный ответ скрыт, а
прослушанное сбрасывается. Состояние экрана — класс `ListenChooseSession` вне
React (под `useSyncExternalStore`), поэтому e2e подменяет записи тихим mp3 через
`page.route`, и настоящий плеер проходит «послушал → выбрал» за полсекунды.

Прогресс: синкается только `{seen: {easy, medium, hard}}` (какие задания уже
показывали; модуль `listenchoose`, replace); недоигранный набор и настройки
(сложность, размер набора, темп, громкость) — localStorage устройства
(`jts_listenchoose_run`), их чистит `clearLocalPractice` вместе с прогрессом.
Каждое закрытое задание пишет `recordSkill('listening', с первой попытки)`; в
домашнюю работу раздел не отчитывается — area `listenchoose` бэкенду неизвестна.
Формулировка задания, названия сложностей и подписи плеера (Play, Stop, Replay)
английские во всех языках — это язык упражнения. Ключ раздела не `listening`:
он занят прежним Аудированием.

**Озвучка без записи — Soniox, а не браузерный синтез (с 23.09.2026).** Всё,
что раньше читал `speechSynthesis` (Словарь, Воркбук, Чтение, Грамматика,

остаётся и там, где Soniox упёрся в лимит: у Soniox лимит запросов в минуту на
ОРГАНИЗАЦИЮ, общую с голосом тьютора, поэтому новые синтезы ограничены
(`TTS_SONIOX_PER_MIN`, 50/мин на процесс, плюс лимит на адрес) — сверх отдаётся
429. Считаются только промахи кэша. Разделы с записями («Слушай и выбирай»,
«Слова в картинках», «Глаголы») синтеза не имели и не имеют.

**Комиксы в «Практике» — картинки, а не разметка, и приходят из API.** Каталог,
поиск и страницы веб берёт из `/mobile/comics`, `/mobile/comics/search?q=` и
`/mobile/comics/{id}` — контент заводит методист через админку, статической
копии в `public/` НЕТ намеренно (иначе два источника правды). Контракт
эндпоинтов и таблиц: `docs/superpowers/specs/2026-08-31-comics-api-contract.md`.
Форму ответа разбирает `src/practice/comics/comicsShape.js` — слой терпим к
именам полей, потому что контракт уже разошёлся с реализацией один раз
(читалку просили по slug, сделали по id).

Материал готовят экстракторы, а не руки: источник — PDF графического романа,
где каждая страница это белый лист с одной вшитой JPEG.
`scripts/extract-comics.js` (свой мини-парсер PDF 1.4, без внешних
зависимостей) достаёт растр как есть, срезает белое поле по яркости, жмёт в
WebP и складывает staging в `build/comics/<id>/`, а `scripts/lib/zip.js` (свой
писатель ZIP, тоже без зависимостей) пакует его в `build/comics/<id>.zip` —
именно этот архив заливают через админку. `build/` в gitignore.

Экстрактор адресует объекты PDF парой «номер поколение»: у этих файлов первая
страница лежит в поколении 1, и парсер, считавший поколение нулевым, тихо
съезжал на страницу и резал не тот кусок начала. Поэтому там же стоит сверка
числа найденных страниц с `/Count` — лучше упасть, чем залить брак.

Текстового слоя в PDF нет, поэтому реплики снимает зрение Claude
(`scripts/extract-comic-text.js` → `text-<id>.json` в тот же staging, архив
перепаковывается; прогон докатывается по страницам). Координаты баллонов у
модели ненадёжны — до половины рамок ложится на пустой рисунок, — поэтому
кликабельных зон поверх картинки НЕТ: читалка (`src/screens/ComicReader.jsx`)
показывает реплики колонкой в порядке чтения. Слово тапается через общий
`src/lib/wordTranslate.js` (тот же, что в «Книжках»), а перевод реплики целиком
приходит готовым вместе со страницей: сетевой переводчик комиксовый сленг
портит.

Закладка чтения помечается slug, а не id: id при перезаливке материала может
смениться, а место в книге терять нельзя.

Зум страницы пальцами (щипок, двойной тап) у читалки свой —
`src/practice/comics/usePinchZoom.js`, математика в `zoom.js`. Штатный зум
браузера на сцене погашен `touch-action`: он увеличивал всю страницу с шапкой,
а свайп и тап продолжали листать увеличенный лист.

Возрастного гейта у комиксов сейчас по сути нет. Веб умеет прятать карточки с
флагом `adultOnly` (`visibleComics` в `src/practice/comics/comicsData.js`;
через него идут и каталог, и поиск, а своей проверки у читалки нет — в неё
попадают только с карточки). Но бэкенд такого флага не хранит и не отдаёт: ни
колонки в `V203__Create_comics_tables.sql`, ни поля в `ComicResponse`, ни
галочки в админке (проверено 16.09.2026). `comicsShape.js` читает
отсутствующее поле как false, поэтому 18+ видят все. Вторая половина гейта —
заглушка: `PracticePage` передаёт ему `profile = null`, а `canSeeAdult`
считает неизвестный возраст отказом, так что с появлением флага такие комиксы
пропали бы у всех, включая взрослых. Причина, записанная в комментариях там
же и в спеке («бэкенд не отдаёт `birthDate`»), неверна: `/user/me` отдаёт
`birthDate` с 2025 года, и веб его читает (`src/lib/auth-server.js`, стейт
`birthDate` в App.jsx). В Практику дату просто не протянули.

У тьютора возрастного гейта тоже нет: кнопка «18+» — ось нрава calm/harsh,
а не фильтр контента. С 28.08 по 24.09.2026 она была заперта
несовершеннолетним (`isMinor()`, 403 `ADULT_ONLY` в `/api/profile`, harsh→calm
в токен-роуте LiveKit); замок снят по решению владельца, жёсткий нрав
включает любой ученик. Какое правило взять для комиксов — продуктовое
решение, отдельное от тьютора. И фильтр в вебе в любом варианте останется
витриной, а не защитой: `/mobile/comics*` браузер зовёт у бэкенда напрямую,
поэтому настоящий запрет по возрасту можно держать только там.

**Шэдоуинг в «Практике» — два источника уроков.** Вшитые уроки лежат файлами `public/shadowing/<id>.json` и
индексом `src/practice/shadowing/lessons.js` (их читает и серверный каталог для панели преподавателя). Урок,
который методист завёл в админке (Библиотека → Шэдоуинг), хранится в базе бэкенда (`shadowing_lessons`, фразы
JSON-строкой) и приезжает из `/mobile/shadowing` (каталог без фраз) и `/mobile/shadowing/{адрес}` (с фразами).
Склеивает их `src/practice/shadowing/catalog.js`: реестр уроков с хуком `useShadowingCatalog(token)`, а простым
функциям (`getLesson`, `hasLesson`, `lessonAvailable`) он доступен без пропсов. Правила, которые на этом держатся:
адрес админского урока создаёт бэкенд один раз и **всегда с дефисом** (`calm-talk-ab3k9`), у вшитых id дефиса нет —
так по одному id видно, откуда урок, и совпасть они не могут (`isRemoteLessonId`). `lessonContent.loadLessonFile(id,
token)` для админского читает бэкенд и приводит ответ к виду файла урока, кэш такого — 2 минуты (методист мог
поправить фразы). Пока список не доехал, ссылка на админский урок (домашняя работа, диплинк) не считается чужой
(`lessonAvailable`) и экран показывает «Загружаем урок…», а не первый вшитый; когда доехал и урока в нём нет
(скрыли, удалили) — кнопки в домашке нет, как и у любого несуществующего урока. Прогресс, записи, мастерство и
домашние работы ключуются тем же id, что и у вшитых. Оценке произношения (`/api/shadowing/assess`) список уроков
не нужен. Кабинет преподавателя берёт админские уроки у бэкенда сам: `GET /admin/shadowing/catalog`
(`PracticeCatalogService` в web-admin подмешивает их к каталогу сайта).

**Подбор учителя — сторона ученика (ТЗ 08, с 26.10.2026).** Спека —
`docs/superpowers/specs/2026-10-26-student-teacher-matching-design.md` (там же ТЗ, прототип — `data/jts-student-matching.html`).
Ученик сам выбирает учителя: «Формат → Время → Учитель» (без «Формата» у гарантии, IELTS, SAT), до трёх с
приоритетом, учитель предлагает время, ученик подтверждает; или «Пусть менеджер подберёт». Сервер — модуль
`matching` бэкенда (ручки `/student/matching/**`, v2 — карточка с `apiVersion: 2`); сайт — `src/matching/` и три
экрана: `?screen=my-teacher` (все статусы), `teacher-wizard` (мастер), `teacher-pick` (последний шаг онбординга
после итога теста и маршрута GE, один раз). Статуса на сайте нет — его выводит `matchingView` из карточки
(`matchingState.js`), и меню (пункт «Мой учитель» с бейджем), экран, профиль и окна при входе (`MatchingPopups`) не
могут разойтись. Карточка одна на вкладку (`matchingStore.js`, опрос 30 с; без подбора на стенде — раз в 10 мин, и
пункта меню нет). Слоты — UTC (`{weekday, start}`), на экране — в поясе ученика (`users.timezone`, иначе устройства),
«разные дни» — по дню школы, как на сервере (`slots.js`). Тексты — свой словарь `texts.js` (ru/kk/en), интересы
уходят на сервер русскими названиями ТЗ (`interests.js`). Ученик не видит телефона учителя, причин отказа и числа
его учеников; «Скачать PDF» резюме — печать листа браузером (серверный PDF печатает телефон). Тариф у ученика только
для чтения. Панель первой версии (`TeacherMatchingPanel`) убрана: «Главная» по ТЗ без изменений, в «Уроках» —
ссылка-карточка. Тесты, рисующие сайдбар с подменой `api.js` без `getStudentMatching`, падать не должны: стор
ловит и обращение к отсутствующей ручке мока.

**Отчёты о прогрессе (раздел Feedback) — сторона ученика.** Раз в 30 дней от
первого урока преподаватель пишет каждому ученику личный отчёт, координатор
одобряет, после этого отчёт уходит родителю в WhatsApp/Telegram и в кабинет
(решение руководства 20.10.2026: 30 дней вместо «каждые 7 уроков»). Форма
преподавателя и проверка — web-admin, рассылка и задачи — бэкенд; здесь только
то, что видят ученик и родитель. Контракт ручек —
`docs/superpowers/specs/2026-10-20-feedback-reports-student-design.md`.
Ссылка из мессенджера — маршрут `/report/<token>` без входа (как `trial/[token]`;
noindex, no-referrer), в кабинете — вкладка «Отчёты» в «Уроках»
(`src/feedback/ReportsTab.jsx`, только у ученика), новый отчёт — уведомление
`FEEDBACK_REPORT` (`deepLink: feedback-reports/<id>`) и карточка «Главной». Вид
один (`src/feedback/ReportView.jsx`) и снят с превью прототипа
`data/jts-progress-report.html`. Подписи — на языке ОТЧЁТА (`lang`), а не
интерфейса (`labels.js`); бейджи считает бэкенд, веб их только подписывает.
«Открыт»/«просмотрен» — отдельные POST после показа: мессенджеры сами ходят по
ссылкам. Ручки — на бэкенде (ветка `feat/feedback-reports`, backend#283); на
стенде со старым бэкендом 404 читается как «отчётов нет» и помнится 10 минут
(карточка «Главной» спрашивает на каждом заходе); вид смотрится на образце —
`?screen=lessons&tab=reports&reportSample=1` и `/report/sample`, только на
локалке и дев-стендах. В `theme-dark.generated.css` блок раздела вставлен
отдельно: полная перегенерация на 20.10 тянула чужие несведённые правки.

**Караоке в «Практике» — каталог из API, разметка приходит инлайном.** Каталог
берётся из `/mobile/karaoke`, а строки с таймкодами — из `/mobile/karaoke/{id}`
полем `lyrics`: в каталоге их нет намеренно (десятки килобайт на карточку,
которую список не читает), поэтому `karaokeData.js` доспрашивает трек при
открытии. Сама она лежит файлом в MinIO рядом с фонограммой
(`karaoke/<slug>/lyrics.json`), в базе только ссылка — текст туда класть незачем,
это десятки килобайт на трек. Но отдаёт её бэкенд телом ответа, а не ссылкой:
забрать объект напрямую браузер не может, на `fetch` нужен CORS у бакета,
которого там нет (аудио и обложке он не нужен — их тянут теги
`<audio>`/`<img>`). Разбор последних открытых треков лежит в памяти
(`KaraokeLyricsCache`), иначе каждое открытие стоило бы похода в хранилище.
Таблицы строк нет: строка караоке не единица редактирования, таймкоды правят
всем блоком после переразметки. Контракт (таблица, ручки,
формат файла): `docs/superpowers/specs/2026-09-03-karaoke-api-contract.md`.

Разметку не пишут руками: её собирает `scripts/make-karaoke-lyrics.js` из LRC
(в нём таймкоды и размечают — это выгружают LRC-редакторы и Audacity). Скрипт
берёт `duration` из самого mp3, а не из конца последней строки: по ней строятся
маски метрик, и на песне с длинным проигрышем в конце укороченная шкала завысила
бы и ритм, и покрытие. Конец строки в LRC не хранится вовсе — он выводится из
начала следующей записи (пустая метка `[mm:ss]` там значит паузу) и обрезается
потолком `--max-line`, иначе последняя строка куплета тянулась бы через весь
проигрыш и считалась бы неспетой. Результат скрипт прогоняет через тот же
`normalizeLyrics`, что и плеер, и не пишет файл, который приложение не примет.

Разметку валидирует `src/practice/karaoke/karaokeShape.js` — пересекающиеся
строки или `start >= end` делают трек непроигрываемым (экран показывает
сообщение, а не белый лист), кривые пословные таймкоды всего лишь гасят
пословную подсветку. Ровно те же правила стоят на бэкенде
(`KaraokeLyricsService`), и битый файл админка не принимает вовсе: методист
должен узнать о браке при заливке, а не от студента. Эти две копии обязаны
совпадать — их общий источник §3 контракта.

Оценка исполнения целиком в браузере (`src/practice/karaoke/scoring.js`):
покрытие и ритм считаются по бинарным маскам с шагом 50 мс (эталон из
таймкодов, студенческая из VAD по громкости микрофона), темп — по слогам.
Слова — единственное, что уходит в сеть: запись дубля один раз отправляется в
собственный `/api/transcribe` (Azure/Soniox), обратно приходит текст, дальше
WER. Web Speech API не используем намеренно: в Safari его нет, а ТЗ требует
iPhone. Если распознавание не ответило, балл считается по второму набору
весов, и экран результата честно об этом пишет. **Запись никуда не
сохраняется** — ни на диск, ни в JTS-бэкенд; обещание про это стоит на экране
до запроса разрешения, и ломать его нельзя.

**«Аркада» в Практике — зал из двух игр.** Карточка — секция `arcade` во
вкладках «Говорение» и «Чтение», последней перед сказками (правило «сказки —
последние» не нарушено); экран `?screen=arcade` — зал
(`src/screens/ArcadePage.jsx` + `src/screens/arcade/ArcadeHub.jsx`), прямо в
игру — `&game=speak|runner`. «Назад» из игры ведёт в зал, из зала — в ту
вкладку Практики, откуда пришли (`skill` едет в навигации).

**Speak or Die** — `src/screens/arcade/ArcadeGame.jsx`, движок —
`src/practice/arcade/`. Молчание гонит бензопилу к дереву за лимит сложности (12/10/5/2.5 с),
раунд 60 с; отгоняют пилу только РАСПОЗНАННЫЕ слова (Web Speech API), «э-э-э»
ловит акустика (`voiceFeatures.js`). Слово засчитывается, только пока голос
ещё и громче порога, а микрофон открыт БЕЗ автоусиления — поэтому порог
(`voiceActivity.js`) считается от пика гласных самого ученика, а не жёстким
полом: с полом 0.012 тихий ноутбук (речь ~0.006 RMS) давал «Тишину» весь
раунд при полностью распознанных словах. Без распознавателя (Firefox)
работает один порог громкости, и экран об этом пишет, советуя Chrome.
Наличию `webkitSpeechRecognition` не верим: Opera GX его отдаёт, принимает
`start()` и молчит — ни старта, ни слов, ни ошибки, и раунд целиком шёл
тишиной. Поэтому `transcript.js` сам проверяет поведение (нет `start` за 2 с
или 4 с голоса без единого слова → код `silent`, дальше порог громкости), а
экран до конца визита больше не ждёт слов от такого браузера. Язык игры — язык
интерфейса; темы Hard/Very Hard только английские, как в исходнике.

После раунда — окно «Анализ» (стенограмма с паузами, заминками и повторами,
целиком клиентская) и ИИ-разбор по кнопке: `POST /api/practice/arcade/review`
(Sonnet через `structured()`, промпт, схема и проверка ответа — общий
`reviewContract.js`). В модель уходит только ТЕКСТ, звук не записывается и не
отправляется. Тему клиент шлёт номером — текст берётся из своих данных, чтобы в
промпт не попадало ничего, кроме отгороженной тегами речи. Цитата, которой нет
в речи, выбрасывается. Гостю разбор не положен. Лимит — дневной, как у
«Ситуаций» (`lib/db/arcadeBudget.js`, миграция 0012): 20 в сутки, демо 5 —
константы `DAILY_LIMIT` / `DEMO_DAILY_LIMIT` там же (`Infinity` — без потолка).

**Word Rush** — 3D-бегун по трём дорожкам: сверху слово по-русски (в казахском
интерфейсе — по-казахски), впереди ряд из трёх ворот с английскими словами,
вбежать надо в перевод. 3 жизни, после верного ряда скорость ×1.04 до ×1.6;
сложности те же ключи, что у Speak or Die, но меняют уровень слов и время на
ответ (A1+A2 6 с, B1 4.5, B2 3.5, C1 2.5). Слова — из Словаря
(`public/practice/vocab/essential-*.json`, своего экстрактора нет). Правила —
`src/practice/arcade/runner/`: `deck.js` собирает ряд (ложные ворота той же
части речи и по возможности темы; части речи в Словаре записаны вразнобой —
`adj`/`adjective`, их приводит `normPos`; ложное слово с общим смыслом на языке
вопроса исключается, иначе у ряда два верных ответа; слово с ошибкой
возвращается через 5 рядов), `engine.js` двигает забег по кадрам. Оба под
vitest. Почти-синонимы с разными переводами в словаре (could «мог бы» / might
«может быть») колода не ловит — это предел данных.

Мир — three.js (`src/screens/arcade/runner/runnerScene.js`), грузится ТОЛЬКО
динамическим импортом с экрана игры: в общий бандл three не попадает (чанк
~650 КБ). Сцена правил не знает — `RunnerGame.jsx` отдаёт ей снимок каждый кадр.
Бегун — Higgsfield: картинка → Meshy image→3D с авто-ригом. Файл —
`public/arcade/runner/runner-v3.glb` (~1.1 МБ): сетка (10 392 треугольника),
риг и бег (RunFast 16) — ПЕРВОЙ выгрузки, а прыжок (Jump_Run 13), подкат
(slide_light 516) и спотыкание (sliding_stumble 519) перенесены на её скелет
`scripts/retarget-runner-clips.js` (`scripts/lib/retarget.js`, без
зависимостей). Почему не склейка: клипы Meshy отдал только на повторном
`3d_rigging`, а тот урезал сетку до 250 треугольников, оставил кисти без весов
и перепутал позвоночник (`neck` растёт из бёдер, шея — `Head1`). runner-v2.glb
(PR #539) склеил клипы с ЭТИМ ригом — бегун стал бумажным (жалоба владельца
01.10.2026). Перенос идёт мировым поворотом кости относительно позы покоя
(обе модели — одна фигура в одной позе), а не локальным: оси костей у ригов
разные. Источники в истории git: база — `fb0c6790:…/runner.glb`, клипы —
`44f7c39e:…/runner-v2.glb`, команда — в шапке скрипта. Повторный риг той же
модели проверяй по числу треугольников, прежде чем брать его сетку.
`scripts/merge-runner-clips.js` (склейка выгрузок ОДНОГО рига по именам,
`--alias Spine1=Head1`) остался для этого случая. Клипы длиннее позы и сняты не под неё (Jump_Run стартует уже в
воздухе, sliding_stumble — 11 с с падением и подъёмом), поэтому сцена играет из
каждого свой кусок (`CUTS` в `runnerScene.js`) и приводит бёдра к высоте бега —
по дорожке `Hips.position`, а не первой `.position`: она есть у каждой кости.
Препятствия (`barrier`/`boom`/`bus.glb`) — image→3D, сцена вписывает модель в
размер из правил. Ворота и город — кодом (неоновая трубка перекрашивается одним
`setHex`, у дома своя развёртка в мировых единицах — общая коробка со scale
растягивала окна). Уход с экрана зовёт `dispose()`: без него каждый заход
копил память видеокарты. Рекорд — localStorage (`jts_arcade_runner_best_v2`:
очки с 01.10.2026 в других единицах), на сервер ничего не уходит.

Слова ряда дублируются плашками в шапке под вопросом (порядок — по дорожкам,
дорожка бегуна подсвечена): вдали три таблички стоят на экране в ~20 px друг
от друга, и без плашек на чтение оставалась последняя секунда (жалоба
владельца 01.10.2026). Таблички на воротах шире дорожки не сделать — соседние
налезут; поэтому крупнее только кегль, фразы — в две строки.

Прыжок и подкат — позы движка (`jump` 0.9 с, `slide` 0.7 с); дуга прыжка на
сцене 1.5 (было 0.7 с и 0.7 — «не похоже на прыжок», владелец 01.10.2026).
Препятствия (`obstacles.js`: барьер — прыжком, шлагбаум — прыжком ИЛИ
подкатом, автобус — только обойти; перекладина шлагбаума на сцене опущена до
1.25, чтобы перепрыгнутый читался перепрыгнутым) раскладываются для подхода к
ряду N+1 в момент появления ряда N, ЗА его воротами: положи их вместе с рядом
N+1 — ближние возникали бы перед бегуном, а не выезжали из тумана. Последняя
треть пути перед воротами чистая, первый подход пустой (`WARMUP_ROWS = 2`).
Подход — 1–3 захода: одно препятствие, пара (третья дорожка свободна) или
стена во все три дорожки — только из барьеров и шлагбаумов, то есть
перепрыгиваемая. Место под оставшиеся заходы держится заранее, иначе первый,
упавший к концу отрезка, съедал остальных.

Монеты и турбо — `pickups.js`, поверх препятствий того же подхода: цепочка из
5 монет на дорожке (+2 очка за штуку), над барьером/шлагбаумом монета висит на
высоте дуги и берётся только прыжком (`high`), внутри автобуса не кладётся.
Молния-турбо (не чаще одной на подход): 3 с скорость ×1.5, препятствия
сносятся без удара (`smashed`, сцена их отбрасывает), верные ворота в турбо
×1.5 очков. Ворота в турбо подъезжают быстрее — меньше времени на чтение, это
цена бонуса. В e2e у поля есть `data-pickups` (как `data-obstacles`), а
`passRow` ждёт смены ряда, а не роста счёта: счёт растёт и от монеты.
Удар стоит скорости (×0.75, не ниже стартовой) и серии, но НЕ жизни — жизнь
только за незнание слова (решение владельца 01.10.2026). Поэтому очки —
`10 × скорость × множитель серии` (×2 с пятых подряд, до ×5): считай мы
ворота, удар был бы бесплатным, а медленный бег — выгодным. У поля
`touch-action: none`: вертикальный свайп — прыжок и подкат, а не прокрутка.

Web Audio, файлов нет (`src/screens/arcade/runner/runnerSound.js`). Движок о

Скорость звонка (16.10.2026, «как в Speaking Buddy»; первый живой звонок молчал ~9 с на старте и 4+ с на ответ).
Три причины и что с ними сделано: (1) потоковый TTS агента (blingfire) отдаёт предложение в синтез, только когда
пришёл кусок следующего, а браузер шлёт фразы по 120+ символов — первая фраза Луны ждала вторую; теперь после каждой
фразы `AssistantAgent.llm_node` шлёт `FlushSentinel`. (2) Упреждающая генерация включена и звонку (как у тьюторов):
вопрос уходит браузеру черновиком (`pending`) ещё до решения детектора конца хода; окно готовит ответ сразу, но в
переписке показывает ход только по `luna.commit`, а выброшенный черновик (`luna.cancel` с `drop`) следа не оставляет.
Рубильник без деплоя — секрет агента `LUNA_CALL_PREEMPTIVE=off`. (3) Профиль ученика (`studentContext.js`) раз в три
минуты собирался заново прямо на пути ответа; теперь протухший (до 15 мин) отдаётся сразу и освежается в фоне, сборки
не дублируются, а выдача токена звонка греет его заранее. Где теряется время в живом звонке — строка
`LATENCY luna first_phrase=… browser={…}` в `lk agent logs`: в `browser` замеры окна (`snap` — снимок экрана, `head` —
ответ роута пошёл, `phrase` — первая фраза) и `server` — Server-Timing роута (`auth`, `call`, `ctx`, `model`).

**Луна — преподаватель, а не справочное окно (15.10.2026, решение владельца).** Владелец: «он должен быть реальным
преподавателем» — видеть экран, говорить, что верно и что нет, советовать, какое задание сделать сейчас. Поэтому

его, а голосом — если звук не выключен (открытие окна — нажатие, iPhone звук разрешит). Пометка остаётся ходом ученика
в истории — иначе «да» на её первое «Открыть?» пришло бы без её реплики: разговор обязан начинаться с ученика.

приветствие с подсказками, без плашки. До проверки задания — только подсказка (решение владельца): не оценивать
введённое и не произносить ответ даже примером. Совет «что сделать сейчас» берётся из того же правила, что карточка
«Рекомендация дня» на «Главной» (`pickRecommendation` → строка «Совет сайта … (метка [[OPEN id]])» в профиле,
`adviceLine` в `studentContext.js`): без готовой метки Haiku треть раз советовала словами без кнопки. В контексте —
сегодняшняя дата: без неё модель называла срок через два дня «уже просроченным». В первой реплике переход — только
предложение: виджет снимает `now` с её метки, роут не пишет по ней поломку и не считает отказ «не по теме» (502 →
молча приветствие). Реплика начинается с имени ученика, а голос всего ответа выбирается по первой фразе, поэтому

заданный раньше, чем она договорила, обрывает реплику и уходит без неё. Правила первой реплики подбирались живым замером Haiku 4.5 (скрипт-зонд: chat API напрямую с

- **Режим рации** (`src/lib/pushToTalk.js` → metadata `pushToTalk`): ход
  открывает и закрывает ученик, поэтому детектора конца речи в сессии нет
  вовсе — `turn_detection="manual"`, а команды идут тремя RPC
  (`start_turn`/`end_turn`/`cancel_turn`, `src/tutor/usePushToTalk.js` ↔
  `entrypoint` агента). Микрофон при этом включён весь звонок: лишнее
  отбрасывает агент (`input.set_audio_enabled`), а мьютить трек на каждое
  нажатие — резать первый слог. С 01.10.2026 рация — режим ПО УМОЛЧАНИЮ
  (пустое хранилище = рация, `'0'` пишет только явное выключение), а
  переключатель «Рация | Свободно» стоит прямо в звонке: четвёртый RPC
  `set_turn_mode` (`src/tutor/useTurnMode.js`) меняет режим на лету
  (`session.update_options`), поэтому пороги перебивания задаются и в ручной
  ветке `_turn_handling`. Воркер катится отдельно, поэтому клиент обязан
  пережить `UNSUPPORTED_METHOD` — рация уходит на мьют трека, а переключатель
  пишет «со следующего звонка». Рубильник воркера — `PUSH_TO_TALK=off`.
  По отпусканию кнопки агент взводит у Soniox `finalize` (`finalize_now` в
  `noise_guard.py`, откат — `SONIOX_FINALIZE=off`, канарейка —
  `NOISE_GUARD_TUTORS`): при отцепленном входе Soniox сам фразу не закрывает, и
  `commit_user_turn` ждал финал до 2 с (живой звонок 01.10.2026: 1.4–2.6 с
  тишины после отпускания). Уходит команда НЕ сразу, а после 0.5 с нулей, которые
  досылает сам commit: мгновенный finalize обгонял кадры в очереди агента и
  съедал последнее слово («too.» вместо «too tired.» в 3 ходах из 4). На пустой
  `<fin>` (фраза ушла раньше) обёртка отдаёт пустой FINAL — иначе то же ожидание.
- **Шум и чужие голоса** (`agent/noise_guard.py`): поверх Krisp BVC стоит замок
  на ученика — Soniox размечает говорящих, и слова всех, кроме самого громкого
  (ученик у микрофона), выкидываются ДО склейки в реплику (`GuardedSonioxSTT`
  подменяет сокет плагина). Штатный `MultiSpeakerAdapter` не годится: плагин
  отдаёт реплике говорящего первого слова, и «телевизор + ученик» целиком уходило
  телевизору. Решает замок по ЦЕЛЫМ словам и на конце фразы (v2): решение по
  кускам слов вживую рвало слова («esterdched») — разметка прыгает внутри слова.
  Уровень говорящего — медиана его последних слов (v3): скользящее среднее
  вживую скакало, и телевизор забирал микрофон. Soniox расщепляет одного
  ученика на двух говорящих и путает его с фоном — отсюда «свой» говорящий
  (`SPEAKER_LOCK_SAME`) и слишком громкое для фона слово (`SPEAKER_LOCK_OUTLIER`).
  Пороги подбираются офлайн по записанным ответам Soniox (стенд записи и
  проигрывателя — в истории сессии 01.10.2026, см. память noise-guard).
  Сторож конца хода закрывает ход в «Свободно», если детектор голоса держит его
  на музыке, а слов ученика нет дольше `TURN_WATCHDOG_SEC` (1.2 с). Рубильники
  секретами воркера: `SPEAKER_LOCK=off`, `TURN_WATCHDOG_SEC=0`; канарейки —
  общая `NOISE_GUARD_TUTORS` и свои `SPEAKER_LOCK_TUTORS`/`TURN_WATCHDOG_TUTORS`
  (списки — только `--secrets-file`, в `--secrets` запятая делит пары). Слабое
  место: фраза, где говорит только фон, до первой реплики ученика проходит.
- **«Не понимает, о чём речь»** (`agent/noise_guard.py`, раздел «Контекст
  разговора и сомнительные слова», 13.10.2026) — два слоя поверх шума и эха,
  оба выключены по умолчанию. (1) Последняя реплика тьютора уходит в контекст
  Soniox (`general` — до 120 символов, `text` — до 240): без неё неясный звук
  ищется по всему словарю языка. Контекст Soniox берёт только при подключении
  сокета: в рации поток и так новый на каждый ход, в «Свободно» сокет
  переподключается, когда ученик молчит и его фраза у Soniox закрыта, и только
  ПОСЛЕ finalize → `<fin>` на последний отправленный finalize → 0.3 с тишины
  (детектор голоса отпускает ученика через 0.3 с, а Soniox держит фразу до
  2 с — без этого недосказанная фраза пропадала с сокетом; finalize при
  открытой фразе оборвал бы её на паузе). Не чаще раза в 3 с, повтор по таймеру
  и когда ученик замолчал. В контекст идёт реплика, которую
  тьютор ГОВОРИТ: `llm_node` отдаёт текст, а применяется он по началу речи
  (`begin_reply` сбрасывает несказанный — отменённую предварительную генерацию).
  Цена: контекст подтягивает ошибки ученика к форме вопроса («I watch it» на
  «Did you watch…?» → «I watched it»), инструкция Soniox «не исправляй» с
  вопросом не помогает — поэтому слой не включён.
  (2) Уверенность Soniox по каждому слову (худший кусок слова; плагин её
  усреднял и выбрасывал) — слова ниже `ASR_UNCERTAIN_CONF` дописываются к
  реплике ученика пометкой `[asr_uncertain: "…" — speech recognition may have
  misheard these words]`, только в копии истории для мозга (`_with_asr_note`).
  Имя — флаг пакета Speaking Buddy v3 (`latest_input.asr_uncertain`), другим
  промптам пометка объясняет себя сама. Границ хода у учёта нет: реплика
  выравнивается с хвостом распознанных слов (`difflib`), так что двойной вызов
  мозга (предварительная генерация) и отменённый ответ его не путают.
  Замер 13.10.2026 (синтез Soniox под розовым шумом, 46+10 фраз; scratchpad
  сессии, `dialog-bench/`): контекст — 0 дБ ничья (WER 0.044 / 0.042), −6 дБ
  0.435 → 0.345, слова вопроса в чужие ответы не вставлялись (0/8); ошибки
  ученика «исправлены» 2 → 3 из 16 (0 дБ) и 4 → 7 (−3 дБ). Пометка, мозг
  (24 ответа на ячейку, судья Sonnet 5.5 вслепую): «ругает ослышку как ошибку»
  Декстер Haiku 4.5 20 → 7, Луна 9 → 5, Buddy Haiku 5.5 16 → 11; «отвечает на
  ослышку как на сказанное» 11 → 4, 12 → 5, 12 → 7; на верных репликах лишних
  переспросов нет. Порог 0.5: на чистой речи помечено 12 из 106 верных реплик.
  Рубильники: `SONIOX_DIALOG_CONTEXT=on`,
  `ASR_UNCERTAIN=on`, канарейки `*_TUTORS` (иначе `NOISE_GUARD_TUTORS`), порог
  `ASR_UNCERTAIN_CONF`. Сводка звонка — строка `STT dialog:` в логе.
- Проект LiveKit один на дев и прод, и пара `LIVEKIT_API_KEY`/`_SECRET` у них
  ОБЩАЯ (эта строка раньше утверждала, что у каждого стенда свой ключ — неверно,
  и стоило одного ложного следа при разборе учёта минут). Значит подпись вебхука
  сходится на любом стенде, куда бы событие ни прилетело, и единственный способ
  не получить `room_finished` — не зарегистрировать URL стенда в проекте
  LiveKit. URL там должно быть ДВА; когда оба на месте, каждое событие летит на
  оба, и это безопасно — стенд находит комнату только в своей базе, чужое
  событие уходит в лог без списания.
- Повторение ошибок (`review_item`) двигает НЕ только `log_review`: модель зовёт
  его почти никогда — в проде на 03.09.2026 вышел один вызов на 56 строк, все
  56 висели в нулевой коробке с просроченным `due_at` и заезжали в промпт
  каждого звонка. Поэтому показ строки тьютору сам считается повторением
  (`touchServedReviews` в токен-роуте), а ошибка, уже стоящая в расписании, во
  второй блок промпта («Recent learner mistakes») не дублируется. Сопоставление
  «ярлык тьютора ↔ текст ошибки» — по токенам (`src/lib/db/reviewMatch.js`), а
  не подстрокой: ярлыки приходят в другом числе и в кавычках, и подстрочный
  отсев «пройденного» не срабатывал ни разу.
- Минуты считаются НЕ по жизни комнаты: платное окно — от подключения тьютора
  (`armed_at`) до последнего пульса вкладки (`last_seen_at`) плюс запас, см.
  `src/lib/usage.js`. Потерянный `room_finished` лимит больше не жжёт, он
  остался страховкой для комнат, где клиент не успел отметиться.
- Отметки жизненного цикла (`/api/livekit/session`) авторизуются ЗНАНИЕМ имени
  комнаты, а не присланным id: чей разговор — уже решил токен-роут, положив в
  `voice_session.device_id` тот же profileId, по которому считается лимит. У
  залогиненного это `user-<id>`, а не device-id браузера, и сверка с
  клиентским deviceId ломала тарификацию всем авторизованным.
- `src/app/api/hl/[...path]/route.js` — прокси Speakout-курса с
  files-dev.justtostudy.kz; ограничен `ALLOWED_PREFIX` и .html (SSRF-защита) —
  не расширять без причины.
