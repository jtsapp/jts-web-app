# Кэш озвучки Soniox в Redis

Дата: 2026-10-06. Ветка: `feat/tts-redis-cache`.

## Зачем

Кнопки «послушать» (Словарь, Воркбук, Чтение, Сказки, курс) читают текст через
`GET /api/tts` → Soniox (PR #491). Готовая запись кэшируется, чтобы одно слово
не оплачивать сотни раз. Но кэш лежит в `/tmp` контейнера, а CI на каждый
деплой делает `docker compose up --force-recreate` — контейнер новый, кэш
пустой, и всё синтезируется и оплачивается заново. Деплоев в день много.

Совет тимлида: хранить синтез в Redis, чтобы он переживал деплои и отдавался
всем ученикам без нового похода в Soniox.

## Решения

- **Redis — отдельный сервис в `compose.yaml`** рядом с Postgres: `redis:7-alpine`,
  у dev и прода свой (CI разводит их `-p jts-$APP_ENV`).
- **Наружу не открыт**: порт не пробрасываем, виден только `web` во внутренней
  сети compose. Пароль поэтому не нужен.
- **Переживает деплой**: AOF (`appendfsync everysec`) в volume
  `jts-web-app-redis` на `/data`. Пересоздание контейнера поднимает кэш с диска.
- **Лимит памяти** `--maxmemory ${TTS_REDIS_MAXMEMORY:-256mb}`,
  `allkeys-lru` — при переполнении выкидываются давно не слушанные записи.
  `mem_limit: 512m` контейнера — запас под fork при перезаписи AOF.
- **Адрес** — `REDIS_URL: ${REDIS_URL:-redis://redis:6379}` в `compose-app.yaml`;
  новых переменных в GitLab не нужно.
- **Срок жизни записи 90 дней** (`TTS_CACHE_TTL_DAYS`). Синтез иногда
  срывается (была рамка курса с 23 с бормотания); раньше брак смывал деплой,
  теперь — срок жизни или ручное удаление.
- **Вся `/api/tts`**, не только Словарь: точка одна на все разделы.

## Код

- `src/lib/redis.js` — `getRedis()`: `null`, если `REDIS_URL` не задан
  (как `getSql()`); иначе ленивый синглтон `ioredis` с
  `enableOfflineQueue: false` и коротким `commandTimeout` — пока Redis лежит,
  команды падают сразу, а не копятся. BOM в env срезается. На импорте не бросает.
- `src/lib/soniox-tts.js`:
  - `readCached(key)` — Redis есть → `getBuffer('tts:'+key)` с потолком 300 мс;
    ошибка или таймаут → `null` (промах, идём в Soniox). Redis нет → дисковый
    кэш, как сейчас (локалка, тесты).
  - `writeCached(key, buf)` — Redis есть → `SET … EX <ttl>`; ошибка → warn.
    Redis нет → диск.
  - `dropCached(keys)` — удалить записи (Redis `DEL` или файлы); вернуть число.
  - Redis задан, но недоступен → НЕ откатываемся на диск: два источника правды
    дали бы разный звук на одно слово.
- `src/app/api/tts/route.js`:
  - заголовок `X-TTS-Cache: hit | miss` (ожидание чужого синтеза того же текста
    — `hit`: платили не мы);
  - `DELETE /api/tts?t=…[&v=…][&l=…][&s=…]` под `x-internal-key`
    (`isTrustedInternalCaller`, fail-closed). Не указанный параметр = все его
    значения (голоса из `TTS_VOICES`, языки en/ru/kk, темп 0.7–1.3 шагом 0.05) —
    удаляет все варианты фразы одним `DEL`. Ответ `{ deleted }`, `no-store`.
    Текст — тот, что ушёл в синтез: для омографов это `reed`, а не `read`
    (RESPELL в `practice/vocab/audio.js`).
  - Браузер ученика держит свою копию до недели (`max-age=604800`) — это не
    меняется.

## Проверка

- vitest (`route.test.js` + `redis`-ветка с фейковым клиентом): чтение/запись
  через Redis, TTL, Redis бросает → Soniox, Redis висит → Soniox через 300 мс,
  `X-TTS-Cache`, `DELETE` без ключа 401 / с ключом удаляет все варианты,
  без `REDIS_URL` работает диск.
- `npm run build` + `npm run lint`.
- Живьём на dev после мержа: новое слово → `miss`, повтор → `hit`, после
  следующего деплоя → снова `hit` (кэш пережил деплой).

## 07.10: один Redis на dev и прод

Решение владельца: вместо Redis на каждый стенд — один общий, 256 МБ на всех.

- `compose-redis.yaml`, свой проект `jts-tts-redis`, внешняя сеть
  `jts-tts-redis`, алиас `tts-redis`; web обоих стендов входит в сеть,
  `REDIS_URL=redis://tts-redis:6379`.
- CI перед деплоем стенда: `docker network create … || true`, `up -d` общего
  Redis БЕЗ `--force-recreate` (с повтором через 5 с на гонку пайплайнов),
  удаление сироты `jts-$APP_ENV-redis-1` и её volume от #594.
- Цена: прод не изолирован от dev — запись, испорченная кодом с dev, звучит и
  на проде (лечится `DELETE /api/tts`); правка `compose-redis.yaml` в develop
  перезапускает Redis обоим; очистка кэша — общая.
