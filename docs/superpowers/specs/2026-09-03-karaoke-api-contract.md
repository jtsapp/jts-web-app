# Караоке: контракт API

Раздел «Караоке» в «Практике»: каталог треков, фонограммы и построчная
разметка с таймкодами.

**Статус на 04.09.2026: реализовано целиком.** Бэкенд — ветка `feat/karaoke`
в `backend` (миграция `V227__Create_karaoke_tracks.sql`, модуль
`modules/karaoke`, ручки `/admin/karaoke*` и `/mobile/karaoke*`), админка —
`feat/karaoke-admin` в `web-admin`, веб — `feat/karaoke-section` здесь.
Документ остаётся описанием контракта: по нему сверяются три клиента.

Решения, на которых стоит раздел:

- модуль сделан по образцу уже существующего `comic`: свой сервис хранения в
  MinIO под `karaoke/<slug>/`, `LanguageLevel` для уровня, теги строкой через
  запятую, списки без пагинации, `is_active = false` по умолчанию;
- разметка (строки с таймкодами) хранится **текстом в строке таблицы**, а не
  файлом в MinIO и не отдельными строками-записями;
- веб берёт треки **только из API**, статического фолбэка нет;
- запись голоса студента на бэкенд не попадает вообще (см. §7).

---

## 1. Что такое караоке-трек

Песня + разметка. Разметка — список строк с таймкодами (`start`/`end` в
секундах), по ним плеер подсвечивает текущую строку, а после исполнения
считает метрики. Одна песня = мини-урок на 10–15 минут.

Первая версия веба играет два режима: **Warm-up** (лексика до пения, без
микрофона) и **Full Karaoke** (цельное исполнение с оценкой). Остальные
режимы ТЗ (Hot Seat, Fill the Gap, Line Shuffle, Speed Run, Sound Zoom)
данными уже обеспечены — `hotspots`, `gaps`, `focus` лежат в той же
разметке, — поэтому вводить их отдельной миграцией потом не придётся.

**Правовое ограничение.** В библиотеку идут только собственные треки JTS и
public domain. Чужие фонограммы не хостим.

## 2. Таблица

`V227__Create_karaoke_tracks.sql`:

```sql
CREATE TABLE karaoke_tracks (
    id               BIGSERIAL PRIMARY KEY,
    slug             VARCHAR(120) NOT NULL UNIQUE,
    title            VARCHAR(500) NOT NULL,
    artist           VARCHAR(255),
    level            VARCHAR(10),
    tags             TEXT,
    bpm              INTEGER,
    duration_sec     INTEGER,
    line_count       INTEGER NOT NULL DEFAULT 0,
    cover_image_url  TEXT,
    audio_url        TEXT,
    instrumental_url TEXT,
    lyrics_json      TEXT,
    description_ru   TEXT,
    description_en   TEXT,
    description_kk   TEXT,
    order_index      INTEGER NOT NULL DEFAULT 0,
    is_active        BOOLEAN NOT NULL DEFAULT FALSE,
    created_at       TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMP
);

CREATE INDEX idx_karaoke_active_order ON karaoke_tracks (is_active, order_index, id);
```

Пояснения к неочевидному:

- `slug` — латиницей, `^[a-z0-9-]{2,120}$`; собирается из названия, если не
  задан руками (как у комиксов, с суффиксом `-2` при совпадении). Им веб
  помечает прогресс в `localStorage`, поэтому после публикации он меняться не
  должен: `id` при пересоздании карточки уедет, а прогресс студента останется
  висеть на старом ключе.
- `audio_url` / `instrumental_url` / `cover_image_url` — ссылки на объекты в
  MinIO, положенные `KaraokeStorageService` под `karaoke/<slug>/`. Минус
  необязателен; без него веб не показывает выбор фонограммы и не начисляет
  множитель ×1.15.
- `lyrics_json` — разметка как есть. **Отдельной таблицы строк нет
  намеренно:** строка караоке не единица редактирования, таймкоды правятся
  всем блоком после переразметки, и CRUD по строкам никому не нужен. Цена
  решения: правка одной опечатки = перезаливка всего файла. Это принято.
- `line_count` — денормализация ради списка в админке и карточки в каталоге:
  каталог не должен тянуть разметку, чтобы показать «строк: 24». Заполняется
  на заливке разметки.
- `tags` — теги грамматики через запятую (`past-simple,weather`). Отдельной
  таблицей не делаем: по ним пока только фильтруют глазами.

## 3. Формат разметки (`lyrics.json`)

Файл, который методист заливает в поле «Разметка».

```json
{
  "version": 1,
  "slug": "rainy-monday",
  "duration": 168.5,
  "vocab": [
    { "w": "umbrella", "ru": "зонт", "line": 3 },
    { "w": "on my way", "ru": "по дороге", "line": 7 }
  ],
  "lines": [
    {
      "id": 1,
      "start": 12.40,
      "end": 16.10,
      "text": "I woke up on a rainy Monday",
      "ru": "Я проснулся дождливым понедельником",
      "words": [
        { "w": "I", "t": 12.40 },
        { "w": "woke", "t": 12.62 },
        { "w": "up", "t": 12.95 }
      ],
      "focus": ["ed-ending", "linking:woke-up"],
      "gaps": [1]
    }
  ],
  "hotspots": [
    { "afterLine": 4, "durationSec": 6.0, "returnAt": 41.2, "difficulty": 2 }
  ]
}
```

**Обязательное:** `lines[]`, у каждой — `start`, `end`, `text`.
**Опциональное:** всё остальное. Без `words[]` подсветка идёт заливкой строки
целиком, без `ru` — кнопка перевода не показывается, без `vocab` — Warm-up у
трека недоступен.

**Правила валидности.** Проверяются дважды: на заливке
(`KaraokeLyricsService` на бэкенде) и при загрузке в плеере
(`karaokeShape.js`). Обе копии обязаны совпадать, и этот раздел — их
источник.

Фатальные (трек не играется вовсе, заливка отбивается `400`):

1. `lines` пустой;
2. у строки нет `start`/`end`, либо `start < 0`, либо `start >= end`;
3. пустой `text`;
4. строки пересекаются (`start` следующей меньше `end` предыдущей).

Поправимые (заливка проходит, приходит в `warnings`):

5. `words[].t` вне `[start, end]` своей строки или убывают — пословная
   подсветка гасится, строка подсвечивается целиком;
6. `hotspots[].returnAt` не попадает в паузу — hotspot выбрасывается;
7. нет `vocab` — у трека не будет режима «Разогрев».

Сообщение об ошибках обрезается восемью пунктами: криво нарезанный файл даёт
их сотнями, и читать такое невозможно.

## 4. Заливка файлов

Общий `/media/upload` **не используется**: у модуля свои ручки, поэтому файлы
ложатся под `karaoke/<slug>/` и перезаливка заменяет их на месте, а не плодит
объекты с uuid в имени.

| Ручка | Что кладёт | Куда в MinIO |
|---|---|---|
| `POST /admin/karaoke/upload` | всё сразу: метаданные + `audio`, `instrumental`, `cover`, `lyrics` | `karaoke/<slug>/…` |
| `POST /admin/karaoke/{id}/upload-audio` | поле `audio`, флаг `instrumental` | `karaoke/<slug>/audio.<ext>` или `instrumental.<ext>` |
| `POST /admin/karaoke/{id}/upload-cover` | поле `cover` | `karaoke/<slug>/cover.<ext>` |
| `POST /admin/karaoke/{id}/upload-lyrics` | поле `lyrics` | в базу, не в MinIO |

Два пути, как у комиксов. **Обычный — `POST /admin/karaoke/upload`**: карточка
и файлы уезжают одним запросом, и заводить трек можно за один заход.
Обязательна там только фонограмма (`audio`) и название; минус, обложка и
разметка — по наличию. `isActive=true` применяется после заливки, чтобы
галочка не спорила с проверкой публикуемости.

Поштучные ручки работают по сохранённой карточке и заменяют файл на месте —
они для правки одного файла, а не для заведения трека. В обоих случаях slug
должен существовать до заливки: это путь в MinIO.

Лимиты: аудио — 100 МБ, разметка — 2 МБ.
`spring.servlet.multipart.max-file-size` = 200 МБ, так что реальный потолок —
`client_max_body_size` на прокси; в этом проекте на такие грабли уже
наступали (STT «не слышал дольше 30 секунд» — ровно nginx'овый дефолт 1 МБ).

Ответ заливки разметки:

```json
{
  "lines": 24, "vocab": 9, "hotspots": 3, "duration": 168.5,
  "warnings": ["строка 7: таймкоды слов вне строки — подсветка будет построчной"],
  "track": { … }
}
```

## 5. Эндпоинты админки

Под `@PreAuthorize("hasRole('ADMIN')")`, как `AdminComicController`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/admin/karaoke` | список (без разметки) |
| `GET` | `/admin/karaoke/{id}` | карточка вместе с разметкой |
| `POST` | `/admin/karaoke` | создать (только метаданные) |
| `POST` | `/admin/karaoke/upload` | создать вместе с файлами (обычный путь) |
| `PUT` | `/admin/karaoke/{id}` | обновить метаданные |
| `POST` | `/admin/karaoke/{id}/upload-audio` | фонограмма (`instrumental=true` — минус) |
| `POST` | `/admin/karaoke/{id}/upload-cover` | обложка |
| `POST` | `/admin/karaoke/{id}/upload-lyrics` | разметка (проверяется) |
| `PATCH` | `/admin/karaoke/{id}/activate` | показать в приложении |
| `PATCH` | `/admin/karaoke/{id}/deactivate` | скрыть |
| `DELETE` | `/admin/karaoke/{id}` | удалить вместе с файлами |

**Активация — не просто флаг.** Трек без фонограммы или без разметки
активировать нельзя (`400`): в приложении он открылся бы сообщением об
ошибке. Проверка стоит на сервере, чтобы её не пришлось повторять в каждом
клиенте.

`KaraokeTrackRequest`:

```json
{
  "title": "Rainy Monday",
  "slug": "rainy-monday",
  "artist": "JTS Originals",
  "level": "A2",
  "tags": "past-simple,weather",
  "bpm": 92,
  "durationSec": 168,
  "descriptionRu": "…", "descriptionEn": "…", "descriptionKk": "…",
  "orderIndex": 0,
  "isActive": false
}
```

`title` обязателен, `slug` необязателен (соберётся из названия) и проверяется
паттерном, `isActive` обязателен.

## 6. Эндпоинты для приложения

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/mobile/karaoke` | каталог активных треков (без разметки) |
| `GET` | `/mobile/karaoke/search?q=` | поиск по названию, исполнителю и тегам |
| `GET` | `/mobile/karaoke/{id}` | один трек вместе с разметкой |

`GET /mobile/karaoke` → массив:

```json
[{
  "id": 1,
  "slug": "rainy-monday",
  "title": "Rainy Monday",
  "artist": "JTS Originals",
  "level": "A2",
  "tags": "past-simple,weather",
  "tagList": ["past-simple", "weather"],
  "bpm": 92,
  "durationSec": 168,
  "lineCount": 24,
  "coverImageUrl": "https://files-api.iqra.space/development/karaoke/rainy-monday/cover.webp",
  "audioUrl": "https://files-api.iqra.space/development/karaoke/rainy-monday/audio.mp3",
  "instrumentalUrl": "…/instrumental.mp3",
  "description": { "ru": "…", "en": "…", "kk": "…" },
  "isActive": true
}]
```

`GET /mobile/karaoke/{id}` → та же карточка плюс поле `lyrics` с разобранной
разметкой.

Замечания:

- **Разметка едет инлайном и только в ответе на один трек.** В каталоге её нет
  намеренно: десятки килобайт на карточку, которую список не читает. Файлом в
  MinIO она не лежит по другой причине — её пришлось бы читать `fetch`'ем, а
  на это браузеру нужен CORS у бакета, которого там нет (аудио и обложке он не
  нужен, их тянут теги `<audio>`/`<img>`).
- Неактивный трек исключается из всех трёх ручек, включая адресный `{id}`.
- Порядок — по `order_index`, затем по `id`.

## 7. Микрофон и оценка — чего на бэкенде НЕТ

Запись голоса **никуда не сохраняется**. Веб пишет исполнение в память,
считает метрики (покрытие, ритм, темп) прямо в браузере, а для оценки слов
один раз отправляет запись в собственный STT приложения
(`POST /api/transcribe` в `jts-web-app`, Azure/Soniox) и получает текст. В
JTS-бэкенд аудио не попадает, таблиц под него нет.

Прогресс по трекам живёт в `localStorage` (`jts_karaoke_v1`). Когда
понадобится синхронизация между устройствами — заведём
`/mobile/karaoke/{id}/progress`, но это не блокирует запуск.
