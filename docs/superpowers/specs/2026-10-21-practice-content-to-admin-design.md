# Материалы «Практики» — из `public/` сайта в админку (MinIO)

Дата: 21.10.2026. Статус: дизайн согласован с владельцем, пилот — Аудирование.

## Зачем

Материалы Практики лежат статикой в `public/practice/**` сайта: 244 МБ из 720 МБ
всего `public/` (mp3 134, mp4 42, webp 26, json 18, png 11, jpg 6). Добавить или
поправить задание может только разработчик — правкой прототипа и прогоном
экстрактора. В будущем материалы будут заводить сами преподаватели через
админку, поэтому контент переезжает в бэкенд (таблицы + MinIO), а сайт его
читает по API. Попутно сайт и Docker-образ теряют медиа.

Ученику сайт легче не станет: браузер и сейчас грузит только файлы своего
экрана. Выигрыш — в образе, клоне CI и в том, что материал можно менять без
релиза.

## Решения владельца (21.10.2026)

1. **Сначала пакетом, формы потом.** Этап 1 — весь нынешний контент раздела
   заливается в админку пакетом (то, что сейчас делают экстракторы). Этап 2 —
   формы для преподавателей, по разделам, на тех же таблицах.
2. **Материал виден всем ученикам** — общий каталог, как комиксы и караоке.
   Личных материалов преподавателя «только для своих» нет.
3. **Своя таблица на каждый раздел** (как комиксы, караоке, шэдоуинг), а не
   общее jsonb-хранилище. Общие куски (медиа, пакет, загрузчик) пишутся один
   раз, на пилоте, и переиспользуются.
4. **Пилот — Аудирование.**
5. **Запасной путь на статику** остаётся до проверки прода; чистка — отдельным
   PR после неё.

## Общая схема (для всех разделов)

```
public/ сайта ──скрипт пакета──▶ <раздел>.zip
                                   │
            дев-админка «Залить пакет» (zip распаковывает браузер)
                │ медиа по одному: есть? → нет → залить        │ задания
                ▼                                               ▼
       MinIO practice/<раздел>/<sha24>.<ext>        таблица раздела (upsert по ключу)
                └──────────────── бэкенд ───────────────────────┘
                                   │ GET /practice-content/<раздел>/…
                                   ▼
                 сайт: бэкенд → если пусто/ошибка → старая статика
```

Перенос дев → прод: тот же zip заливается в прод-админку, либо «Выгрузить
пакет» из дев-админки (если на деве что-то правили) → «Залить» на проде.

Порядок по разделу: бэкенд → админка → сайт (запасной путь включён) → заливка
на дев → проверка → релиз develop → main (бэкенд первым) → заливка на прод →
проверка → PR чистки. Каждый раздел — свои PR в трёх репо и отчёт.

### Общие куски (делаются на пилоте)

| Где | Что |
|---|---|
| backend | `PracticeMediaStorage`: ключ `practice/<раздел>/<sha24>.<ext>` (первые 24 hex sha256 содержимого, как у IELTS), `Cache-Control: public, max-age=31536000, immutable` при `put`, проверка «уже есть», отдача файла через бэкенд для выгрузки пакета (у бакета нет CORS). Сервер сам считает sha и отвергает файл, если он не совпал с заявленным. |
| backend | `docs/practice/PACK_FORMAT.md` — контракт пакета (единственный источник; на него ссылаются CLAUDE.md сайта и админка). |
| web-admin | Компонент пакета Практики: zip → разница → заливка медиа с пропуском уже залитых и продолжением после обрыва → импорт заданий; выгрузка zip. fflate, как у пакетов IELTS/SAT, — код IELTS не трогаем (раздел заморожен), подход копируем. |
| сайт | `src/practice/remoteContent.js` — загрузчик «бэкенд, иначе статика»; `scripts/practice-pack/` — сборщики пакетов на `scripts/lib/zip.js`. |

### Формат пакета (общая часть)

zip:
- `manifest.json` — `{format: "jts-practice-pack", version: 1, section, createdAt, source, counts}`; `source` — откуда собран (`jts-web-app@<sha коммита>` или `admin-export@<стенд>`).
- `items.json` — записи раздела в его схеме; ссылки на медиа — `media/<sha24>.<ext>`.
- `media/<sha24>.<ext>` — файлы.

Разница (diff) считается по ключу записи: **новые**, **изменённые** (иные поля
или иной sha медиа), **без изменений**, **есть только в админке**. Импорт
пишет новые и изменённые; «есть только в админке» не трогает, только
показывает.

### Очередь разделов

Пилот — Аудирование (88 МБ). Дальше по одному: Ситуации (45, видео), Слова в
картинках (38), Слушай и выбирай (17), Числа (15), Грамматика (5.6), Чтение,
Письмо, Воркбуки, Глаголы, вшитые уроки Шэдоуинга (в существующую
`shadowing_lessons`), темы SpeakSpin.

Отдельный этап — **Сказки**: контент вшит в JS-движок (2.9 МБ), медиа на
чужом CloudFront (638 ссылок); это перепроектирование, а не перенос.

Не переносим: оформление (coin/win/lose.png, `skills/*.svg`, маскоты), 3D
аркады (`public/arcade`), пробный тест уровня (`public/practice/placement` —
не Практика).

**CORS.** Бакет публичный, но без CORS. `<audio>`, `<video>`, `<img>` из него
работают, `fetch` — нет. Поэтому json всегда отдаёт бэкенд. Глаголы
(`fetch` → WAV-парсер → WebAudio), предзагрузка записей Чисел и выгрузка
пакета из браузера требуют CORS: для первых двух — правка nginx хоста файлов
(`files-dev` / `files`), когда дойдём до разделов; для выгрузки — отдача через
бэкенд (см. общие куски). Пилоту CORS не нужен.

## Пилот: Аудирование

### Данные сейчас

`public/practice/listening/content/<a1|a2|b1|b2|c1>.json` — 800 заданий
(124/164/167/182/163), 797 mp3 (79 МБ) в `audio/<уровень>/`. Прототипа и
экстрактора нет: источник — нарезка курса Empower (коммит 19bf623e).

| Тип | Кол-во | Поля |
|---|---|---|
| `listen_choice` | 406 | `prompt`, `options[]`, `answer` |
| `listen_assemble` | 176 | `text`, `tokens[]`, `distractors[]` |
| `listen_type` | 218 | `answer` |

У всех: `id`, `type`, `audio` (имя файла), `explanation` (HTML). В разборе
встречаются только `<b>` (1004) и `<i>` (38). Три записи общие у нескольких
заданий. id уникальны.

**id не меняется.** `a1_001` — ключ прогресса (`jts_listening_done`), квоты
`PRACTICE_LISTENING` и счёта «пройдено на уровне»: `getListeningDone`
отбирает по префиксу `<уровень>_`. Поэтому префикс id обязан совпадать с
уровнем.

### Бэкенд

Таблица `practice_listening_tasks`:

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | bigserial | |
| `task_key` | varchar UNIQUE | `a1_001`; regex `^(a1\|a2\|b1\|b2\|c1)_\d{3,}$`, префикс = `level` |
| `level` | varchar(2) | `a1`…`c1` |
| `type` | varchar | один из трёх типов |
| `position` | int | порядок внутри уровня (из порядка в пакете) |
| `audio_url` | text | публичный URL MinIO |
| `audio_sha` | char(24) | для diff и выгрузки |
| `explanation` | text | HTML, только `<b>`/`<i>` |
| `body` | jsonb | поля типа (см. таблицу выше) |
| `is_active` | boolean | выключенное не отдаётся ученику |
| `created_at`, `updated_at` | timestamptz | |

Номер миграции Flyway — в момент мержа, не при создании PR (на 21.10
последняя — V386; номера занимают, пока PR висит).

Правила при заливке (ошибки списком, как `ShadowingRules`):
- тип известен, у типа есть все поля, лишних нет;
- `listen_choice`: 2–6 вариантов, `answer` ∈ `options`;
- `listen_assemble`: `tokens` не пуст, дистракторы не совпадают с токенами. Совпадения `text` с `tokens` НЕ требовать: `text` — то, что звучит в записи (движок показывает его как «услышано»), а ответ сверяется по `tokens`; у a1_007, a1_096, a2_022, b2_007 текст длиннее плиток;
- `explanation`, `prompt`, `text`, `answer`: из тегов разрешены только `<b>`, `</b>`, `<i>`, `</i>` без атрибутов — сайт вставляет разбор как HTML, а писать его будут преподаватели;
- запись — mp3 (сигнатура ID3 или кадр MPEG), до 20 МБ (сейчас максимум 1.4 МБ; у всех 797 файлов сигнатура в порядке — проверено 21.10).

Ручки:

| Метод и путь | Доступ | Что |
|---|---|---|
| `GET /practice-content/listening/levels` | без входа | `[{level, count}]` активных |
| `GET /practice-content/listening/{level}` | без входа | массив активных заданий по `position` **в форме нынешнего json** (`id`, `type`, `audio`, `explanation` + поля типа), `audio` — полный URL. `Cache-Control: public, max-age=300` |
| `GET /admin/practice/listening/tasks?level=` | ADMIN | список для экрана админки |
| `PATCH /admin/practice/listening/tasks/{key}` | ADMIN | `{active}` |
| `POST /admin/practice/listening/pack/diff` | ADMIN | тело — `items.json`, ответ — разница |
| `POST /admin/practice/listening/pack/import` | ADMIN | upsert новых и изменённых; все медиа обязаны уже лежать в MinIO |
| `GET /admin/practice/listening/pack/export` | ADMIN | `manifest` + `items` (медиа — по ручке ниже) |
| `GET /admin/practice/media/exists?section=&sha=` | ADMIN | есть ли файл |
| `POST /admin/practice/media?section=` | ADMIN | multipart, один файл |

не персональный, ответы и так лежат в публичном json. В `SecurityConfig`
строка `GET /practice-content/**` → `permitAll` (рядом с `/catalog/**`).

### Админка (web-admin)

«Библиотека» → вкладка **«Аудирование»** (рядом с комиксами и караоке):
- уровни со счётчиками; таблица заданий: id, тип, вопрос/ответ коротко, ▶ запись, переключатель «вкл»;
- «Пакет»: выбрать zip → разница (четыре группы) → «Залить» с прогрессом; «Выгрузить пакет».

Форм редактирования на этапе 1 нет.

### Сайт (jts-web-app)

- `src/practice/remoteContent.js` — `loadPracticeContent(section, path, staticUrl)`: запрос к `${NEXT_PUBLIC_API_URL}/practice-content/<section>/<path>` с таймаутом 8 с. Если 404, пустой массив, 5xx или ошибка сети — `fetch(staticUrl)`. Возвращает `{data, source: 'api'|'static'}`; источник пишется в консоль и в `data-source` корня экрана (для тестов).
- `ListeningPage.jsx`: `loadContent` идёт через загрузчик; `audioUrl` — полный URL берётся как есть, имя файла — как раньше `/practice/listening/audio/<уровень>/<файл>`.
- Разбор (`Rich`): перед вставкой вырезаются все теги, кроме `<b>`/`<i>` — вторая линия после проверки бэкенда.
- `/api/practice/catalog` (`listeningArea`): счётчики с `${BACKEND_URL}/practice-content/listening/levels`, при неудаче — с диска.
- `scripts/practice-pack/build-listening.js` → `build/practice-packs/listening.zip`: `items.json` — задания всех уровней с полем `level`, порядок = порядок в файле уровня, `audio: "media/<sha24>.mp3"`; три общие записи — один файл.

### Тесты

- **сайт, vitest:** загрузчик (api → api; 404 / `[]` / 5xx / сеть → static); `ListeningPage.test.jsx` — оба источника и полный URL записи; сборщик пакета (800 заданий, у каждого есть файл, имя = sha, манифест сходится); очистка разбора.
- **сайт, e2e:** `practice-listening-trainer.spec.js` — образец mp3 переезжает в `tests/fixtures/` (чистка удалит `public/…/audio`), маршруты на API и статику; `practice-gate.spec.js` — то же.
- **backend:** правила (каждое нарушение), upsert и diff, форма ответа публичной ручки, неактивные не отдаются, несовпавший sha отвергается. На Mockito: WebMvc-срезы сейчас красные (`IeltsAccessInterceptor` без бина).
- **web-admin:** spec на расчёт разницы и на пропуск уже залитых медиа.

### Проверка

На деве (сначала — что стенд жив после переезда сервера):
1. В сети — `dev-server…/practice-content/listening/a1`, записи — с `files-dev…`, `data-source="api"`.
2. Полная сессия A1 гостем и под входом.
3. Пройденное до переноса осталось пройденным (тот же аккаунт).
4. Кабинет преподавателя показывает счётчики; домашка с Аудированием открывается.
5. Выключенное в админке задание пропало с сайта (через ≤5 мин кэша).

После релиза — те же пункты на проде, после заливки пакета в прод-админку.
До заливки прод работает на статике (`data-source="static"`).

### Чистка (отдельный PR после проверки прода)

Удаляются `public/practice/listening/content/` и `public/practice/listening/audio/`
(~79 МБ). coin/win/lose.png остаются — это оформление других экранов. Запасной
путь Аудирования убирается: при недоступном бэкенде — своя ошибка
`listening.loadError`, без тихой подмены. Каталог для преподавателя — только с
бэкенда. CLAUDE.md: источник Аудирования — бэкенд, ссылка на `PACK_FORMAT.md`.

## Подвохи

- **Порядок релиза:** бэкенд в main раньше сайта, иначе прод-сайт стучится в несуществующую ручку (запасной путь спасёт, но шум в логах).
- **Креды S3** лежат дефолтами в `backend:application.yml` открытым текстом (как и другие секреты). Пилот их не трогает; ротация — отдельная задача владельца.
- **Кэш:** правила `next.config.mjs` для `/practice/*` на файлы MinIO не действуют — поэтому `immutable` ставится при заливке; имя по хэшу делает его безопасным.
- **Удаление в MinIO:** как у комиксов, удаление записи не стирает объект; осиротевшие медиа — терпимо на этапе 1.
- Код IELTS не меняется: подход пакетов копируется в новый общий компонент.
