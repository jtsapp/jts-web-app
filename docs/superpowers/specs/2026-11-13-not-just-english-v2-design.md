# Not Just English (Birge v2) — лента преподавателей и новое имя

Дата: 13.11.2026. Источник — ТЗ «Раздел Not Just English» v2.0 от 12.11.2026 (задача 211 в prod-admin «Задачи»,
вложение `Not_Just_English.zip`: ТЗ docx/pdf и `prototype/index.html`). Это обновление раздела Birge, собранного по
ТЗ v1.0 — базовая спека `2026-11-11-birge-community-design.md` остаётся в силе во всём, что ниже не изменено.

## 1. Что меняет v2 и решения владельца (13.11.2026)

| Вопрос | Решение | Почему |
|---|---|---|
| Имя | Везде, где его видит человек, — **Not Just English** (не переводится). Подзаголовок: «Сообщество студентов Just to Study» / «Сообщество преподавателей Just to Study» (kk/en — переводом). Внутренние имена (`birge` в коде, путях API, таблицах, ключах i18n и `?screen=birge`) НЕ меняются | ТЗ v2 §1. Переименование кода — риск без пользы для ученика |

## 2. Платформа

`platform` = `student` | `teacher`. Определяет её **сервер** по роли автора запроса: `STUDENT` → `student`,
`TEACHER` → `teacher`; клиент платформу не присылает (ученик не может подменить её параметром). У пользователя с
обеими ролями — `teacher`. Остальные роли в ленту не допускаются (403, как раньше).

### 2.1 Темы

| Платформа | Коды (API) | Подписи ru |
|---|---|---|
| student | GRAMMAR, SPEAKING, VOCABULARY, MOTIVATION, QUESTION (как было) | Грамматика, Speaking, Словарь, Мотивация, Вопрос |
| teacher | METHODOLOGY, LESSON_IDEAS, MATERIALS, STUDENTS, METHODIST_QUESTION, EXPERIENCE | Методика, Идеи уроков, Материалы, Ученики, Вопрос методисту, Опыт |

Тема чужой платформы в публикации и в фильтре ленты — 400. Тема по умолчанию в форме: student — «Вопрос»,
teacher — «Идеи уроков» (как в прототипе).

### 2.2 Модерация преподавателей — отличия

- **Персональные данные ученика** — новая причина `STUDENT_PERSONAL_DATA`, вес 52 (как `LINK_OR_CONTACT`), значит
  при порогах по умолчанию — в очередь менеджера с этой причиной (критерий ТЗ §10: «пост преподавателя с телефоном
  ученика уходит менеджеру с причиной…»). Ставится:
  - правилами: телефон в тексте учителя даёт `STUDENT_PERSONAL_DATA` **вместо** `LINK_OR_CONTACT` (ссылки, @ники,
    Telegram у учителя — прежний `LINK_OR_CONTACT`);
  - AI-классификатором: для учительской платформы в промпт добавляется категория «ФИО ученика, его телефон или
    оценки» → `STUDENT_PERSONAL_DATA` с уверенностью; у студентов категории нет.
- **Мягкая критика**: у учителей свой словарь `criticism` в настройках платформы (по умолчанию из прототипа):
  «не нравится, неудобн, расписани, зарплат, не платят, руководств, администрац, переработ, разочар, жалоб, глючит,
  тормозит». Мат и «плохие отзывы → Feedback» — те же словари, что у студентов (копия в настройках платформы).
  Классификатору для учительской платформы в описание мягкой критики добавляется «расписание, организация, зарплата,
  руководство».
- Плохой отзыв о платформе учителя — тоже обращение в Feedback (тот же `BirgeFeedbackGateway`); если Feedback для
  роли TEACHER не создаётся — решение `auto_feedback` всё равно не публикует пост, а в ответ уходит обычный отказ
  (бэкенд решает и описывает в PR).
- Остальной конвейер (фото, словарь мата, риск, решение, жалобы, антиспам 5 веток / 30 комментариев в час) — общий.

### 2.3 Настройки и лимит — на платформу

Настройки модерации (пороги, лимит, поведение при переполнении, порог жалоб, словари) и дневной счётчик ручных
заявок — отдельно у каждой платформы. Значения по умолчанию у обеих — из v1 (30 / 70 / 3 / reject / 3); словари
учителя — §2.2. Счётчик сбрасывается в 00:00 Asia/Almaty, как раньше.

## 3. Бэкенд

### 3.1 Миграция `V611__Birge_platform.sql` (номер сверить с develop и всеми ветками перед мержем)

Таблицы уже есть на деве с данными и на проде (пустые) — только `ALTER`, без пересоздания:

- `birge_posts`: `platform VARCHAR(10) NOT NULL DEFAULT 'student'` + check `('student','teacher')`; индексы ленты и
  очереди — с `platform` первым столбцом (старые заменить).
- `birge_moderation_settings`: была одна строка `id = 1`. Стать: ключ — `platform` (PK), строка `student` из
  существующей (значения не терять), строка `teacher` — копия порогов `student` и словари §2.2. Столбец `id` и его
  check убрать.
- `birge_moderation_daily_counter`: ключ `(day, platform)`, существующие строки — `student`.
- `birge_moderation_log` не меняется: платформа берётся через `post_id`.

### 3.2 API

Ученик и учитель — те же `/mobile/birge/**`, `@PreAuthorize("hasAnyRole('STUDENT','TEACHER')")`. Платформа — из роли
(§2), все выборки и проверки доступа — в её пределах.

Менеджер — `/admin/birge/**`: `GET /summary`, `/queue`, `/log`, `/posts`, `GET|PUT /settings` принимают
`?platform=student|teacher` (по умолчанию `student` — старый web-admin работает как раньше; неизвестное значение —
400). `POST /posts/{id}/decision` и `POST /log/{id}/revert` платформу берут из поста.

### 3.3 Формы JSON (дополнения к §5.3 базовой спеки)

- `Author`: + `"role": "STUDENT" | "TEACHER"`; у учителя `level` = null.
- `PostCard`, `ManagerPost`, `LogItem`: + `"platform": "student" | "teacher"`.
- `SettingsView` / `SettingsRequest`: + `"platform"` (в ответе; в запросе — из query).
- Причина `STUDENT_PERSONAL_DATA` в `reasons[].code`.

### 3.4 Уведомления

Заголовок уведомлений раздела — «Not Just English» вместо «Birge» (`BirgeNotificationTexts`), тексты те же. Типы и
deepLink (`birge/<id>`) не меняются.

## 4. Веб (`?screen=birge`)

- Платформа на клиенте — `isTeacher(token)` (`src/lib/jwt.js`); она выбирает только оформление: темы, подписи,
  правила, бейдж. Данные приходят уже отфильтрованные сервером.
- Имя: пункт меню и заголовок «Not Just English», подзаголовок по платформе (ru/kk/en). Справка Луны
  (`knowledge.js`) — новое имя.
- Меню учителя: `birge` добавить в `TEACHER_SECTIONS` (после «Практики»). Прод-гейт `STUDENT_HIDDEN_ON_PROD` действует
  и на учителя — раздел на проде скрыт для всех, пока владелец не откроет.
- Темы учителя (§2.1) в фильтре ленты и в выборе темы формы, тема по умолчанию «Идеи уроков».
- Подсказка поля у учителя: «Поделитесь идеей урока, материалом или вопросом…» (у студента — «Что нового?»).
- Бейдж автора: `role === 'TEACHER'` → «Преподаватель» вместо уровня.
- Правила сообщества учителя (колонка справа, на телефоне — свёрнуто):
  1. Пишем уважительно о коллегах и учениках
  2. Не публикуем ФИО, телефоны и оценки учеников
  3. Вопросы о графике и оплате — в Feedback или методисту
  4. Материалы — только свои или из открытых источников
  5. Посты проверяет AI; спорные — смотрит контент-менеджер
- Причина `STUDENT_PERSONAL_DATA` — подпись «Персональные данные ученика» (ru/kk/en) в итоге публикации.
- Колокольчика у учителя в вебе нет — уведомления ему не видны (ограничение, не баг; ссылка из уведомления
  работает, если откроется).

## 5. Web-admin (кабинет CONTENT_MANAGER)

- Имя блока «Not Just English».
- Меню — два блока «Not Just English · Студенты» и «Not Just English · Учителя» (или один блок с двумя группами — как
  ложится в `role-navigation.config.ts`), в каждом: Очередь проверки, Журнал решений, Настройки модерации, Лента.
  Счётчик ждущих в очереди — у каждой платформы свой, если меню умеет счётчики.
- Платформа — в адресе (`/system/birge/student/queue`, `/system/birge/teacher/queue` …); старые адреса
  `/system/birge/queue` и т. п. ведут на `student`. Все запросы сервиса — с `?platform=`.
- Сводка, очередь, журнал, лента, настройки — те же экраны, данные своей платформы. В карточке поста учителя — бейдж
  «Преподаватель», темы учителя подписаны по §2.1, причина `STUDENT_PERSONAL_DATA` — «Персональные данные ученика».

## 6. Приёмка (ТЗ v2 §10, что входит в итерацию)

| Критерий | Чем проверяется |
|---|---|
| Студент не видит ленту преподавателей, преподаватель — ленту студентов | бэкенд: выборки и доступ по платформе (юнит + Postgres-тест); веб: e2e учитель видит свои темы и правила |
| У менеджера два отдельных блока со своими очередями и настройками | бэкенд: summary/queue/settings по `platform`; web-admin: spec меню и сервиса |
| Пост преподавателя с телефоном ученика уходит менеджеру с причиной «Персональные данные ученика» | бэкенд: правило + решение `pending` |
| Остальные критерии v1 (мат, Feedback, очередь, лимит, жалобы, отмена) | прежние тесты, теперь на обеих платформах там, где отличается |
| Преподаватель прикрепляет PDF | **не входит** (файлы — следующий шаг, нужен антивирус) |

## 7. Порядок выкатки

Бэкенд первым (миграция + API с `platform` по умолчанию `student` — старые веб и web-admin работают без изменений),
затем веб и web-admin в любом порядке. Раздел на проде скрыт (`STUDENT_HIDDEN_ON_PROD`) — открытие решает владелец.
