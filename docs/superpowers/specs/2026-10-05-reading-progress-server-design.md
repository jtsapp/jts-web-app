# Прогресс «Чтения» с сервера — дизайн

Дата: 05.10.2026. Ветка `feat/reading-progress-server` от `origin/develop`
(после #576 — досдача непроверенных заданий на «Завершить»).

## Зачем

Жалоба 05.10: ученик под входом жал «Проверить» у всех заданий
«Eleven Days in the Jungle», видел «Всё верно» и «✅ 5/5», а итог — 0 %
(дев и прод).

Причина воспроизведена на dev-tutor: localStorage домена забит до квоты.
Его съедает кэш каталогов `cachedAuthGet` (`jts_catalog_*`, только под входом;
один раздел «Словаря» — 170–550 КБ, все 21 — 7,5 МБ при лимите Chrome ~5 МБ).
`writeState` глотает `QuotaExceededError`, галочки держит React-стейт, а итог
читает пустое хранилище.

Сервер при этом тоже страдает. Сейчас состояние уходит целиком (replace,
`pushModule`) и собирается из localStorage, поэтому каждое «Проверить» шлёт
«старое + одно задание», и на сервере остаётся только последнее.

## Решения владельца

- Результаты идут на сервер и берутся оттуда (вариант A из обсуждения).
- Итог после «Завершить» показывает числа с сервера: «Сохраняем…», затем
  процент из ответа сервера. Сервер не ответил — итог из памяти и плашка
  «Не сохранено на сервере · Повторить».
- Сначала только «Чтение». Остальные разделы Практики и урезание кэша
  каталогов — отдельными PR потом.

## Как устроено

### Сервер — источник истины, слияние «лучший результат»

`src/lib/readingState.js` — чистые правила формы, общие для клиента и сервера
(`practiceContract.js` подключает отсюда слияние):

- `sanitizeReadingState(raw)` — приводит вход к форме
  `{ texts: { <id>: { ex: { <i>: { score, total } }, done } } }` или
  возвращает `null` (тогда 400). Правила: `texts` — объект, не больше 1000
  текстов; id — непустая строка до 64 символов; индекс задания — целое 0…49;
  `score`, `total` — целые, `0 ≤ score ≤ total ≤ 1000`; `done` — boolean.
  Неизвестные поля отбрасываются.
- `mergeReadingState(existing, incoming)` — по каждому заданию берётся запись
  с большим `score` (при равенстве — входящая, чтобы обновлялся `total`, если
  данные текста поменялись); `done` только включается (`a || b`). Ни один
  вход не может уменьшить сохранённое. Повторная отправка той же дельты ничего
  не меняет.
- `readingDelta(base, next)` — что в `next` лучше, чем в `base` (для досылки
  недолетевшего); `null`, если нечего.
- `practiceContract.js`: `mergeModuleState('reading', …)` → `mergeReadingState`.
  Остальные модули без изменений.

`src/lib/db/practice.js`, `savePracticeState`: read-merge-write в транзакции
(`sql.begin`) под `pg_advisory_xact_lock(hashtext(profile_id || ':' || module))`.
Без замка два параллельных POST одного ученика (две вкладки, быстрые
«Проверить») читают одно и то же и последний затирает первого. Замок ставим
для всех модулей: это та же функция, а union-модулям атомарность тоже нужна.
Функция возвращает слитое состояние (уже возвращает).

`src/app/api/practice/state/route.js`:

- POST для `reading` прогоняет `state` через `sanitizeReadingState`
  (`null` → 400 `Invalid state.`) и отвечает `{ configured, ok, state: merged }`.
  У остальных модулей в ответе тоже появляется `state` — лишнее поле старые
  клиенты игнорируют.
- GET принимает `?module=<имя>`: отдаёт `state` только с этим модулем
  (`{ reading: … }`), неизвестное имя — 400. Без параметра — как сейчас.

### Клиент — память + сервер, localStorage только черновик

`src/practice/reading/readingProgress.js` переписывается, API для экранов
сохраняется (`readState`, `textState`, `markExercise`, `markTextDone`,
`progressOf`, `levelProgress`, `levelDoneCount`) плюс новые функции ниже.

**Память.** Модульная переменная `mem = { owner, state }`. `owner` — личность
из токена (`payloadOf(loadToken())?.sub`, иначе `'guest'`). `readState()`
отдаёт `mem.state`, если `owner` совпадает с текущим; иначе перечитывает
localStorage-черновик и запоминает. Так смена аккаунта в той же вкладке и
выход (их `clearLocalPractice` чистит черновик) не показывают чужой прогресс.

**Запись.** `markExercise` / `markTextDone` сливают изменение в `mem` тем же
`mergeReadingState` (из `src/lib/readingState.js`), пробуют записать черновик в localStorage (ошибку
квоты по-прежнему глотаем — теперь это безопасно), шлют событие прогресса. Для
вошедшего — ставят ДЕЛЬТУ (`{ texts: { id: { ex: { i: {score,total} } } } }`
или `{ texts: { id: { done: true } } }`) в очередь отправки.

**Очередь отправки.** Одна отправка в полёте на вкладку. Новые дельты, пока
идёт запрос, копятся и сливаются в одну. Ответ сервера (`state`) сливается в
`mem` (`mergeReadingState(serverState, mem)` — монотонно, поэтому ответ на
раннюю дельту не откатывает более позднюю) и пишется в черновик. Ошибка сети
или не-2xx — дельта остаётся в очереди и уходит со следующей отправкой или
при `flushReading`. Без задержки 0,6 с: «Проверить» отправляется сразу.
`pushModule('reading', …)` больше не вызывается.

**Загрузка с сервера.** `loadReadingFromServer()` (вошедший): GET
`/api/practice/state?module=reading` → `mem = merge(server, mem)`. Если в
памяти или черновике есть что-то лучше серверного (результат, не долетевший
в прошлый раз), разница досылается дельтой. Вызывается при открытии раздела
(`ReadingPage`, монтирование) — пока ответа нет, экран рисует черновик.

**Итог.** `flushReading()` → `Promise<{ ok, state }>`: дожидается очереди,
повторяет неотправленное один раз, затем GET `?module=reading` и возвращает
серверное состояние. Гость → сразу `{ ok: true, state: mem.state, local: true }`.

### Экран итога

`ReadingResult`: при монтировании `markTextDone` (как сейчас) и `flushReading()`.

- Пока ждём — вместо чисел «Сохраняем…» (новый ключ i18n).
- `ok` — процент, «Верно N/M», «Заданий сделано», «Что повторить» считаются из
  `state` сервера.
- Не `ok` — те же числа из памяти и плашка «Не сохранено на сервере» с кнопкой
  «Повторить» (снова `flushReading`).

Библиотека и задания продолжают читать `readState()` (память) и
перерисовываться по событию прогресса.

### Что не меняется

- Гость: память + localStorage, на сервер ничего не идёт.
- Отчёт в домашнюю работу (`countUnitTowardsHomework` в `markTextDone`).
- `hydratePractice` при входе по-прежнему кладёт серверное «Чтение» в
  черновик; память подхватит его по смене `owner`.
- Форма данных в `practice_state.reading` та же — профиль и квоты, читающие
  её, не трогаем.

### i18n

В `src/i18n.jsx` (ru/en/kk): `reading.result.saving`,
`reading.result.saveFailed`, `reading.result.retrySave`.

## Тесты

- `src/lib/readingState.test.js`: `mergeReadingState` — лучший счёт побеждает,
  урезанная дельта не стирает, `done` не выключается, повтор идемпотентен;
  `sanitizeReadingState` — мусор, отрицательные/дробные/`score>total`,
  лимиты размеров → `null`; лишние поля отброшены.
- `src/lib/db/practice.test.js` (фейковый sql): reading сливается, а не
  заменяется; запись идёт внутри `begin` с advisory-замком.
- `readingProgress.test.js`: localStorage бросает `QuotaExceededError` —
  `readState`/`progressOf` всё равно видят результаты; вошедший шлёт дельту
  (мок fetch) и сливает ответ; ответ на раннюю дельту не откатывает позднюю;
  ошибка сети — дельта досылается при `flushReading`; смена `owner` сбрасывает
  память; гость не ходит в сеть.
- `ReadingResult` (jsdom): «Сохраняем…» → числа сервера; отказ → плашка и
  «Повторить».
- `tests/reading.spec.js` — гостевой путь зелёный без изменений.
- Живая проверка под входом на dev — владелец (войти за него нельзя).
