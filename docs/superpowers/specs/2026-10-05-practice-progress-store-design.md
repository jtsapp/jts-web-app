# Общее хранилище прогресса «Практики» — дизайн

Дата: 05.10.2026. Ветка `feat/practice-progress-server` от `origin/develop`.
Продолжение `2026-10-05-reading-progress-server-design.md` (#578): там «Чтение»
переведено на сервер, здесь — остальные разделы.

## Зачем

Прогресс разделов «Практики» читается из localStorage. Его забивает кэш
каталогов (`jts_catalog_*`, только под входом) — и запись молча падает:

- **разделы-«галочки»** (грамматика, аудирование, шэдоуинг, ситуации, уровни
  воркбуков): сервер объединяет пройденное, там ничего не теряется, но экран
  читает пустое хранилище — пройденное «исчезает»;
- **разделы-«объекты»** (воркбук, «Письмо», «Слова в картинках», «Глаголы»,
  «Слушай и выбирай»): сервер заменяет состояние целиком. После перезагрузки
  `hydratePractice` не может записать серверное в полный localStorage, раздел
  поднимает старый черновик, и первое же действие отправляет его на сервер —
  прогресс стёрт.

«Словарь» (`practice/vocab`) не трогаем: его хук `useVocabState` нигде не
подключён, раздел живёт на бэкенде. «Чтение» — своя схема из #578.

## Решения владельца

- Экраны итога не меняются: прогресс отправляется фоном, «Сохраняем…» нет.
- Один общий механизм на все разделы (вариант A).
- Серверная семантика прежняя: union для «галочек», replace для объектов.

## Как устроено

`src/practice/progressStore.js`, `createProgressStore({ module, key, event,
empty, normalize, merge })` → `{ read(), write(next, { sync }) }`.

**Память.** `mem = { owner, state, raw, draftOk }`. `owner` — личность токена
(`'guest'` без него). `read()` отдаёт память; перечитывает черновик, если
сменился владелец или черновик поменял кто-то другой (`raw` не совпал — другая
вкладка, уборка при выходе) — но только пока наши записи в него проходят
(`draftOk`). Пока хранилище не пишет, главная — память.

**Запись.** `write(next)`: память ← next, черновик (ошибку квоты глотаем,
`draftOk = false`), событие раздела, для вошедшего — `pushModule(module, next)`
(полное состояние из памяти, прежний debounce). `sync: false` — без отправки
(нужно «Слушай и выбирай»).

**С сервера.** `hydratePractice` (загрузка страницы, вход) отдаёт ответ в
`adoptHydratedState(state, owner)`: он запоминает снимок по владельцу и
передаёт каждому созданному хранилищу его модуль. Разделы, ещё не открытые в
этой загрузке, возьмут снимок при первом `read()`. В localStorage
`applyHydratedState` пишет только модули без хранилища (reading и т.п.).

Сведение сервера с памятью:
- `merge` задан («галочки»): объединение; если в памяти было то, чего нет на
  сервере, — отправка;
- объекты: серверное, если в памяти нет действий этой загрузки; иначе память
  остаётся и отправляется (поведение до правки — то же).

При первом `read()` сведение идёт без события (`read` зовут из рендера).

**Выход/вход.** `clearLocalPractice` сбрасывает снимок и память хранилищ.

**Тесты.** Сброс памяти между тестами — из `vitest.setup.js` через
`globalThis.__jtsPracticeStores` (импортировать модуль в setup нельзя: тесты
мокают `practiceSync`, и хранилище из setup держало бы настоящий `pushModule`).

## Разделы

grammar, listening, shadowing, situations, workbooks — `merge` по множеству id;
workbook, writing, words, verbs, listenchoose — объекты без `merge`. Публичные
функции модулей прогресса не меняются; свои «зеркала в памяти» у verbs и
listenchoose заменяются хранилищем; писатели больше не мутируют прочитанное
состояние (память общая).

## Тесты

- `progressStore.test.js`: гость пишет черновик; квота — память держит;
  смена владельца; чужая запись черновика перечитывается; снимок для позднего
  хранилища; «галочки» объединяются и досылаются; объект: сервер побеждает
  без действий, память — с действиями; `sync:false` не отправляет; сброс.
- `practiceSync.test.js`: `hydratePractice` отдаёт модули хранилищам и не пишет
  их черновики сам; `clearLocalPractice` сбрасывает память.
- Существующие тесты модулей прогресса — зелёные без правки смысла.
- Квота для каждого раздела: отметка видна при забитом localStorage.
