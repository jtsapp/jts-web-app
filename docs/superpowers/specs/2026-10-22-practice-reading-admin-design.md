# «Чтение» Практики — в админку: пакет и формы

Дата: 22.10.2026. Статус: дизайн согласован с владельцем. Второй раздел после Аудирования по шаблону
`2026-10-21-practice-content-to-admin-design.md` (общая схема, загрузчик, пакет) и
`2026-10-22-practice-listening-forms-design.md` (формы, удаление отметкой).

## Решения владельца (22.10.2026)

1. **Пакет и формы — одним кругом.** Две волны PR: сначала пакет (перенос 80 текстов, список, скрыть/показать), затем
   формы (добавить, изменить, удалить текст).
2. **Упражнения в форме — полями по механике.** 13 типов сводятся к пяти редакторам, как в движке сайта: выбор
   ответа, пары, порядок, пропуски, свободный ответ. JSON руками преподаватель не пишет.
3. **Языки:** в переводимых полях (задание к тексту, инструкция, разбор, пояснение к ответу, заголовок абзаца)
   обязателен только en; ru и kz — по желанию. Чего нет, ученик видит по-английски (`loc()` сайта так и делает:
   язык → en → ru). Список в админке помечает тексты без перевода.
4. **Новый текст из формы создаётся скрытым.** Его можно сохранять по ходу работы, проверить предпросмотром и только
   потом нажать «Показать». Недописанное ученик не увидит.
5. Правят только админы (как у Аудирования).

## Данные сейчас

`public/practice/reading/<a1…c1>.json` — `{level, texts[16]}`, 80 текстов, 760 КБ; режет их
`scripts/extract-reading.js` из прототипа `data/jtsreading.html`. **Медиа нет вовсе:** обложка — эмодзи, записей
и картинок нет. HTML нет ни в одном поле (сайт всё показывает текстом).

Текст:

| Поле | Что |
|---|---|
| `id` | `a1-sci-honey`: уровень, код жанра, слово. Ключ прогресса, квоты и домашней работы (`practice_unit_key`). Не меняется никогда |
| `level` | `A1`…`C1` (заглавными — так показывает экран) |
| `genre` | adventure, culture, history, mystery, nature, people, science, technology (по 10 текстов) |
| `title` | до 48 знаков сейчас |
| `cover` | `{emoji}` |
| `task` | Loc — задание к чтению |
| `words` | 6–8 ключевых слов `{en, tr, ru, kz, ex}` (транскрипция, переводы, пример) |
| `text` | абзацы (2–7), строки до ~1000 знаков |
| `exercises` | 5–7 упражнений |

Loc = `{en, ru, kz}`; сейчас 2225 таких полей, ни одного пропуска.

Упражнения (у всех: `type`, `instruction` Loc, необязательный `explanation` Loc — экран показывает его после проверки):

| Механика | Типы | Поля |
|---|---|---|
| Выбор | `before`, `mc`, `vocab` | `items[{q, o[], a: индекс, e?: Loc}]` |
| | `finish` | `items[{s, o[], a: индекс, e?}]` |
| | `tf` | `items[{s, a: true\|false, e?}]` |
| | `tfng` | `items[{s, a: "T"\|"F"\|"NG", e?}]` |
| Пары | `match` | `pairs[{l, r, alt?}]` двух видов: слово ↔ эмодзи (`r` строка, `alt` Loc — подпись картинки; 4 упражнения) или слово ↔ значение (`r` Loc; 36) |
| | `wwmatch` | `pairs[{l, r}]` |
| | `headings` | `pairs[{l: Loc, r}]` — «Абзац N» ↔ заголовок |
| Порядок | `order`, `summary` | `items[string]` в верном порядке |
| Пропуски | `gap` | `text` с `{ответ}`, `extra[]` — лишние слова банка |
| Свободный ответ | `reflection` | `q`, `keys[[синонимы]]`, `min`, `model` |

Пары и порядок проверяются совпадением индексов: данные лежат в верном порядке, перемешивает их `initExercise`
(`shuffledIdx` — ни один элемент не остаётся на месте). Общий словарь тапа `dict.json` (3799 слов) — справочник
раздела, а не материал текста: **остаётся статикой сайта**.

## Бэкенд

### Таблица `practice_reading_texts`

| Колонка | Тип | Смысл |
|---|---|---|
| `id` | bigserial | |
| `text_key` | varchar(60) UNIQUE, не обновляется | `a1-sci-honey` |
| `level` | varchar(2) | `a1`…`c1` |
| `genre` | varchar(20) | один из восьми |
| `title` | varchar(200) | для списка и каталога преподавателя |
| `order_index` | int | порядок внутри уровня |
| `body` | TEXT | остальное: `cover`, `task`, `words`, `text`, `exercises` — JSON. TEXT, а не jsonb: документ читают целиком (как `practice_listening_tasks.body`) |
| `is_active` | boolean | скрытое не отдаётся ученику |
| `deleted_at` | timestamp | удалено отметкой: id не достанется другому тексту |
| `created_at`, `updated_at` | timestamp | |

Индекс `(level, is_active, order_index)`. Сущность — с `@DynamicUpdate` (ловушка Аудирования: при open-in-view
UPDATE по всем колонкам воскрешал удалённое). Номер миграции — в момент мержа (сверять `origin/*`, открытые PR и
локальные ветки соседних worktree).

### id нового текста

Сервер выдаёт `<уровень>-<код жанра>-<слово>-<5 знаков>`: `b1-sci-placebo-k3f9q`. Код жанра — тот же, что у
нынешних id (adv, cul, his, mys, nat, peo, sci, tec); слово — первое значимое слово заголовка латиницей, до 16
знаков (нет такого — `text`); хвост — случайные `[a-z0-9]`, при совпадении — новый хвост. **Случайный хвост решает
вопрос, открытый на Аудировании:** формы дева и прода не выдадут одинаковых id, и пакет при переносе не затрёт
чужой текст. Правило id: `^(a1|a2|b1|b2|c1)-[a-z0-9]+(-[a-z0-9]+)*$`, до 60 знаков, префикс = уровень. 80
нынешних id — как есть.

### Правила (`ReadingRules`, ошибки списком до 10, как у Аудирования)

**Форма данных — всегда** (и у скрытого черновика, и в пакете):
- уровень, жанр, тип упражнения — из списков; у полей нужные типы (строка, число, массив, Loc); лишних полей нет
  (разбор строгий, как у Аудирования);
- Loc — только ключи `en`, `ru`, `kz`, значения — строки;
- пределы: заголовок 200, абзац 3000, абзацев 20, ключевых слов 30, упражнений 20, вопросов/пар/строк в
  упражнении 30, вариантов 8, любая прочая строка 1000; текстов в пакете — 2000;
- строки обрезаются по краям.

**Готовность — чтобы показать** (проверяется на «Показать», на правке показанного текста и при заливке текста без
`active: false`):
- заголовок, эмодзи обложки, `task.en`, хотя бы один абзац;
- ключевые слова: у каждого `en` и `ru`;
- 1–12 упражнений; у каждого `instruction.en`; у каждого Loc в тексте (разбор, пояснение, заголовок абзаца,
  подпись картинки) есть `en`;
- выбор: 1–12 вопросов; у `before/mc/vocab/finish` 2–6 вариантов, без повторов, `a` — индекс варианта;
  у `tf` — `true`/`false`, у `tfng` — `T`/`F`/`NG`;
- пары: 2–12, левые без повторов и правые без повторов (иначе две верные пары и перемешивание не сработает;
  Loc сравнивается по `en`, всё — без учёта регистра); в одном `match` все правые одного вида;
- порядок: 2–12 строк без повторов;
- пропуски: 1–20 `{ответов}`, фигурные скобки парные и не вложены, лишние слова (0–10) не совпадают с ответами
  без учёта регистра;
- свободный ответ: `q`, `model`, 1–10 групп ключей по 1–20 синонимов, `min` — от 1 до числа групп.

Текст, нарушающий готовность, можно сохранить скрытым — форма показывает, чего не хватает.

### Ручки

| Метод и путь | Доступ | Что |
|---|---|---|
| `GET /practice-content/reading/levels` | без входа | `[{level, count}]` показанных |
| `GET /practice-content/reading/{level}` | без входа | массив показанных текстов по `order_index` в форме файла сайта (`id`, `level` заглавными, `genre`, `title`, `cover`, `task`, `words`, `text`, `exercises`). `Cache-Control: public, max-age=300` |
| `GET /admin/practice/reading/texts?level=` | ADMIN | список: `id, level, genre, title, orderIndex, active, ready, missing` (`ru`/`kz` — каких переводов нет), `exercises` (число), `updatedAt` |
| `GET /admin/practice/reading/texts/{id}` | ADMIN | текст целиком + `active`, `ready`, `problems[]` (что мешает показать), `orderIndex`, `updatedAt` |
| `POST /admin/practice/reading/texts` | ADMIN | текст без `id` → `201`, создан **скрытым**, в конце уровня |
| `PUT /admin/practice/reading/texts/{id}` | ADMIN | правка; уровень не меняется (400); `id` в теле игнорируется; у показанного — правила готовности |
| `DELETE /admin/practice/reading/texts/{id}` | ADMIN | отметкой `deleted_at`, `204` |
| `PATCH …/texts/{id}/activate`, `…/deactivate` | ADMIN | показать (с проверкой готовности) / скрыть |
| `POST /admin/practice/reading/pack/diff` | ADMIN | `{items}` → новые / изменённые / без изменений / есть только на стенде / удалены на стенде |
| `POST /admin/practice/reading/pack/import` | ADMIN | upsert новых и изменённых |
| `GET /admin/practice/reading/pack/export` | ADMIN | все тексты, скрытые и удалённые — с `active: false` |

`active` в теле `POST`/`PUT` игнорируется: видимость меняют только `activate`/`deactivate`. Пакет: как у
Аудирования — импорт не удаляет то, чего нет в пакете, не воскрешает удалённое и не включает скрытое на стенде;
`active: false` в пакете скрывает. Медиа у раздела нет: в `PracticeMediaNames.SECTIONS` его не добавляем, в zip нет
папки `media/`, в манифесте `media: []`.

`SecurityConfig`: `GET /practice-content/**` уже `permitAll` (пилот). `docs/practice/PACK_FORMAT.md` — раздел
`reading` с таблицами выше.

## Админка (web-admin)

«Библиотека» → вкладка **«Чтение»** рядом с «Аудированием», маршруты `/system/library/reading`,
`…/reading/pack`, `…/reading/create`, `…/reading/{id}/edit`.

**Список:** уровни со счётчиками; строки — id, жанр, заголовок, число упражнений, пометки «нет ru» / «нет kz» /
«не готов», переключатель «Показан/Скрыт» (у неготового «Показать» выдаёт список проблем), «Изменить», «Удалить» (с
подтверждением). Кнопки «Добавить текст» и «Перенос между стендами» (пакет).

**Пакет:** общий `practice-content/practice-pack.ts` (zip, манифест, сверка); у Чтения шаг медиа пропускается. Экран
— по образцу `listening-pack`.

**Форма** (один экран, секции сверху вниз, «Сохранить» внизу и в шапке):
1. **Шапка:** уровень (при создании; дальше показан), жанр, заголовок, эмодзи обложки, задание к тексту (en/ru/kz).
2. **Абзацы:** поля текста, «+ абзац», «×», ↑↓.
3. **Ключевые слова:** строки «слово · транскрипция · ru · kz · пример», «+ слово», «×».
4. **Упражнения:** карточки, ↑↓, «×», «+ упражнение» → выбор типа (13 подписанных типов, сгруппированы по
   механике). У новой карточки инструкция заполнена стандартной для типа (самая частая инструкция этого типа в
   нынешних 80 текстах — таблица в коде формы). У каждой карточки: инструкция (en/ru/kz), разбор (en/ru/kz,
   необязательный) и редактор механики:
   - **Выбор:** вопрос (или утверждение у `finish/tf/tfng`); варианты строками с отметкой верного (у `tf` —
     «правда/ложь», у `tfng` — «да/нет/не сказано»); пояснение к ответу (en/ru/kz, необязательное); «+ вопрос».
   - **Пары:** строки «левое ↔ правое»; у `match` переключатель вида: «слово ↔ значение» (правое на en/ru/kz) или
     «слово ↔ картинка» (эмодзи + подпись en/ru/kz); у `headings` левое — «Абзац N» на трёх языках, по кнопке
     «заполнить по числу абзацев».
   - **Порядок:** строки в верном порядке; подсказка «ученик увидит их перемешанными».
   - **Пропуски:** текст, где ответ берётся в `{фигурные скобки}`, под ним — найденные ответы фишками; лишние слова.
   - **Свободный ответ:** вопрос, группы ключевых слов (синонимы через запятую, группа — строкой), минимум групп,
     образец ответа.
5. **Готовность:** список того, что мешает показать текст (считает форма теми же правилами, что сервер; сервер —
   окончательный судья), и кнопка «Показать» прямо из формы.
6. **Предпросмотр:** справа (на узком экране — вкладкой) текст, ключевые слова и упражнения так, как их видит
   ученик, с отмеченными верными ответами. Рисует админка своими средствами — компоненты сайта в Angular не
   встраиваются; задача — проверить содержание, а не пиксели.

Модель формы — чистый модуль `reading-form.model.ts` (документ ↔ состояние формы ↔ документ), правила готовности —
`reading-rules.ts`. **Главный тест:** каждый из 80 нынешних текстов проходит документ → форма → документ без единого
отличия — так видно, что пять редакторов покрывают все данные.

## Сайт (jts-web-app)

- `ReadingPage.jsx`, `fetchLevel`: через `loadPracticeContent('reading', level, '/practice/reading/<level>.json')`.
  С бэкенда приходит массив текстов — оборачиваем в `{level: 'A1', texts}`; со статики — как сейчас. `data-source` на
  корне экрана.
- `/api/practice/catalog`, `readingArea`: `${BACKEND_URL}/practice-content/reading/levels`, затем уровни с бэкенда;
  любой сбой или пусто — весь раздел с диска (не смешиваем источники внутри раздела).
- `scripts/practice-pack/build-reading.js` → `build/practice-packs/reading.zip`: 80 текстов из `public/` в порядке
  файлов, манифест `{section: 'reading', counts, media: []}`, `source: jts-web-app@<коммит>`.
- `dict.json`, `meta.json`, экстрактор и оракул движка не трогаем. Прототип `data/jtsreading.html` остаётся
  источником оракула; **после заливки правки контента идут в админку, а не в прототип** — это пишем в CLAUDE.md.

## Тесты

- **backend (Mockito, без WebMvc-срезов — они красные):** каждое правило формы и готовности; выдача id (формат,
  повтор хвоста); create — скрытый в конце уровня; activate неготового — 400 со списком; PUT показанного с поломкой
  — 400, скрытого — 200; delete → не отдаётся, id не переиспользуется; diff/import (скрытие, удалённое не
  воскресает); публичная форма: залитый `a1.json` возвращается тем же документом.
- **web-admin (karma):** модель формы — 80 текстов туда-обратно (фикстура — снимок `public/practice/reading` сайта);
  правила готовности; пакет без медиа; экран списка и формы — по образцу спеков Аудирования.
- **сайт (vitest):** `ReadingPage` с обоими источниками; каталог — бэкенд, сбой → диск; сборщик пакета (80 текстов,
  счётчики, `media: []`). **e2e:** спеки Чтения проходят и на статике, и с подменённым API.

## Проверка на деве

1. Залить пакет (владелец, в дев-админке) → 80/80; сайт `data-source="api"`, библиотека и текст как раньше.
2. Пройденные до переноса тексты остались пройденными (тот же аккаунт); домашка с текстом открывается.
3. Скрыть текст → пропал у ученика (≤5 мин) и из каталога преподавателя; показать → вернулся на место.
4. Новый текст формой: сохранить неготовым → скрыт, «Показать» перечисляет проблемы; дописать → показать → виден в
   конце уровня; пройти его учеником.
5. Удалить → пропал; выгрузка → в пакете скрытым.

## Порядок и вне рамок

Бэкенд → админка → сайт → заливка на дев → проверка → релиз develop → main (бэкенд первым) → заливка на прод →
проверка → PR чистки (удалить `public/practice/reading/<уровень>.json`, запасной путь, экстрактор перестаёт писать
файлы уровней).

Вне рамок: перестановка текстов внутри уровня руками (порядок задаёт пакет, новые — в конец), права преподавателя,
перевод формы на другие языки, автоперевод ru/kz, правка общего словаря тапа.
