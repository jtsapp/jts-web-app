# SpeakSpin в Практике — дизайн

Дата: 02.10.2026. Ветка `feat/speakspin` от `origin/develop`.

## Что это

Новый тренажёр говорения из прототипа `data/jts-speakspin.html`: случайная тема
(90 тем: по 30 на Easy A1–A2 / Medium B1 / Hard B2) → 30 с подготовки →
60 с записи → прослушать → ИИ-разбор. В прототипе разбор был выключен: в нём
оставлено место под сервер и описан контракт ответа v1.

## Решения владельца

- Вид — как в прототипе (макета нет).
- Свой дневной лимит разборов: 20 в сутки, демо 5, гостю разбор не положен.
- Баннер во вкладке «Говорение» после «Ситуаций».
- Анализ — Azure + Sonnet 5.5.

## Как устроено

**Данные.** `scripts/extract-speakspin.js` режет из html темы и словарик
(`src/practice/speakspin/topics.json`) и строки en/ru/kk (`strings.json`).
Темы лежат в `src`, потому что их читает и сервер: текст темы разбор берёт по
`topicId` сам, а не из запроса.

**Экран** — `src/screens/SpeakSpinPage.jsx`, `?screen=speakspin`. Движок —
скрипт прототипа, перенесённый модулем почти дословно
(`src/practice/speakspin/engine.js`, mount → destroy). Это его собственный
режим встраивания. Переписывать машину состояний на React значило бы заново
ловить гонки, которые прототип уже обработал (фон вкладки, отвалившийся
микрофон, отмена разбора). Экран живёт в **Shadow DOM**: классы прототипа
(`.hero`, `.spinner`, `.badge`, `.timer`…) совпадают с глобальными классами
приложения и без изоляции ломались.

Записи живут только в памяти вкладки. В localStorage (`jts-speakspin-v1`)
уходят лишь настройки и колоды тем, как в прототипе. С аккаунтом ничего не
синкается.

**Разбор** — `POST /api/practice/speakspin/assess` (WAV 16 кГц + метаданные):
1. Бесплатно отсекаем мусор.
2. Списываем разбор из лимита (`speakspinBudget.js`, миграция 0014).
3. Azure параллельно делает текст (Fast Transcription, запасной — Soniox) и
   оценку произношения.
4. Меньше 5 слов — `insufficient_audio`, попытка возвращается в лимит.
5. Sonnet 5.5 ставит 4 оси (выполнение задания, беглость и связность,
   грамматика, лексика) и пишет советы.
6. Произношение 1–5 переводится из балла Azure, модель его не ставит.

Ответ — контракт прототипа v1, клиент проверяет его своим `validateFeedback`.
Модель переопределяется env `SPEAKSPIN_MODEL`.

**Sonnet 5.5 и `structured()`.** Новые модели отвечают 400 на
`thinking: disabled` и на принудительный `tool_choice`. Для них `structured()`
берёт JSON через `output_config.format`. Остальные модели идут прежним путём
без изменений.

## Не сделано

- Калибровка перевода произношения 0–100 → 1–5 (пороги 45/60/75/88 — первая
  прикидка).
- Таймкоды цитат: у Azure нет выравнивания по словам, а неточные таймкоды
  контракт запрещает.
- Прогресс в аккаунте и статистика навыка.
- Вычитка казахского носителем.
