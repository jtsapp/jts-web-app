# Синхронизация языка раздела «Тьютор» с остальным приложением

Дата: 2026-07-27 · Ветка: `feat/tutor-i18n-sync` · PR в `develop`

## Проблема

В приложении две независимые i18n-системы:

| | Основное приложение | Раздел «Тьютор» |
|---|---|---|
| Провайдер | `I18nProvider` (`src/i18n.jsx`) | `LanguageProvider` (`src/i18n/LanguageContext.jsx`) |
| Хук | `useI18n` | `useLang` / `useT` |
| Ключ localStorage | `lang` | `jts.lang` |
| Коды языков | `ru` / `en` / `kk` | `ru` / `en` / `kz` |
| Где меняется | профиль, лендинг | только `TutorLanguagePage` в онбординге |

Следствия: смена языка в профиле не меняет язык тьютор-раздела (и наоборот),
код казахского различается (`kk` против `kz`), после онбординга язык тьютора
сменить негде.

## Решение: делегация

`LanguageProvider` вложен внутрь `I18nProvider` (см. `src/app/providers.jsx`),
поэтому он перестаёт хранить собственный стейт и становится тонким адаптером
над `useI18n`:

- **Источник правды один** — язык `I18nProvider`, ключ `lang`.
- **Маппинг кодов** — `kk → kz` при чтении (тьютор-словарь исторически на
  `kz`), `kz → kk` при записи через `setLang` тьютор-экранов.
- **Словари не сливаются** — `src/i18n/dict.js` остаётся отдельным: ключи
  (`welcome.title`, `common.back`, `kingdom.*`…) пересекаются с основным
  словарём, но несут другие тексты.
- **Публичный API не меняется** — `useLang`/`useT`/`t(key, vars)` работают как
  раньше; все ~25 тьютор-экранов не трогаем.
- **Миграция** — одноразовый перенос `jts.lang` в `lang` на импорте модуля (до
  первого рендера, чтобы не было мигания языка): если общий `lang` уже
  выбран — он главнее; ключ `jts.lang` удаляется в любом случае.

Поведение после изменения:

- смена языка в профиле мгновенно переключает тьютор-раздел;
- выбор языка в тьютор-онбординге (`TutorLanguagePage`) переключает всё
  приложение — что и задумывалось («выбор языка сразу меняет язык интерфейса»);
- у пользователей со старым `jts.lang` язык не теряется.

## Отвергнутые варианты

- **Полное слияние в один словарь** — конфликтующие ключи с разными текстами
  требуют массового переименования в ~25 файлах; большой дифф, тяжёлый
  бэкпорт в `main` (прод тьютора).
- **Переключатель внутри тьютора без объединения** — лечит симптом, двойная
  система и рассинхрон остаются.

## Тесты (Playwright, `tests/tutor-i18n.spec.js`)

1. `lang=kk` в профиле → тьютор-экраны на казахском.
2. Выбор «Қазақша» в тьютор-онбординге → `lang` становится `kk`, раздел
   «Практика» тоже на казахском.
3. Миграция: только `jts.lang=kz` → приложение поднимается на казахском,
   `lang=kk`, легаси-ключ удалён.
4. Приоритет: `lang=en` + `jts.lang=kz` → всё на английском, легаси-ключ
   удалён.

## Затронутые файлы

- `src/i18n/LanguageContext.jsx` — делегация + миграция (основной дифф).
- `src/app/providers.jsx` — только комментарий (описание архитектуры).
- `tests/tutor-i18n.spec.js` — новый спек.

Бэкпорт в `main` — черри-пик одного коммита (файлы совпадают на обеих ветках).
