# Онбординг и роадмап «Главной» (General English) по образцу IELTS — часть 1

Дата: 12.10.2026. Статус: дизайн согласован по секциям в разговоре (секции 1–3 — владельцем, 4–5 —
решения исполнителя, перечислены в конце).

## Зачем

Онбординг и маршрут раздела IELTS признаны лучше, чем у «Главной». У IELTS цепочка полная: анкета →
замер (диагностика) → срок до цели → выбор маршрута → план по дням. У «Главной» General English нет
анкеты (цель выбирается шагом тура), нет срока, нет маршрута и плана; калькулятор `src/lib/roadmap.js`
(ТЗ «Roadmap & AI Notification Engine» v2.0) написан, но в интерфейсе не используется.

## Разбиение

Весь объём («всё, как в IELTS, с планом по дням») — три части, у каждой свой цикл спека → план → код:

1. **Основа (этот документ):** анкета, профиль ученика на JTS-бэкенде, тест уровня как замер, экран
   «Как дойти до цели» со сроком и форматом, новый блок цели на «Главной».
2. **План по дням:** генератор задач на бэкенде (аналог `IeltsPlanner`), «Сегодня» и вид «План»,
   выполнение по фактам. Факты практики (тьютор, шэдоуинг, воркбук, словарь) лежат в базе веба —
   сервер веба будет сообщать бэкенду о выполнении служебным ключом (как `IELTS_GRADER_KEY`).
3. **Админка:** анкета и план ученика у преподавателя (по образцу `ielts-diagnostic-card`),
   переключение карточки преподавателя с `level_goal` на профиль бэкенда.

Вне всех трёх частей: мобильное приложение (Flutter), найденные баги IELTS (идут отдельно, после).

## Решения владельца

- Анкета и план живут на **JTS-бэкенде**, как у IELTS (не в базе веба). Это отменяет прежнее решение
  «цель — только в базе веба» (`level_goal`, 04.10.2026): источником правды становится профиль бэкенда.
- Макета нет — **визуально как IELTS new**: те же кирпичи (шаги с полосой, карточки-ответы, календарь,
  экран маршрута, баннер с маскотом), вынесенные в общие компоненты.
- **Новые ученики** проходят анкету сразу после регистрации; **уже учащиеся** — по приглашению с
  «Главной», ничего не запирается.
- Цель — **уровень, которого ученик хочет достичь**. Плитки A0–C1; C2 нет. A0 и всё не выше текущего
  уровня видны, но неактивны.
- Экран маршрута и формула срока — как в секции 2 ниже (подтверждено «ок»).

## Секция 1 — путь ученика и анкета

**Новый ученик:** регистрация → анкета → тест уровня → «Как дойти до цели» → «Главная». Сейчас после
теста ученик уходит в `kingdom` (`testExit` в App.jsx) — для пути из анкеты выход ведёт на маршрут.

**Уже учащийся** (уровень есть, анкеты нет): на «Главной» карточка «Составим ваш план» (текущий
уровень и процент + «Начать»). Анкета без шага 5 (уровень известен) и сразу ведёт на маршрут.

**Ученик на C1 и выше:** выбирать цель не из чего — шаг цели пропускается; если анкета ему ничего не
даёт (цели нет), «Главная» остаётся прежней с «Вы на высшем уровне», приглашения нет.

**Шаги анкеты** (`?screen=ge-onboarding`, режим фокуса без меню, полоса шагов, «Назад», «Выйти»):

1. **Зачем вам английский?** `work` Работа и карьера · `travel` Путешествия и переезд · `study` Учёба ·
   `self` Для себя. Картинки — из `public/ielts/onboarding/` (work, abroad, study, school).
2. **Какой уровень нужен?** Плитки A0, A1, A2, B1, B2, C1 с пояснением уровня. Неактивны A0 и всё
   ≤ текущего уровня (подпись «ваш уровень» / «пройдено»). Чип «Рекомендуем» по цели:
   work → B2, travel → B1, study → B2, self → B1; если рекомендованный ≤ текущего — следующий за
   текущим. Карточка «Пока не знаю» — берётся рекомендованный.
3. **К какому сроку?** «Есть дата» с календарём (прошедшие дни недоступны; до трёх лет вперёд) ·
   `1-3m` · `3-6m` · `6-12m` · `none` (без срока).
4. **Сколько времени в день?** 15 · 30 · 60 · 90 мин (по умолчанию 30). На карточке темп и «≈ N до
   цели» для самостоятельного формата. Уровень неизвестен (новый ученик до теста) — вместо срока
   «срок посчитаем после теста»: срок не выдумываем (у IELTS подстановка давала три разных срока).
   Если указана дата — плашка «успеваете / не успеть к {дата}» (тоже только при известном уровне).
5. **Знаете свой уровень?** (только без уровня) `zero` Начинаю с нуля — уровень A0 без теста ·
   `some` Немного знаю — тест · `known` Знаю, хочу подтвердить — тест. Внизу — сводка ответов чипами.

Кнопка «Продолжить» неактивна, пока шаг не заполнен. Тест можно отложить («Пройду позже») — тогда
«Главная» показывает следующий шаг «Пройдите тест — посчитаем срок».

**Режим правки** (`?screen=ge-onboarding&geEdit=1`): только шаги 2–4 с подставленными ответами; после
сохранения — экран маршрута. Повторно проходить всю анкету и тест не нужно.

## Секция 2 — «Как дойти до {цель}» и расчёт срока

Экран `?screen=ge-route`, в обычной раскладке с меню. Без уровня маршрут не считается — экран
предлагает тест.

**Осталось уроков** (`remainingLessons`): сумма курсов силлабуса от текущего уровня до цели
(`SYLLABUS_LESSONS` из `roadmap.js`: A0 24, A1 32, A2 36, B1 36, B2 48) минус пройденная доля курса
текущего уровня: `round(percent / 100 × SYLLABUS[current])`, где `percent` — из
`/mobile/level-progress`. Пример: B1, 50 % → до B2 = 36 − 18 = 18 уроков. Прогресс не пришёл — доля 0.

**Три карточки** — формула `estimateWeeks` из `roadmap.js` (K_eff формата, ускорение за домашку,
буфер повторения 1.15):

| Карточка | `learningFormat` | Пропускная способность |
|---|---|---|
| Самостоятельно | `self_study` | минуты/день × 5 дней ÷ 90 мин на урок |
| В группе | `group` | 2 занятия в неделю + ускорение за домашку (минуты/день) |
| Индивидуально | `individual_60` | 2 занятия по 60 мин в неделю + ускорение |

Допущения — константы модуля (`GE_SESSIONS_PER_WEEK = { group: 2, individual: 2 }`, 5 учебных дней —
`DEFAULT_STUDY_DAYS_PER_WEEK`). Пример B1→B2 с нуля курса (36 уроков), 30 мин/день: 30 / 20 / 16
недель ≈ 7 / 4,5 / 3,5 мес (месяц = 4.345 недели, округление до полумесяца).

**Как писать срок:** до 18 месяцев — месяцами (шаг полмесяца), дальше — годами с шагом полгода
(«≈ 2,5 года»). Длинный срок не прячем: путь A0→C1 длинный, это нормально.

**Успеваете ли:** дата задана — сравниваем с ней; окно — с его верхней границей от дня сохранения
(1-3m → +3 мес, 3-6m → +6, 6-12m → +12; дату считает бэкенд, `deadline.date`); `none` — чипа нет. Чипы как в IELTS: «Успеваете» /
«С запасом» (остаётся ≥ 21 дня) / «Не успеваете к …».

**Рекомендация** (звезда на одной карточке), по порядку:
1. Есть срок, самостоятельно не успеваете, группа успевает → группа.
2. Группа не успевает, индивидуально успевает → индивидуально.
3. Не успевает никто → индивидуально + плашка «к сроку не успеть — сдвиньте срок или добавьте время».
4. Срока нет или все успевают: цель `work` или `study` и разрыв ≥ 2 уровней → группа; иначе
   самостоятельно.

**Выбор** пишется в профиль (`route`): `self_study` → «Главная»; `group` / `individual` → тарифы
(`pricing`). Если ученик уже занимается с преподавателем (`track: 'LESSONS'` из level-progress или
занятия GROUP / INDIVIDUAL_* в расписании) — его карточка помечена «Ваш формат», кнопка «Продолжить»
ведёт на «Главную» без тарифов. Цель после теста оказалась ≤ уровня — вместо карточек «Цель уже
достигнута — выберите новую» → режим правки.

## Секция 3 — «Главная»

Верхний блок «Главной» (не IELTS-аккаунт, не преподаватель) выбирается по профилю:

| Состояние | Что видно |
|---|---|
| ручки профиля нет (бэкенд старый, 404) | прежняя карточка уровня и тур с выбором цели — без изменений |
| уровня нет, анкеты нет | прежняя карточка «Пройдите тестирование» → **анкета** (а не test-intro) |
| уровень есть, анкеты нет | «Составим ваш план» → анкета |
| анкета есть, уровня нет | шаг «Пройдите тест — посчитаем срок» |
| анкета и уровень есть, маршрута нет | шаг «Выберите, как будете заниматься» → маршрут |
| всё есть | **блок цели** |

**Блок цели** (по образцу `GoalBanner`):
- Маскот с репликой (`public/ielts/mascot/`), 2–3 варианта фразы на состояние: цель достигнута ·
  срок сегодня / завтра / прошёл · срок не указан · не успеваете при выбранном формате («добавьте
  минут или смените формат») · идёте по плану («до B2 ≈ 5 мес»).
- Заголовок: «N дней до срока» + карандаш / «≈ к {месяц год}» для окна / «Срок не указан» +
  «Указать срок» / «Срок прошёл» + «Обновить цель».
- Дорожка «Старт → Сейчас → Цель»: `fromLevel` → текущий уровень с процентом → цель. Ниже — прежние
  строки «Ещё N материалов — и вы на {следующий}» и «+N % за неделю».
- Клик по блоку — экран маршрута с пересчётом. Цель достигнута — трофей и «Приобрести следующий курс».
- Карандаш / «Изменить цель» / «Указать срок» — анкета в режиме правки.

**Тур «Главной»:** первый шаг — подсказка про блок цели без выбора внутри («Ваша цель и срок — нажмите,
чтобы увидеть путь»). Остальные шаги (навыки, «Что сделать сегодня», расписание) без изменений. При
старом бэкенде (404) тур прежний.

Не меняются: IELTS-аккаунт (`IeltsHomeCard`), преподаватель, остальные блоки «Главной». Демо-аккаунт
проходит ту же анкету. Мобильный слой — правила нового блока в `src/mobile/home.css`.

## Секция 4 — устройство

### Бэкенд (`backend`, модуль `ge`, по образцу `ielts`)

Миграция `V327__Ge_profiles.sql` (номер сверить с develop перед мержем — занятые номера уже ломали
выкатку):

```sql
CREATE TABLE ge_profiles (
    user_id         BIGINT PRIMARY KEY REFERENCES users (id) ON DELETE CASCADE,
    purpose         VARCHAR(10) CHECK (purpose IS NULL OR purpose IN ('work', 'travel', 'study', 'self')),
    target_level    VARCHAR(2)  CHECK (target_level IS NULL OR target_level IN ('A1', 'A2', 'B1', 'B2', 'C1')),
    from_level      VARCHAR(2),
    deadline_date   DATE,
    deadline_window VARCHAR(10) CHECK (deadline_window IS NULL OR deadline_window IN ('date', '1-3m', '3-6m', '6-12m', 'none')),
    daily_minutes   SMALLINT,
    start_mode      VARCHAR(10) CHECK (start_mode IS NULL OR start_mode IN ('zero', 'some', 'known')),
    route           VARCHAR(12) CHECK (route IS NULL OR route IN ('self_study', 'group', 'individual')),
    onboarded_at    TIMESTAMP,
    route_at        TIMESTAMP,
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW()
);
```

Ручки (`/mobile/ge`, любой вошедший; IELTS-замка нет):

- `GET /mobile/ge/profile` → `ProfileView`:
  `{ onboarded, purpose, targetLevel, fromLevel, deadlineDate, deadlineWindow, dailyMinutes, startMode,
  route, onboardedAt, deadline: { state, date, daysRemaining, approximate }, journey: { start, current:
  { level, percent }, target, reached } }`.
  - `deadline.state`: `none | today | tomorrow | days | passed`. Окно при сохранении переводится в дату
    (день сохранения + верхняя граница окна) и хранится в `deadline_date` рядом с самим окном;
    `approximate: true`, если окно не `date`. Так правка срока считает от дня правки, а не от первой анкеты.
  - `journey.current.level` — `users.language_level`, `percent` — `LevelProgressService.summaryFor`.
    `reached` = уровень ≥ цели. `fromLevel` пуст, а уровень появился (тест после анкеты) — заполняется
    текущим и сохраняется.
- `PUT /mobile/ge/profile` — анкета или правка: `{ purpose, targetLevel, deadlineDate, deadlineWindow,
  dailyMinutes, startMode }`. Проверки: значения из наборов; `targetLevel` выше известного уровня;
  дата — от сегодня до трёх лет; `dailyMinutes` ∈ {15, 30, 60, 90}. `startMode = zero` при пустом
  уровне ставит `users.language_level = A0`. `onboarded_at` ставится один раз.
- `PUT /mobile/ge/profile/route` — `{ route }`: `self_study | group | individual`; без анкеты — 400.
- `POST /mobile/ge/profile/legacy-goal` — `{ targetLevel, fromLevel }`: разовый перенос цели из
  `level_goal`; пишет только если цели в профиле нет, анкету пройденной не делает. C2 → C1.

Бэкенд строгий к лишним полям JSON — веб с новыми полями катится **после** бэкенда.

### Веб (`jts-web-app`)

- **Чистые модули** (vitest): `src/ge/onboarding.js` — шаги, наборы, рекомендованная цель, доступные
  плитки, тело PUT; `src/ge/route.js` — `remainingLessons`, `routeTerms` (поверх `estimateWeeks`),
  `fitsDeadline`, `recommendRoute`, `formatTerm`; `src/ge/goalState.js` — состояние блока цели.
- **Общие кирпичи онбординга** из `IeltsOnboardingPage.jsx` → `src/components/onboarding/`
  (`OnboardingFrame`, `OptionCard`, `ImageCard`, `Calendar`). IELTS переходит на них без видимых
  изменений; классы `ih-ob*` остаются.
- **Экраны:** `src/screens/GeOnboardingPage.jsx`, `src/screens/GeRoutePage.jsx`,
  `src/screens/home/GeGoalBanner.jsx`, `src/screens/home/GePlanInvite.jsx` (приглашение и следующий
  шаг). Ветки в App.jsx: `ge-onboarding` (режим фокуса), `ge-route`.
- **API** (`src/api.js`): `getGeProfile` (404 → `null` = «ручки нет», кэш как у `getIeltsMe`),
  `saveGeProfile`, `setGeRoute`, `importLegacyGoal`.
- **Поток в App.jsx:** после регистрации и при «Пройдите тестирование» — `ge-onboarding`, если ручка
  есть и анкеты нет (IELTS-аккаунт, преподаватель, класс, TUTOR_ONLY — как раньше). Анкета → тест
  (`testReturn = 'ge-route'`) или сразу маршрут.
- **Цель из `level_goal`:** при заходе на «Главную», если в профиле бэкенда цели нет, а в `level_goal`
  (или кэше) есть — `importLegacyGoal` один раз. До части 3 веб **дублирует** цель в `level_goal` при
  каждом сохранении анкеты: карточка преподавателя в web-admin читает её оттуда
  (`/api/admin/student-activity`) и держит копию `levelTrack` — форма `{target, from}` не меняется.
- **i18n:** ключи `geOb.*`, `geRoute.*`, `geGoal.*` в `src/i18n.jsx` (ru/kk/en), зона `useI18n`.
- **Стили:** кирпичи IELTS (`ielts.css`) как есть; своё — в файл раздела «Главной»; мобильное — в
  `src/mobile/home.css`.

## Секция 5 — проверка и выкатка

- **Бэкенд:** юнит-тесты `GeProfileService` (проверки, `deadline`, `journey`, `fromLevel`, перенос
  цели, A0 для `zero`) без Testcontainers; `./gradlew test` по модулю.
- **Веб:** vitest для `src/ge/*` (числа срока против `roadmap.js`: B1 50 %→B2 = 18 уроков, таблица
  примеров; правила рекомендации; окно как срок; формат срока), `goalState`, `HomePage` по состояниям
  таблицы секции 3 (включая 404 = прежняя главная); playwright `tests/ge-onboarding.spec.js` с моками
  `/mobile/ge/*`: новый ученик (анкета → тест → маршрут), учащийся (приглашение → анкета без шага 5 →
  маршрут), правка цели. Плюс `npm run build`, `npm run lint`, прогон IELTS-онбординга после выноса
  кирпичей.
- **Выкатка:** PR бэкенда → develop → dev-server; затем PR веба → develop → dev-tutor; проверка вживую.
  В прод — бэкенд в main первым. Пока прод-бэкенд без ручки, прод-веб показывает прежнюю «Главную»
  (404 → старый путь), отдельный флаг не нужен.

## Решения исполнителя (секции 4–5)

- Формула срока — `roadmap.js` (ТЗ Roadmap), а не часы IELTS: она уже покрыта тестами и описывает
  именно форматы JTS.
- Срок в анкете и на маршруте считает веб (как `estimateTerm` у IELTS); в Java формулу переносит
  часть 2 вместе с планировщиком.
- Деградация по 404 вместо флага по домену.
- Двойная запись цели в `level_goal` до части 3 — чтобы не сломать карточку преподавателя.
