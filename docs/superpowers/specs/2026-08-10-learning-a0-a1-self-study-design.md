# A0 и A1 self-study в разделе «Обучение»

Дата: 2026-08-10
Статус: согласовано

## Задача

Курсы Just to Study A0 и A1 существуют как самодостаточные HTML-файлы с тремя
режимами работы (Self-Study, 1-to-1, Group Study). Их ветку **Self-Study** нужно
перенести в раздел «Обучение» нативно — теми же React-компонентами и тем же
дизайном, что и нынешние уроки-королевства, с тропой и картой.

Дизайн существующих уроков и тропы сохраняется: новые данные ложатся в
существующий формат, плеер расширяется двумя типами задания, ничего из
существующего не переименовывается и не переверстывается.

## Источник данных

Источник правды — **исходные файлы курса** `a0.html` и `a1.html`.

Внутри каждого — объявления `UNITS`, `LESSONS`, `REVIEWS`, `AUDIO_B64`. Урок это
объект с полями `unit / no / title / blurb / VOCAB / IMG / SLIDES / tracks / html`,
а `html` — семь секций `<section class="stage" data-stage="…">`, внутри которых
блоки трёх режимов помечены `data-only="self|solo|group"`.

Опубликованные админкой пофайловые уроки
(`files-dev.justtostudy.kz/development/course-catalog/a0/lessons/L01.html?mode=self`)
источником быть **не могут**: конвертер вырезает из них ключи ответов — в
проверенном L01 нет ни одного `data-answer`, ни одного `<select>` и ни одного
`data-why`. Нативному плееру нечего было бы проверять.

Раздел «Обучение» к API каталога уровней (`/mobile/course-catalog`) не
подключается — данные остаются статикой в `public/learning/`, как сейчас.

## Конвейер

Новый `scripts/extract-jts-self-lessons.js` — по образцу
`scripts/extract-kingdom-lessons.js` и с тем же выходным контрактом.

Вход: путь к файлу курса (`--src <файл>`), код уровня выводится из самого файла.

Шаги:

1. Достать объявления курса из файла. Формат разный: A0 хранит урок одной
   строкой с JSON-совместимыми ключами, A1 — pretty-print с невалидным для JSON
   синтаксисом (некавыченные ключи, шаблонные строки). Поэтому литерал
   вырезается по балансу скобок с учётом `'`, `"` и бэктиков, и вычисляется как
   JS-выражение — источник свой, скачанный нами.
2. Оставить ветку `self`: удалить все узлы `[data-only]`, в списке которых нет
   `self`. Та же семантика, что у `prune-by-mode.ts` в web-admin.
3. Разрезать урок по стадиям: **каждая стадия становится отдельным узлом
   тропы**. Код узла — `L01-1 … L01-7`, заголовок — «<название урока> ·
   <стадия>», `unit` — из `UNITS`. Так длина узла остаётся 15–20 экранов, как в
   нынешних уроках, вместо 130.

   В A1 состав стадий плавает: помимо общих (Intro, Words, Grammar, Practice,
   Listen, Write, Done) встречаются разовые вроде «Riddles» или «Hotel» на
   один-два экрана. Узел короче трёх экранов не создаётся: его задания
   дописываются в предыдущий узел урока, а если предыдущего нет — в следующий.
   Иначе на тропе появляются «печеньки» из одного клика.
4. Юнит-тесты (`REVIEWS`) дают узлы `R01…` с типом `final`.
5. Перевести задания в нативные типы (таблица ниже). Строка задания (`.row`) —
   один экран плеера, порядок сохраняется.
6. Записать `public/learning/<level>.json` и обновить `public/learning/index.json`.

### Маппинг заданий

| Источник | Нативный тип | Примечание |
|---|---|---|
| `.opts[data-correct]` | `choice` | правильный — по индексу из `data-correct` |
| `<select data-answer>` | `choice` | варианты из `<option>`, ответ из `data-answer` |
| `input[data-answer="a\|b"]` | `gap` | `answers[]` — разбор по `\|` |
| `.order[data-order]` | `order` | **новый тип** |
| `.opts[data-multi]` | `multi` | **новый тип**, ответ — набор индексов |
| чеклист стадии Wrap | `check` | без оценки, как сейчас |
| `.segbtn` + `data-track` | `listen` | ссылка на аудио файл-сервера |
| bubble, grammar-reference, карточки слов | `info` | html переносится как есть |

`data-why` кладётся в поле `why` задания и показывается в блоке фидбэка рядом с
правильным ответом.

### Медиа

Аудио **не выносится**: треки уже опубликованы админкой и отдаются публично по
`https://files-dev.justtostudy.kz/development/course-catalog/<level>/audio/<файл>.mp3`.
Имена файлов совпадают с ключами `AUDIO_B64` в исходнике, так что ссылка
собирается без загрузки. Проверено: `a0/audio/a0_01cf00421b.mp3` → 200, 757 КБ.

Картинки словаря A0 (201 файл, ~8 МБ) в опубликованный бандл не попали. Они
выносятся экстрактором в `public/learning/media/a0/` — тот же локальный staging
под `.gitignore`, что и у остального медиа раздела, — и заливаются `mc mirror`
на `https://files-api.iqra.space/development/learning-media`, куда смотрят
ссылки в JSON. В git уходит только лёгкий JSON.

Заливка требует доступа к бакету и делается отдельным шагом. Пока картинки не
залиты, карточка слова рендерится текстом: ссылка ведёт в 404, `onError`
прячет изображение — экстрактор и плеер не падают.

## Изменения в плеере

`src/learning/LessonPlayer.jsx` получает два компонента в существующем дизайне —
на тех же классах `kl-opt`, `kl-chip`, `kl-fb`, `kl-btn`:

- **`Order`** — сборка предложения кликами по чипам: клик добавляет слово в
  строку ответа, повторный клик убирает; проверка сравнивает порядок с
  `data-order`.
- **`Multi`** — множественный выбор: верно, когда набор отмеченных совпадает с
  эталонным.

Оба добавляются в `GRADED`, то есть дают монеты за верный ответ и снимают сердце
за неверный — как `choice`/`gap`/`chips`.

Блок фидбэка дополняется строкой `why`, когда она есть у задания.

Стили — в `styles.css` рядом с существующими `kl-*`, без новых CSS-модулей.

## Карта и тропа

`src/kingdoms.js`: уровни съезжают по узлам на один, города, короли, цвета колец
и позиции остаются на местах.

| Город | Было | Стало |
|---|---|---|
| Redtown | A1 | **A0** |
| Bluewave Town | A2 | A1 |
| Green Peace Town | B1 | A2 |
| Music Town | B2 | B1 |
| Cocalastic Town | C1 | B2 |
| Rosewind Town | C2 (coming soon) | C1 |

Уровень C2 из раздела исчезает. `computeKingdoms` по умолчанию открывает A0
вместо A1. Сама тропа, «печеньки» по типу первого задания узла и кольцо
прогресса не меняются.

Контент привязан к уровню, а не к городу: `a2.json`, `b1.json`, `b2.json`,
`c1.json` остаются как есть и обслуживают свои уровни, просто на других узлах
карты. Перегенерируются только `a0.json` (новый) и `a1.json` (заменяется).

## Админка

- `MODULE_LEVELS` в `web-admin/src/app/feature/system/lesson-modules/lesson-module.model.ts`
  дополняется уровнем A0, иначе модуль A0 не завести через UI.
- На `/system/lessons` заводится модуль A0 и переназначается модуль A1:
  `indexUrl` указывает на уже опубликованный бандл
  `.../development/course-catalog/<level>/index.html`, `lessonCount` — по числу
  узлов тропы. Это ручной шаг в UI, не код.
- Прогресс и квоты студентов ходят через `moduleId`, поэтому появление модуля A0
  достаточно — ничего в логике прогресса не меняется.

Бэкенд не меняется: `LanguageLevel` уже содержит A0.

## Тесты

- `tests/learning-extractor.spec.js` — существующий файл, дополняется набором на
  новый экстрактор: фикстура-обрезок курса с одним уроком на каждый тип задания,
  проверки разбиения по стадиям, кодов узлов, ссылок на аудио, разбора
  `data-answer` с несколькими вариантами и переноса `why`.
- `tests/learning-lesson.spec.js` — дополняется рендером `order` и `multi`:
  верный и неверный ответ, начисление монет и снятие сердца, показ `why`.
- Перед PR: `npm test`, `npm run lint`, `npm run build` и ручной прогон тропы A0
  через `?screen=kingdom`.

## Что осознанно не делается

- Режимы 1-to-1 и Group Study в раздел «Обучение» не переносятся — они остаются
  учительским сценарием в каталоге уровней.
- Задания на запись голоса (`.rec`) в ветке self отсутствуют, отдельной
  поддержки не требуют.
- Раздел не переводится на API каталога: данные остаются статикой.
