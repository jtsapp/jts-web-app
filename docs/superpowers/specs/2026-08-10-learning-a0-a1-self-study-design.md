# A0 и A1 self-study в разделе «Обучение»

Дата: 2026-08-10
Статус: согласовано

## Задача

Курсы Just to Study A0 и A1 существуют как самодостаточные HTML-файлы с тремя
режимами работы (Self-Study, 1-to-1, Group Study). Их ветку **Self-Study** нужно
перенести в раздел «Обучение» нативно — теми же React-компонентами и тем же
дизайном, что и нынешние уроки-королевства, с тропой и картой.

Дизайн существующих уроков и тропы сохраняется: новые данные ложатся в
существующий формат, плеер расширяется двумя типами задания (`order`, `multi`)
и кнопкой озвучки на существующих токенах, ничего из существующего не
переименовывается и не переверстывается.

## Источник данных

Источник правды — **исходные файлы курса** `a0.html` и `a1.html`.

Внутри каждого — объявления `UNITS`, `LESSONS`, `REVIEWS`, `AUDIO_B64`. Урок это
объект с полями `unit / no / title / blurb / VOCAB / IMG / SLIDES / tracks / html`,
а `html` — семь секций `<section class="stage" data-stage="…">`, внутри которых
блоки трёх режимов помечены `data-only="self|solo|group"`.

Опубликованные админкой пофайловые уроки
(`files-dev.justtostudy.kz/development/course-catalog/a0/lessons/L01.html?mode=self`)
источником быть **не могут**: конвертер вырезает из них ключи ответов — в
проверенном L01 нет ни одного `data-answer`, ни одного `<select>` и ни одного
`data-why`. Нативному плееру нечего было бы проверять.

Раздел «Обучение» к API каталога уровней (`/mobile/course-catalog`) не
подключается — данные остаются статикой в `public/learning/`, как сейчас.

## Конвейер

Новый `scripts/extract-jts-self-lessons.js` — по образцу
`scripts/extract-kingdom-lessons.js` и с тем же выходным контрактом.

Вход: путь к файлу курса (`--src <файл>`), код уровня выводится из самого файла.

Шаги:

1. Достать объявления курса из файла. Формат разный: A0 хранит урок одной
   строкой с JSON-совместимыми ключами, A1 — pretty-print с невалидным для JSON
   синтаксисом (некавыченные ключи, шаблонные строки). Поэтому литерал
   вырезается по балансу скобок с учётом `'`, `"` и бэктиков, и вычисляется как
   JS-выражение — источник свой, скачанный нами.
2. Оставить ветку `self`: удалить все узлы `[data-only]`, в списке которых нет
   `self`. Та же семантика, что у `prune-by-mode.ts` в web-admin.
3. Разрезать урок по стадиям: **каждая стадия становится отдельным узлом
   тропы**. Код узла — `L01-1 … L01-7`, заголовок — «<название урока> ·
   <стадия>», `unit` — из `UNITS`. Так длина узла остаётся 15–20 экранов, как в
   нынешних уроках, вместо 130.

   В A1 состав стадий плавает: помимо общих (Intro, Words, Grammar, Practice,
   Listen, Write, Done) встречаются разовые вроде «Riddles» или «Hotel» на
   один-два экрана. Узел короче трёх экранов не создаётся: его задания
   дописываются в предыдущий узел урока, а если предыдущего нет — в следующий.
   Иначе на тропе появляются «печеньки» из одного клика.
4. Юнит-тесты (`REVIEWS`) дают узлы `R01…` с типом `final`.
5. Перевести задания в нативные типы (таблица ниже). Строка задания (`.row`) —
   один экран плеера, порядок сохраняется. Внутри `.task` обходятся не только
   строки: подписи частей рядом с ними («Part 1 · Grammar and vocabulary»,
   «questions 1–12», «Choose the correct answer», «Part 2 · Write the answer»)
   становятся `info` на своём месте — 28 таких элементов в A0 и 32 в A1, все в
   юнит-тестах. Без них узел `R01` открывается семнадцатью вопросами подряд без
   единого пояснения, что это тест и что вторая часть на ввод. Кнопка курса
   «Check answers» и пустой `.res` рядом — контролы его собственной проверки, в
   плеере их роль играет своя кнопка: потерянным контентом они не считаются и в
   сводку не идут.
6. Записать `public/learning/<level>.json` и обновить `public/learning/index.json`.

### Маппинг заданий

| Источник | Нативный тип | Примечание |
|---|---|---|
| `.opts[data-correct]` | `choice` | верный — кнопка, чей `data-val` равен `data-correct` |
| `<select data-answer>` | `choice` | варианты из `<option>`, ответ из `data-answer` |
| `input[data-answer="a\|b"]` | `gap` | `answers[]` — разбор по `\|` |
| `.order[data-order]` | `order` | **новый тип**, ранг чипа — позиция его `data-val` в `data-order` |
| `.opts[data-multi]` | `multi` | **новый тип**, ответ — набор кнопок с перечисленными `data-val` |
| `.opts` без ключа ответа | `check` | самооценка курса, без оценки — как `check` выпущенных уровней |
| `button.btn-audio` с `playTrack(id,…)` / `playRange(A(id),…)` | `listen` | id трека разбирается из inline-вызова, ссылка собирается на файл-сервер |
| `sayWord('word')` рядом с вариантами | поле `say` у задания | слово читает синтез речи браузера (ниже) |
| `sayText(this)` с `data-say="…"` | `info` + поле `say` | абзац для чтения возвращается на экран текстом (ниже) |
| bubble, grammar-reference, карточки слов | `info` | html переносится с чисткой (ниже) |

Ключ ответа — **значение кнопки, а не индекс**: A0 пишет `data-correct="0"` при
`data-val="0","1",…`, A1 — `data-correct="c"` при `data-val="a","b","c"`.
Одна модель на оба уровня: ищем позицию кнопки с таким `data-val`, числовой
формат A0 работает сам собой. Спецкейсов по уровню в конвейере нет.

`data-why` кладётся в поле `why` задания и показывается в блоке фидбэка рядом с
правильным ответом.

### Кикер, заголовок и подзаголовок задания

`sec` — «`<номер стадии>. <название стадии>`» (`2. Vocabulary`): плеер разбирает
номер через `splitSec` и рисует его отдельным чипом, как на выпущенных уровнях
A2–C1. Номер — место стадии в исходном уроке, а не среди узлов тропы.

`title` и `sub` у заданий self-курсов **намеренно пустые**. Инструкции урока
(«Listen. Choose the word you hear.») переносятся отдельными info-блоками перед
вопросами, как их писала методика; дублировать их в заголовок каждого экрана
значило бы придумать заголовок за автора курса.

### Задания на слух без аудиофайла

260 строк ветки self в A0 — 240 стадии Vocabulary и 20 стадии Practice —
звучали не файлом, а синтезатором речи браузера:
`<button class="segbtn" onclick="sayWord('repeat')">🔊 Word 1</button>` рядом с
вариантами ответа. Кнопка — контрол исходного курса и из разметки уходит, а
вместе с ней уходило и само задание: на экране оставались «Listen. Choose the
word you hear.» и четыре слова, то есть угадайка один к четырём ценой в сердце.
До плеера доезжает 250 из них: 10 строк «13 or 30?» стадии Practice отбракованы
(см. ниже) — не из-за озвучки.

Есть и третье место с `sayWord` — 288 иконок 🔊 в списках слов стадии Wrap
(`<span class="wspk" onclick="sayWord('like')">🔊</span>` рядом со словом
«like»). Это не задание: слово там написано текстом, ответ ни от чего не
зависит, и иконка уходит как обычный мёртвый контрол вместе с остальными. Само
слово остаётся на месте.

Поэтому слово из вызова `sayWord` едет в задание отдельным полем `say`
(механика привязана к строке `.row`, а не к типу: поле навешивается один раз
поверх готового задания, поэтому `choice`, `multi`, `gap`, `order` и `check`
получают его одинаково), а озвучивает его плеер — Web Speech API, без новых
зависимостей. Параметры перенесены из `sayWord()` исходника: отмена предыдущей
реплики, `lang='en-GB'`, `rate=0.85`. Текстом слово не показывается — оно и
есть ответ. Ответ на такое задание засчитывается в навык Listening независимо
от названия стадии.

Синтез есть не везде. Наличия объектов Web Speech API недостаточно: в Android
WebView без установленных голосовых данных, в части сборок Linux и при
отключённом голосовом движке `speechSynthesis` есть, `getVoices()` пуст, а
`speak()` молчит. Поэтому доступным синтез считается, только когда есть хотя бы
один голос; список асинхронный, и плеер подписан на `voiceschanged`. Отдельно
ловится тихий отказ движка: у реплики есть `onerror`, и первая же ошибка (кроме
собственных отмен `canceled`/`interrupted`) переводит урок в текстовый режим.

Без синтеза плеер показывает слово текстом и **снимает задание с начисления**:
ни монет, ни снятого сердца, ни записи в рейтинг навыков. Проверка и фидбэк при
этом остаются: упражнение с подсказанным ответом всё ещё упражнение, а экран, на
котором варианты кликаются и не делают ничего, теряет смысл целиком.
Альтернатива — оставить начисление и не показывать слово — и есть та самая
угадайка, ради которой всё делалось.

### Текст для чтения, живущий в атрибуте кнопки

Семь абзацев A1 курс хранит только в атрибуте своей кнопки:
`<button class="btn-audio" onclick="sayText(this)" data-say="Phone battery
dying? First, open Settings…">`. В уроках 16 и 25 это ЕДИНСТВЕННЫЙ носитель
текста — на экране его нет ни в каком другом виде, а кнопка уходит как мёртвый
контрол курса. Узлы `L16-6` и `L25-6` получались с восемью и семью оценочными
вопросами про текст, которого студент нигде не видит: при трёх сердцах такой
узел заваливается почти гарантированно.

Кнопка заменяется абзацем на её месте: текст встаёт туда, где студент ждал
плеер, и попадает в тот же `info`-блок, что и подпись рядом («Video 1 — the
battery»). Поле `say` при этом сохраняется — в исходнике абзац именно
озвучивали, и плеер даёт ту же кнопку озвучки, что и словам, только с подписью
`t('lesson.say.playText')`. Если тот же текст в стадии уже напечатан (урок 1 —
транскрипт в `<details>` рядом с плеером), второй копии не добавляем: озвучка
работает, дубля на экране нет.

Оставшиеся вопросы `L25-6` («ice was thicker than a wall», «pollution») текстом
не покрыты: инструкция стадии обещает «two texts», а в исходнике их нет ни в
одном режиме — дефект самого курса, восстанавливать тексты значило бы придумать
их за автора.

### Чистка info-разметки

Плеер печатает info через `dangerouslySetInnerHTML`, а скриптов исходного курса
в приложении нет. Поэтому из info уходят:

- элементы с inline-обработчиком курса (`sayWord`, `cardAdd`, `slide`,
  `sayText`, `check`, неразобранные `btn-audio`) — вместе с `<label>`, если
  контрол был подписан (у `sayText` текст из `data-say` перед этим возвращается
  на экран, см. выше);
- контролы формы (`input#trToggle` и подобные) — курс подключал их скриптом по
  id, в приложении они мертвы;
- **любая оставшаяся `<button>`**: контролы, подключённые делегированием по
  классу, inline-обработчика не имеют и первую версию правила пережили — 112
  кнопок `.opt` в A0 и 10 кнопок `.say` в A1 (у последних обработчика нет даже
  в исходнике). Классов `.opt`/`.opts`/`.say` в `styles.css` нет, поэтому они
  рисовались дефолтными кнопками браузера внутри карточки урока и ничего не
  делали при нажатии. К этому месту кнопка, несущая смысл, уже стала блоком
  (`audio`, `check` или заданием), так что в info кнопок не остаётся вовсе;
- контейнеры, опустевшие после этого или изначально наполнявшиеся скриптом
  (`div.words#words`, `div.slide#slide`, `div.dots#dots`, обёртка `.slider`) —
  заодно исчезают дублирующиеся в DOM id.

Текст, таблицы, списки, `<details>` со справкой и картинки остаются целиком.
Блок, который после чистки не содержит ничего, попадает в сводку потерь.

### Самооценка без правильного ответа

`.opts` без `data-correct` и `data-multi` курс не проверял: `check()` в
исходнике считает только группы с ключом ответа, а делегированный обработчик
лишь подсвечивал выбранное. Это два сюжета A0 на 25 узлов и 47 заданий `check` вместе — разминка
«No right or wrong — just you.» (одно упражнение на 10 карточек, узел `L01-1`) и
диалог с Сэмом, где студент выбирает свою реплику (остальные 24 узла). Удалять их вместе с кнопками нельзя: в диалоге
текст реплик живёт внутри кнопок и исчез бы вместе с ними.

Обе становятся заданиями типа `check` — тем же неоценочным чек-листом, что у
выпущенных уровней A2–C1 (`type: check` в `a2.json`), без монет и без сердец:

- у разминки кнопки — шкала (👍/👎), смысл несёт подпись карточки, поэтому
  пункт чек-листа это «☕ coffee», а отметка = «👍». Инструкцию «Tap 👍 or 👎 for
  each one.» после этого читать не по чему — кнопок на экране нет, есть
  галочки, — поэтому ровно эта фраза заменяется на «Tick the ones you like.».
  Остальные 👍/👎 курса — содержание, а не подпись к кнопкам («👍 = I like. 👎 =
  I don't like.», «👍 coffee → ___ coffee.»), и остаются как есть;
- у диалога подписи рядом с группой нет, поэтому пункты — сами реплики.

Контейнер при этом **режется по группам**: текст до группы — `info`, группа —
`check`, текст после — снова `info`. Порядок здесь часть методики: реплика
отвечает на предыдущее сообщение Сэма, а не на весь разговор целиком.
Отметка пункта сообщается вспомогательным технологиям через `aria-pressed`, а
галочка внутри квадрата помечена `aria-hidden` — иначе состояние доезжало бы
только цветом и символом.

### Сводка потерь

Блок, не ставший заданием, считается по причине (`choice-no-answer`,
`audio-no-track`, `info-empty`, `check-empty`, `row-no-block` — строка задания,
в которой не нашлось интерактива), и по итогам уровня CLI печатает сводку:
сколько блоков потеряно и почему, плюс сколько узлов не содержит ни одного
проверяемого задания. Молчаливая потеря контента — тот самый дефект, из-за
которого буквенный `data-correct` уровня A1 выбросил 1222 задания незамеченным.

Последний прогон: A1 — потерь нет; A0 — 10 блоков, все `choice-no-answer`.
Это одна задача стадии Practice «Listen. 13 or 30?»: в исходнике у неё
`<div class="opts" data-correct="0"></div>` — группа вариантов пуста, кнопок
`.opt` нет ни одной, и до отсечения чужих режимов тоже. Скрипты курса
`.opts` только читают (`querySelectorAll('.opts[data-correct]')` в `check()`),
заполнить её было нечем — задача не работала и в самом курсе. Восстанавливать
варианты значило бы придумать их за автора, поэтому строки отбраковываются, а
сводка о них сообщает. Слово для озвучки у них разобрано штатно — потеря не в
ней.

### Медиа

Аудио **не выносится**: треки уже опубликованы админкой и отдаются публично по
`https://files-dev.justtostudy.kz/development/course-catalog/<level>/audio/<файл>.mp3`.
Имена файлов совпадают с ключами `AUDIO_B64` в исходнике, так что ссылка
собирается без загрузки. Проверено: `a0/audio/a0_01cf00421b.mp3` → 200, 757 КБ.

Картинки словаря A0 (201 файл, ~8 МБ) в опубликованный бандл не попали. Они
выносятся экстрактором в `public/learning/media/a0/` — тот же локальный staging
под `.gitignore`, что и у остального медиа раздела, — и заливаются `mc mirror`
на `https://files-api.iqra.space/development/learning-media`, куда смотрят
ссылки в JSON. В git уходит только лёгкий JSON.

Имя файла картинки — читаемый слаг слова плюс шесть символов хэша самого слова
(`why-2b6f1c.jpg`). Хэш обязателен: в словаре A0 есть пары, различающиеся только
знаками препинания («Why?» и «Why…?»), у которых слаг один и тот же — без хэша
второе слово получало картинку первого.

Заливка требует доступа к бакету и делается отдельным шагом. Пока картинки не
залиты, карточка слова рендерится текстом: ссылка ведёт в 404, `onError`
прячет изображение — экстрактор и плеер не падают.

## Изменения в плеере

`src/learning/LessonPlayer.jsx` получает два компонента в существующем дизайне —
на тех же классах `kl-opt`, `kl-chip`, `kl-fb`, `kl-btn`:

- **`Order`** — сборка предложения кликами по чипам: клик добавляет слово в
  строку ответа, повторный клик убирает; проверка сравнивает порядок с
  `data-order`.
- **`Multi`** — множественный выбор: верно, когда набор отмеченных совпадает с
  эталонным.

Оба добавляются в `GRADED`, то есть дают монеты за верный ответ и снимают сердце
за неверный — как `choice`/`gap`/`chips`. `GRADED` при этом отвечает за
ПРОВЕРЯЕМОСТЬ (`checkable`), а начисление (`scored`) снимается отдельно —
задание на слух без синтеза проверяется и даёт фидбэк, но не даёт монет и не
снимает сердец.

- **`SayWord`** — кнопка озвучки для заданий с полем `say` (`.kl-say` в
  `styles.css`, те же токены, что у `.kl-opt`/`.kl-chip`). Строка кнопки — через
  `t('lesson.say.play')` для слова и `t('lesson.say.playText')` для абзаца для
  чтения, в ru/en/kk; повторное нажатие переозвучивает. Без поддержки синтеза
  кнопки нет: слово печатается текстом с пояснением
  `t('lesson.say.unavailable')` и перестаёт начисляться, а абзац для чтения и
  так напечатан на экране — там не показывается ничего.
- **`useSpeech`** — доступность синтеза (голоса + `voiceschanged` + `onerror`
  реплики) и сама озвучка одним местом. Он же отменяет речь при размонтировании
  плеера: без этого студент жмёт озвучку, выходит по стрелке, и голос
  продолжает говорить поверх карты.

Блок фидбэка дополняется строкой `why`, когда она есть у задания.

Стили — в `styles.css` рядом с существующими `kl-*`, без новых CSS-модулей.

## Карта и тропа

`src/kingdoms.js`: уровни съезжают по узлам на один, города, короли, цвета колец
и позиции остаются на местах.

| Город | Было | Стало |
|---|---|---|
| Redtown | A1 | **A0** |
| Bluewave Town | A2 | A1 |
| Green Peace Town | B1 | A2 |
| Music Town | B2 | B1 |
| Cocalastic Town | C1 | B2 |
| Rosewind Town | C2 (coming soon) | C1 |

Уровень C2 из раздела исчезает. `computeKingdoms` по умолчанию открывает A0
вместо A1. Сама тропа, «печеньки» по типу первого задания узла и кольцо
прогресса не меняются.

Контент привязан к уровню, а не к городу: `a2.json`, `b1.json`, `b2.json`,
`c1.json` остаются как есть и обслуживают свои уровни, просто на других узлах
карты. Перегенерируются только `a0.json` (новый) и `a1.json` (заменяется).

## Админка

- `MODULE_LEVELS` в `web-admin/src/app/feature/system/lesson-modules/lesson-module.model.ts`
  дополняется уровнем A0, иначе модуль A0 не завести через UI.
- На `/system/lessons` заводится модуль A0 и переназначается модуль A1:
  `indexUrl` указывает на уже опубликованный бандл
  `.../development/course-catalog/<level>/index.html`, `lessonCount` — по числу
  узлов тропы. Это ручной шаг в UI, не код.
- Прогресс и квоты студентов ходят через `moduleId`, поэтому появление модуля A0
  достаточно — ничего в логике прогресса не меняется.

Бэкенд не меняется: `LanguageLevel` уже содержит A0.

## Что осознанно не делается

- Режимы 1-to-1 и Group Study в раздел «Обучение» не переносятся — они остаются

  поддержки не требуют.
- Раздел не переводится на API каталога: данные остаются статикой.
