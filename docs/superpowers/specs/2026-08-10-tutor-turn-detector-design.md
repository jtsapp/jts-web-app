# Тьютор дослушивает длинные ответы: семантическая турн-детекция

Дата: 2026-08-10
Статус: дизайн согласован, реализация в `feat/tutor-turn-detector`

## Зачем

Сейчас голосовой тьютор режет ученика на паузе в **300 мс**. Живой стек —
cascade (`VOICE_STACK=cascade`), ход закрывает Silero VAD:

```python
silence = float(os.getenv("VAD_SILENCE_SEC", "0.3"))   # agent.py:3343
kwargs = {"turn_detection": "vad", "min_endpointing_delay": 0.3, ...}
```

Ученик уровня A2–B1 держит паузу «на подумать» дольше трёхсот миллисекунд
всегда. Длинный ответ разваливается на два-три хода, тьютор отвечает в
середину недосказанной мысли. Промпт при этом просит ровно обратного —
«Never interrupt — let them finish their whole turn first» (agent.py:2480), но
VAD срабатывает раньше, чем модель успевает что-либо решить.

Настройка «800 мс + HIGH end sensitivity», которая выглядит как решение,
живёт в `build_session()` (agent.py:3392) — это ветка **gemini-live**, она не
используется ни на одном деплое.

## Цель

1. Ход закрывается по смыслу фразы, а не по тишине: незаконченная мысль
   ждёт, законченное «yes» отвечается быстро.
2. Когда ученик оборвался на полуслове и молчит — тьютор подкидывает слово и
   возвращает ход, а не читает лекцию.
3. Ученик видит, что его слушают, всё время длинного ответа.

## Не цель

- **Исправлять ошибки посреди речи.** Демо OpenAI, с которого начался
  разговор, показывает inline-коррекцию по ходу фразы. Мы этого не делаем:
  ломает fluency-first методику (agent.py:2479-2487). Коррекция остаётся
  после хода, как сейчас.
- **Голосовой backchannel** («mhm» поверх речи ученика). Сигнал «слушаю» —
  только визуальный.
- Трогать ветку `gemini-live`.

## Решение

### 1. Семантический детектор конца хода

`build_cascade_session()` (agent.py:3295) переезжает со старых аргументов
`AgentSession` на API `turn_handling`, появившийся в livekit-agents 1.6:

```python
turn_handling = {
    "turn_detection": inference.TurnDetector(),
    "endpointing": {
        "min_delay": float(os.getenv("MIN_ENDPOINTING_SEC", "0.35")),
        "max_delay": float(os.getenv("MAX_ENDPOINTING_SEC", "4.0")),
    },
    "interruption": {"mode": "adaptive"},
}
```

Детектор слушает аудио (просодию вместе со смыслом), а не только текст
транскрипта. Фраза закончена — ход закрывается через `min_delay`. Оборвана
на полуслове — детектор держит ход до `max_delay`, ученик думает молча и ход
не теряет.

Берём именно `livekit.agents.inference.TurnDetector`, а не плагин
`livekit-plugins-turn-detector`: последний в 1.6.7 объявлен устаревшим
(«deprecated and will be removed in a future release. Use
`livekit.agents.inference.TurnDetector` instead») и ставить его в образ
незачем. Новый детектор входит в сам `livekit-agents`.

У детектора две модели, `version` резолвится сам:
`"v1" if (utils.is_hosted() or utils.is_dev_mode()) else "v1-mini"`.

- **v1** — облачный инференс LiveKit, ключи берёт из `LIVEKIT_API_KEY` /
  `LIVEKIT_API_SECRET`. Наш прод-воркер живёт на LiveKit Cloud, значит по
  умолчанию получит именно его. Даёт `backchannel_probability`.
- **v1-mini** — локальная модель через `livekit-local-inference` (уже
  зависимость `livekit-agents`). Работает без облака, backchannel не даёт.

Фолбэк cloud → local автоматический, **односторонний и залипающий**: после
деградации сессия до конца живёт на mini.

Детектору нужна VAD-тишина не меньше 200 мс до запроса инференса
(`MIN_SILENCE_DURATION_MS`); наш `VAD_SILENCE_SEC=0.3` это условие
выполняет — трогать его не надо.

Silero VAD остаётся: он даёт речевую активность. Решение о конце хода больше
не его, поэтому `VAD_SILENCE_SEC` перестаёт быть главной ручкой (переменная
живёт дальше — на ней держится фолбэк).

Старые `min_endpointing_delay` / `turn_detection="vad"` фреймворк мигрирует
автоматически (`_migrate_turn_handling`), но это устаревший путь, и без
явного `max_delay` детектор упрётся в те же 0.3 с — переезд обязателен,
половинчатая правка смысла не имеет.

### 2. Флаг и канарейка

Детектор по умолчанию **выключен**: `TURN_DETECTOR=off`. Выкатка образа не
меняет поведение ни у одного ученика, пока секрет не переключён на
`multilingual`. Откат — секрет обратно, без пересборки.

Сужение до одной персоны — `TURN_DETECTOR_TUTORS=bro` — тем же паттерном,
что уже живёт для `TTS_PROVIDER_<ПЕРСОНА>` и `STT_PROVIDER_<ПЕРСОНА>`
(agent.py:3061-3106). Сначала Декстер, потом остальные.

Создание детектора обёрнуто так же, как остальные опциональные куски
(agent.py:62-81): любая ошибка конструктора → `turn_detection="vad"`, старое
поведение, `logger.warning`. Воркер не падает.

Выбранный режим печатается в существующую строку `Session stack: CASCADE
(...)` — иначе по логам не отличить, включился детектор или нет.

### 3. «Застрял — подкинуть слово»

Отдельного механизма нет и не нужно. По истечении `max_delay` мозг получает
транскрипт, оборванный на полуслове («I need to… emmm»). В промпт рядом с
блоком TWO-TIER CORRECTION (agent.py:2480) добавляется правило: реплика
обрывается на полуслове или филлере → дать одно слово или короткую
фразу-подсказку и замолчать, ход остаётся за учеником; не отвечать по
существу.

### 4. Клиент: визуальный backchannel

`TutorVoiceChatPage` уже держит `useLocalParticipant` и `useTranscriptions`.
Добавляется `useTrackVolume` на микрофонный трек ученика: пока
`va.state === 'listening'`, орб пульсирует от громкости. Новых зависимостей
нет — хук есть в `@livekit/components-react` 2.9.9. Агента изменение не
касается, звук наверх не идёт.

### 5. Сборка

- `requirements.txt`: новых пакетов не нужно — детектор внутри
  `livekit-agents`, локальная модель внутри `livekit-local-inference`
  (транзитивная зависимость). Но **версии пинятся точно**: сейчас там
  `>=1.2.0` без пина, и любая пересборка уже сегодня притащит 1.6.7 с
  другими дефолтами. Это отдельная невыстрелившая мина, чиним здесь же.
- `Dockerfile`: прогрев локальной модели рядом с прогревом Silero
  (Dockerfile:27), чтобы фолбэк на `v1-mini` не упирался в скачивание весов
  посреди звонка.

## Параметры

| Переменная | Дефолт | Что делает |
|---|---|---|
| `TURN_DETECTOR` | `off` | `auto` включает детектор (версия резолвится сама), `v1` / `v1-mini` — принудительно |
| `TURN_DETECTOR_TUTORS` | пусто | сужает включённый детектор до перечисленных персон; пусто = все персоны. При `TURN_DETECTOR=off` не действует |
| `MIN_ENDPOINTING_SEC` | `0.35` | пауза до закрытия законченной фразы |
| `MAX_ENDPOINTING_SEC` | `4.0` | потолок ожидания незаконченной фразы |
| `VAD_SILENCE_SEC` | `0.3` | Silero; работает как раньше в фолбэке |

## Риски

1. **Скачок версии livekit-agents.** `requirements.txt` без пина; пересборка
   прыгнет с той версии, что в текущем прод-образе, на 1.6.7 — меняются
   дефолты эндпойнтинга и появляется adaptive-перебивание. Смягчение: пин
   версий и канареечный флаг из раздела 2.
2. **Языки: ни ru, ни kk.** У локальной `v1-mini` откалиброваны 14 языков —
   ar, de, en, es, fr, hi, id, it, ja, ko, nl, pt, tr, zh. Проверено на живом
   звонке, что **облачная `v1` присылает ровно тот же набор** (лог сессии,
   `audio turn detector initialized`, default_threshold 0.56) — то есть
   русского нет и там, а казахского нет нигде. Речь ученика на занятии
   английская (есть и режим english-only), поэтому основной кейс покрыт;
   реплики на ru/kk откатываются к VAD-подобному поведению.
3. **Стоимость облачного инференса.** `v1` — платный сервис LiveKit
   Inference, тариф на нашем плане не проверен. Перед включением на всех
   персонах посмотреть счёт после канарейки; альтернатива — принудительный
   `TURN_DETECTOR=v1-mini`, он работает локально и бесплатно.
4. **Залипающий фолбэк.** Обрыв связи с облаком переводит сессию на
   `v1-mini` до конца звонка — качество на ru просядет молча. Видно только
   по логам, поэтому активную модель печатаем в лог сессии.
5. **+50–160 мс на ход.**
6. **`interruption: adaptive` — новая логика.** Если начнёт глотать
   настоящие перебивания, откат в `{"mode": "vad"}` одной строкой.

## Проверка

Изоляция от прода — отдельный проект LiveKit Cloud, ключи только в
`.env.local` рабочего worktree. Прод-воркер сидит в другом проекте и эти
комнаты не видит.

Изоляции недостаточно объявить — её надо проверить ДО первого звонка, и
проверять именно на выходе `/api/livekit/token`, а не по содержимому
`.env.local`. Дежурная проверка (порт — тот, на котором поднят стенд):

```bash
curl -s -X POST http://localhost:3200/api/livekit/token -H "Content-Type: application/json" -d '{"deviceId":"check","tutor":"dexter"}'
```

В ответе поле `url` обязано указывать на dev-проект. Мы на этом уже
обожглись: dev-сервер был поднят из основного рабочего дерева, а не из
worktree, взял прод-`.env.local` и увёл тестовый звонок в прод — там его
подхватил боевой воркер. Файл `.env.local` при этом лежал правильный, и
проверка «глазами по файлу» ничего бы не показала. Заодно на стенде стоит
глушить `DATABASE_URL`: иначе локальные звонки пишут сессии и минуты в
боевую базу.

Канареечный воркер рядом с продовым в одном проекте невозможен: продовый
зарегистрирован без `agent_name` (agent.py:3946) и по automatic dispatch
берёт каждую новую комнату. Документация LiveKit гарантирует только
обратное («With `agent_name` set, the agent is only assigned to rooms when
explicitly dispatched»), поэтому изоляция делается проектом, а не диспатчем.

- **pytest** `agent/test_turn_handling.py`: сессия собирается с детектором;
  пороги читаются из env; `TURN_DETECTOR=off` и ошибка конструктора дают
  фолбэк на `"vad"` с предупреждением в лог; `TURN_DETECTOR_TUTORS` включает
  детектор только указанной персоне.
- **vitest**: орб реагирует на громкость только в состоянии listening.
- **Живой прогон** на локальном стенде: 3–4 длинных ответа с паузами на
  подумать + короткие «yes». Критерий: не рвёт на паузе, короткие ответы не
  стали медленнее. Цифры — из `LATENCY eou_delay=` (agent.py:3448).
  Локально живой TTS только у Декстера (`ELEVEN_VOICE_ID_BRO`), поэтому
  прогон на нём.

## Откат

- В проде: `TURN_DETECTOR=off` секретом воркера, без пересборки.
- Сузить ущерб: `TURN_DETECTOR_TUTORS=bro` — детектор только у одной персоны.
- Полный откат кода: ревёрт коммита и `lk agent deploy` предыдущего образа.
