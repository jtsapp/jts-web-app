# Голос у помощника по сайту — дизайн

Дата: 14.10.2026. Ветка: `feat/assistant-voice`.

## Зачем

Помощник по сайту (`AssistantWidget`, `/api/assistant/chat`) сейчас только чат: ученик пишет, помощник
отвечает текстом. Нужен голос: ученик говорит вопрос — помощник отвечает голосом сразу, без кнопки
«послушать».

Помощник — **технический помощник по сайту, а не учитель английского**. Ученики спрашивают его
по-русски и по-казахски («где домашка?», «почему не засчитало?», «не грузится видео»), поэтому
распознавание русского и казахского — главное требование, английский — второстепенное.

## Решения владельца (14.10.2026)

| Вопрос | Решение |
|---|---|
| Схема | Вариант А: запись в окне чата → распознавание → тот же чат → ответ текстом и голосом |
| Когда звучит ответ | Голос на голос: спросил голосом — ответ звучит сразу; набрал текстом — ответ только текстом |
| Чей голос | Голос Луны (Gemini TTS «Aoede», как у Луны в звонке) |
| Как записывать | Нажал — говорит — запись сама останавливается на тишине (или вторым нажатием) |
| Внешний вид | Помощник становится Луной: её аватарка и имя |
| Языки | Распознавание русского и казахского обязательно |

## Не делаем

- Живой разговор с перебиванием (LiveKit) — вариант Б, отклонён.
- Озвучку ответов на вопросы, набранные текстом.
- Хранение записей голоса — нигде, ни на диске, ни в БД.
- Починку слепых зон снимка экрана (SpeakSpin в Shadow DOM, окна-порталы) — отдельная задача.
- Вход и лимит для `/api/transcribe` и `/api/tutor-tts` — отдельная задача (сейчас открыты без входа).

## Как это работает

```
[🎤 нажал] → запись WAV 16 кГц (useRecorder) ──тишина 1.5 с / второе нажатие──┐
                                                                             ▼
                              POST /api/assistant/transcribe  (Bearer, лимит)
                              Soniox: языки [интерфейс, ru|kk, en] + контекст сайта
                              пусто/ошибка → Azure с локалью интерфейса
                                                                             ▼
                              текст → сообщение ученика (с пометкой «голосом»)
                                                                             ▼
                              POST /api/assistant/chat  { …, voice: true }
                              (как сейчас + строка «ответ озвучат» в контексте)
                                                                             ▼
          поток текста → окно чата (как сейчас)
                      → нарезка на фразы (speechChunks) → очередь озвучки
                                                                             ▼
                              POST /api/assistant/speak  (Bearer, лимит)
                              Gemini «Aoede»; казахский или сбой → Soniox «Grace»
                                                                             ▼
                              blob → playUrl() общего <audio> из speech.js
```

## Части

### 1. Запись — `src/lib/assistant/useVoiceQuestion.js` (новый)

Хук окна чата. Состояния: `idle | recording | transcribing`; ошибки:
`unsupported | denied | not_heard | stt_failed`.

- Запись — `useRecorder` из `src/ielts/speaking/useRecorder.js` (WAV 16 кГц mono, микрофон держится
  до закрытия окна, повторного запроса разрешения нет).
- Конец записи:
  - второе нажатие на микрофон;
  - 1.5 с тишины ПОСЛЕ того, как голос был (порог — `createVoiceActivity` из
    `src/practice/arcade/voiceActivity.js`, считается от голоса самого ученика, без жёсткого пола);
  - голоса нет 8 с с начала → запись отменяется, ошибка `not_heard` («Не расслышала, попробуйте ещё раз»);
  - потолок 30 с (WAV ≤ ~1 МБ: на прод-домене nginx мог остаться с лимитом тела 1 МБ ≈ 32 с речи).
- После записи — `POST /api/assistant/transcribe`, по тексту — `onText(text)` в виджет.
- Нажатие на микрофон заодно зовёт `unlockSpeech()` из `speech.js`: это жест, после которого iPhone
  разрешит играть ответ без нового нажатия.

### 2. Распознавание — `POST /api/assistant/transcribe` (новый роут)

- Только для вошедшего ученика: `verifyTokenStatus`, как у чата. Гостю, преподавателю — 401.
- Тело — multipart `audio` (WAV) + поля `lang` (язык интерфейса: ru|kk|en) и `screen` (id экрана).
- Лимит размера 1.2 МБ (30 с WAV + запас), свой лимитер `createRateLimiter` (20 за 10 мин, 150 в
  сутки, ключ `user-<id>`) — распознавание платное независимо от чата.
- Основной движок — **Soniox** (`transcribeWavSoniox`), потому что:
  - он держит смешанную речь в одной фразе («почему тут «don't like» не засчитали?»), а Azure
    распознаёт одну локаль за раз;
  - замер 25.09.2026 (PR #499): с казахским контекстом казахские формы распознаются на 93 % против 78 %.
- Что меняется в `src/lib/soniox-stt.js`: `lang` принимает массив языков (`language_hints`) и
  появляется необязательный `context` (`{ general: [{key, value}], terms: [...] }`). Старые вызовы
  (`lang: 'en'`) работают как раньше.
- Языки — по языку интерфейса, первым идёт он сам: `kk` → `['kk','ru','en']`, `ru` → `['ru','kk','en']`,
  `en` → `['en','ru','kk']`.
- Контекст — `src/lib/assistant/sttContext.js` (новый, чистый): `general` — «технический помощник
  сайта онлайн-школы английского JTS, ученик спрашивает про сайт, задания и поломки»; `terms` —
  названия разделов и кнопок сайта на ru и kk (из `SCREEN_NAMES` и i18n: «Практика», «Домашняя
  работа», «Speaking Buddy», «Воркбук», «Шэдоуинг», «Үй жұмысы»…) плюс имя текущего экрана. Лимит
  Soniox на контекст — 8000 токенов, держим ≤ 3000 символов.
- Запасной путь: Soniox вернул пусто (на 429 он молча отдаёт `''`) или упал → Azure с локалью
  интерфейса (`ru-RU` / `kk-KZ` / `en-US`): `transcribeWavFast(wav, { locale })`, на `null` —
  `transcribeWav(wav, { locale })`. Для этого `transcribeWav` получает параметр `locale`
  (сейчас `en-US` зашит), старые вызовы — без изменений.
- Ответ: `{ text }`. Пустой текст после обоих движков → `{ text: '' }`, клиент показывает
  `not_heard`. Звук нигде не сохраняется и в лог не пишется (в лог — только длительность и движок).

### 3. Ответ — `/api/assistant/chat` (правка)

- В теле запроса новый флаг `voice: true|false` (`parseChatRequest`).
- При `voice: true` в блок `<контекст>` последнего сообщения добавляется строка: «Ученик спросил
  голосом, ответ будет озвучен: 2–4 коротких предложения, без списков, без выделения и без ссылок;
  английские слова и примеры — в кавычках». Системный промпт не меняется → кэш не ломается.
- Правила помощника получают имя: «Тебя зовут Луна» (одна строка в `RULES`; системный промпт
  пересоберётся в кэше один раз).
- Остальное как сейчас: лимиты, OFFTOPIC (отказ тоже озвучивается), REPORT_BUG.

### 4. Озвучка — `POST /api/assistant/speak` (новый роут) + `src/lib/tutorVoice.js` (вынос)

- Синтез Gemini Cloud TTS и Soniox выносится из `src/app/api/tutor-tts/route.js` в общий модуль
  `src/lib/tutorVoice.js` (`synthTutor(provider, text, tutor, lang)`), роут тьютора импортирует его
  же — поведение `/api/tutor-tts` не меняется. Голос помощника и Луны в звонке — один код.
- `/api/assistant/speak`: только для вошедшего; тело `{ text, lang }`, `text` ≤ 600 символов; лимит
  100 фраз за 10 мин и 800 в сутки на ученика (ответ — 2–4 фразы, чат даёт 20 вопросов за 10 мин).
- Голос:
  - казахская фраза (есть буквы `әғқңөұүһі`) → Soniox «Grace» (`lang: kk`): у Gemini казахского нет;
  - иначе Gemini «Aoede» (`gemini-2.5-flash-tts`), русский и английский одним голосом;
  - Gemini упал, нет ключа, исчерпана квота → Soniox «Grace» той же фразой.
  Квота Gemini общая со звонками Луны — поэтому у озвучки свой лимит и запасной голос на любой сбой.
- Ответ — аудио (`audio/wav` от Gemini, `audio/mpeg` от Soniox), `cache-control: no-store`.
- Язык одной фразы решает сервер, а клиент держит один голос на весь ответ: если первая фраза ушла
  в казахский — весь ответ идёт с `lang: kk`.

### 5. Нарезка и очередь — `src/lib/assistant/speechChunks.js` и `voiceQueue.js` (новые)

- `speechChunks` (чистый): принимает куски потока, отдаёт готовые фразы.
  - Чистит разметку: `**…**` → текст, «- » в начале строки → ничего, `[[…]]` никогда не
    озвучивается (метки и так вырезаны сервером, это страховка).
  - Первая фраза — как только закончилось предложение (`.`, `!`, `?`, `…`, перевод строки) и в ней
    ≥ 30 символов: чем раньше уйдёт первая, тем раньше звук.
  - Следующие — склейка предложений до ≥ 120 символов: меньше вызовов синтеза.
  - Жёсткий потолок 400 символов: режем по запятой или пробелу.
  - `flush()` в конце потока отдаёт остаток.
- `voiceQueue`: фраза → `fetch('/api/assistant/speak')` → blob → `playUrl()` из `speech.js`. Следующая
  фраза запрашивается, пока играет текущая (одна вперёд). `stop()` обрывает и очередь, и звук, и
  запросы (AbortController), отзывает blob-адреса.
- Если фраза не синтезировалась — пропускаем её и идём дальше; если не зазвучала ни одна — виджет
  показывает тихую пометку «Не удалось озвучить» под ответом. Текст ответа есть всегда.

### 6. Окно чата — `AssistantWidget.jsx` (правка) + `assistant.css`

- Кнопка микрофона рядом с «Отправить». Во время записи: пульс, таймер, нажатие — стоп. Во время
  распознавания: «Распознаю…», кнопка неактивна.
- Сообщение ученика, сказанное голосом, помечено значком микрофона.
- Ответ на голосовой вопрос отправляется с `voice: true` и озвучивается по мере прихода текста.
- В шапке — кнопка «звук вкл/выкл» (видна, пока есть хоть один голосовой вопрос); выбор хранится в
  `localStorage` (`jts_assistant_voice_muted`, в try/catch). Выключено — ответ на голос приходит
  только текстом.
- Озвучка останавливается: новая запись, ученик начал печатать, «Новый чат», закрытие окна, смена
  ученика, экран, где помощник скрыт (`enabled = false`).
- Микрофона нет (`MediaRecorder` не поддерживается) — кнопки нет. Запрещён — подсказка «Разрешите
  микрофон в настройках браузера», чат текстом работает.
- Луна: аватарка в шапке и на кнопке-запуске — `/tutor/tutor-luna.png`; заголовок — «Луна», подпись —
  «Помощник JTS: сайт, задания, ошибки»; приветствие от её имени («Здравствуйте! Я Луна…», на «вы»,
  как сейчас). Строки — в `src/i18n.jsx` на ru/kk/en (зона помощника
  пользуется `useI18n`). Строка о приватности дополняется: «Голос распознаётся и не сохраняется».

## Ошибки

| Что случилось | Что видит ученик |
|---|---|
| Нет `MediaRecorder` | Кнопки микрофона нет, чат текстом |
| Микрофон запрещён | «Разрешите микрофон…», чат текстом |
| Голоса не было 8 с / распознано пусто | «Не расслышала, попробуйте ещё раз» |
| Распознавание упало (5xx, сеть) | «Не получилось распознать, попробуйте ещё раз или напишите» |
| Лимит распознавания | То же сообщение о лимите, что у чата |
| Чат ответил ошибкой | Как сейчас (кнопка «Повторить»), озвучки нет |
| Озвучка не началась | Текст ответа на месте, под ним «Не удалось озвучить» |
| Автоплей заблокирован (iOS без жеста) | Как выше; жест микрофона это предотвращает |

## Деньги и лимиты

- На каждый голосовой вопрос: одно распознавание (Soniox, реже Azure) + 2–4 синтеза Gemini.
- Soniox real-time STT лимитирован в минуту на организацию, общую с живыми звонками тьюторов.
  Вопросы помощнику короткие и редкие; при 429 распознавание уходит в Azure, а не ждёт.
- Квота Gemini TTS общая со звонками Луны: свой лимит у `/speak` + откат на Soniox.

## Проверка

- vitest:
  - `speechChunks` — первая фраза рано, склейка, потолок, разметка, метки, `flush`;
  - `sttContext` — языки по интерфейсу, терм-лист в пределах лимита;
  - `soniox-stt` — массив языков и контекст уходят в конфиг сокета, старые вызовы не изменились;
  - `parseChatRequest`/`buildContextBlock` — флаг `voice` и строка про озвучку;
  - `/api/assistant/transcribe` — 401 без входа, 413 на большой файл, лимит, откат Soniox → Azure;
  - `/api/assistant/speak` — 401, лимит, казахский → Soniox, сбой Gemini → Soniox;
  - `/api/tutor-tts` после выноса — те же ответы, что до;
  - `voiceQueue` — порядок, одна вперёд, `stop`, пропуск упавшей фразы;
  - `AssistantWidget` — кнопка микрофона по состояниям, `voice: true` только у голосового вопроса,
    «звук выкл», остановка озвучки при печати и закрытии.
- Playwright (`tests/assistant-voice.spec.js`): Chrome с фальшивым микрофоном
  (`--use-fake-device-for-media-stream`), роуты распознавания/чата/озвучки подменены через
  `page.route` — запись → вопрос в чате → ответ → запрос озвучки.
- Живой прогон на дев-стенде своим голосом: вопросы на русском, казахском и со вставкой английского
  слова; ответ звучит голосом Луны; казахский ответ — голосом Grace.

## Риски

- Распознавание казахского на живой речи не замерено — замер 25.09 был на синтезе с шумом. Первый
  живой прогон — главная проверка; если плохо, следующий шаг — расширить `terms` фразами, на которых
  ошибается.
- Gemini TTS не потоковый: фраза приходит целиком (~1–2 с). Первая фраза короткая ради этого.
  Ожидаемая задержка от конца речи до звука — 3–4 с.
