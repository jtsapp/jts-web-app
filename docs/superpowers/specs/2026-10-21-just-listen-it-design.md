# Just Listen It — раздел «Практики»: диктант слова и предложения

Дата: 21.10.2026. ТЗ: Notion «ТЗ: раздел Just Listen It». Источник правды контента —
прототип `data/jtslisten.html` (2,7 МБ, standalone, скачан из вложения ТЗ).

## Что это

Ученик слышит английское слово и пишет его по буквам в ячейки, затем слышит
предложение с этим словом и записывает его целиком. После ответа видит образец и
русский перевод. Материал — словарь курса A0–B2 (2 873 записи) и профессиональная
лексика 16 направлений B1–C1 (8 262 термина).

Три части, три PR, мержатся по порядку:

1. **backend** — модуль `listen`: загрузка HTML прототипа, разбор, хранение в MinIO,
   отдача ученику.
2. **web-admin** — страница «Just Listen It» в «Практика и тесты»: загрузить HTML,
   увидеть текущий релиз.
3. **jts-web-app** — экран `?screen=listen`, движок, звук, прогресс, монеты.

## Решения владельца (21.10.2026)

- Данные — в MinIO, заливаются через админку (как каталог «Словаря»), а не
  вшиваются в бандл: 2,7 МБ в клиент не нужны, правка перевода не требует PR.
- Professional-направления **пока открыты всем**. Признака Premium на платформе нет
  («PREMIUM 16» — только имя тарифа уроков). Закрывать будем потом, в одной точке —
  ручке набора на бэкенде (см. «Premium позже»).
- Озвучка — `/api/tts` по запросу (Soniox + кэш Redis), без заранее сгенерированных
  файлов. Сбой синтеза — голос устройства, как в прототипе.
- «Ошибки — в Повторение»: отдельного раздела ошибок нет (пункт меню «Повторение» —
  карта курса), поэтому ошибки уходят в «хуже запомненные» «Словаря»
  (`recordVocabMisses`).
- **Монеты в баланс — только прирост к лучшему результату урока.** Прототип
  начислял за каждое прохождение, и любой урок фармился без конца. «Повторить
  ошибки» и «Свой список» монет не дают.
- «Свой список слов» видят только преподаватели.

## Данные

### Формат прототипа

В `<script>` прототипа объявлены литералы (ключи без кавычек — это JS, не JSON):

- `SYL = {A0: units[], A1: …, B2: …}` — уровни;
- `FIELDS = [{id, name, cat, units[]}]` — направления, `name` — русское имя;
- `FIELD_META = {<id>: [icon, englishName, group]}` — иконка, английское имя, группа
  как в каталоге платформы;
- `DEMO` — запасной набор для уровня без `SYL`. Все пять уровней в `SYL` есть,
  поэтому `DEMO` не переносим.

`unit = {u, title, lessons[]}`, `lesson = {l, t, g, w[]}`,
запись `w[i] = [en, ru, sentenceEn, sentenceRu, note]`.

Прототип поддерживает варианты: `en` через `|`, `sentenceEn` через `||`, `ru` через
`/`. Сейчас в данных `|` и `||` не встречаются, но формат их допускает, и порт обязан
их понимать.

Урок с пустым `w` — урок-повторение: набирает 20 слов из уроков после прошлого
повторения. Сейчас пустых уроков нет, логика переносится.

### Что хранит бэкенд (MinIO, `listen/current/`)

`index.json` — оглавление без слов:

```json
{
  "release": 12,
  "uploadedAt": "2026-10-21T12:00:00Z",
  "levels": [{ "id": "A0", "name": "Beginner", "units": 8, "lessons": 24, "words": 369 }],
  "fields": [{ "id": "business", "name": "Business", "ru": "Бизнес", "icon": "💼",
               "group": "Business", "premium": true, "units": 3, "lessons": 31, "words": 547 }]
}
```

`sets/<id>.json` — один уровень или направление целиком, записи массивами, как в
прототипе (компактно и совпадает с оракулом):

```json
{ "id": "A1", "kind": "level", "units": [
  { "u": 1, "title": "…", "lessons": [
    { "l": 1, "t": "My biography", "g": "", "w": [["born", "родился / родилась",
      "I was born in a small town near Almaty.", "Я родился в маленьком городе недалеко от Алматы.", ""]] }
  ] }
] }
```

Id набора: `A0…B2` и id направлений прототипа (`business`, `it`, `swe`, `data`,
`cyber`, `medicine`, `nursing`, `pharmacy`, `psychology`, `dentistry`, `mecheng`,
`civeng`, `eleceng`, `biology`, `chemistry`, `physics`); шаблон
`^[A-Za-z0-9_-]{1,32}$`. Размер: уровень 70–140 КБ, направление ~90 КБ.

## Часть 1. Backend

Образец — модуль `vocabcatalog` (V198, `VocabCatalogStorageService`,
`VocabCatalogUploadService`, `MobileVocabCatalogController`).

- **Миграция** `V387__Create_listen_releases.sql` (номер сверить с develop перед
  мержем — его занимают и чужие PR): `listen_releases(id, file_name, levels_count,
  fields_count, lessons_count, words_count, uploaded_by → users ON DELETE SET NULL,
  created_at)` + индекс по `created_at DESC`. Только мета; данные — в MinIO.
- **Разбор** `ListenHtmlParser`: литералы `SYL`, `FIELDS`, `FIELD_META` вырезаются тем
  же кодом, что у словаря (`VocabJsLiterals.extract` + `jsToJson`: строки, комментарии,
  ключи без кавычек). Класс сейчас package-private в `vocabcatalog` — выносим его в
  общий пакет (`shared/util/JsLiterals`), словарь зовёт его оттуда; поведение
  словаря не меняется.
- **Проверка** (отказ всей загрузки с понятным текстом, ничего не пишем):
  - нет `SYL` или `FIELDS`;
  - уровень вне `A0…B2`, id направления не по шаблону, дубли id;
  - у юнита нет целого `u` или массива `lessons`; у урока нет целого `l`, строки `t`
    или массива `w`;
  - запись не массив из 4–5 строк; в `en` нет ни одной латинской буквы (ячейки не
    набрать).

  Предупреждения (загрузка проходит, список — в ответе `warnings`): у записи есть
  только одно из `sentenceEn`/`sentenceRu` — прототип такую считает записью без
  предложения (шаг 2 «Составь своё предложение»). `note` может отсутствовать —
  дополняем `""`. Направление без записи в
  `FIELD_META` — иконка `📘`, имя и группа из `FIELDS`.
- **Хранилище** `ListenStorageService`: префикс `listen/current/`, режим
  `listen.storage=local` + `listen.dir` для разработки без MinIO (как у словаря).
  Порядок записи: все `sets/*.json`, затем `index.json` — оглавление не ссылается на
  недописанный набор. Наборы, которых нет в новой загрузке, удаляются после записи
  оглавления.
- **Чтение** `ListenCatalogService.readIndex()/readSet(id)`: JSON из хранилища,
  кэш в памяти по номеру релиза, сброс при загрузке. Бакет без CORS, поэтому тело
  отдаёт бэкенд, а не ссылка (как караоке и словарь).
- **Ручки**:
  - `POST /admin/listen/upload` (multipart `file`, только ADMIN) →
    `{release, levels, fields, lessons, words, sets: [{id, words}], warnings: []}`;
  - `GET /admin/listen` → текущий релиз + последние 20 загрузок;
  - `GET /mobile/listen` → `index.json`; до первой загрузки — `404` с кодом
    `LISTEN_NOT_UPLOADED`;
  - `GET /mobile/listen/sets/{id}` → набор; неизвестный id — `404`.
  - Безопасность как у `/mobile/vocab-catalog`: нужен Bearer (гостю раздел
    недоступен).
- **Premium позже**: `readSet` — единственная точка, где появится проверка доступа
  для `kind: "field"`; в оглавлении уже есть `premium: true`, клиенту менять
  разметку не придётся.
- **Тесты** (на Mockito, без WebMvc-срезов — они красные из-за
  `IeltsAccessInterceptor`): парсер на урезанной копии прототипа (уровни, поля,
  мета, варианты `|`/`||`, каждая ошибка проверки), загрузка (порядок записи,
  удаление старых наборов, запись релиза), чтение (кэш, 404).

## Часть 3. Веб (jts-web-app)

### Движок `src/practice/listen/` — чистые модули под vitest

- `compare.js` — порт `letters`, `enMain`, `first`, `lev`, `CONTR`, `SYN`, `IRR`,
  `toks`, `forms`, `containsTarget`, `compareSentence`, `missingWords` — дословно по
  семантике прототипа.
- `runs.js` — прогоны набора: части урока (`PART = 12`, деление поровну, как
  `parts()`), урок-повторение (пул уроков после прошлого повторения, 20 слов),
  «Повторить юнит» (15), тест уровня/направления (20). Ключи как в прототипе:
  `A1-L3-0`, `A1-L4-R`, `A1-U2`, `A1-T`, `business-T`. Случайность (`shuffle`,
  `sample`) — аргументом, чтобы тест был детерминированным.
- `scoring.js` — монеты слова (10 / 5 / 2 / 0) и предложения (15 / 8 / 0), допуск
  предложения (до 6 слов — 0 ошибок, длиннее — 1), «почти» для слова
  (`lev ≤ max(1, ⌊len/5⌋)`), `coinsToCredit(earned, best)`.
- `session.js` — `ListenSession`, машина теста вне React (как
  `ListenChooseSession`): колода, шаг `word → sent → done`, попытки, подсказки
  (буква / первая треть предложения), лимиты 3 подсказки + 3 показа на весь тест
  (показ после двух ошибок лимит не тратит), результаты. Звук и DOM не трогает:
  отдаёт снимок и события (`playWord`, `playSentence`), экран подписан через
  `useSyncExternalStore`.

**Оракул.** Скрипт `scripts/extract-listen-oracle.js` выкусывает функции из
`data/jtslisten.html` (тем же `sliceFunction` из `scripts/lib/js-slice.js`, что у
«Чтения»: строки, комментарии, регэкспы) и считает ими `__fixtures__/oracle.json`: `toks` каждого предложения,
`containsTarget` (предложение, слово), `compareSentence` на наборе искажений
(точный ответ, без слова, лишнее слово, перестановка, сокращения, регистр и
пунктуация, британское/американское написание), «почти» для слова, `parts` каждого
урока. Все записи A0–B2 и каждая 10-я запись направлений — чтобы фикстура не
разрослась. Красный `engine.test.js` значит, что порт разъехался с прототипом, и
чинить надо порт.

### Данные на клиенте

`api.js`: `getListenIndex(token)`, `getListenSet(token, id)` → `/mobile/listen…`.
Кэш — в памяти вкладки, **не в localStorage** (кэши каталогов уже забивали квоту и
молча ломали прогресс Практики). Запросы отменяются при уходе с экрана. `404

### Экран `?screen=listen`

`src/screens/ListenPage.jsx` + `src/screens/listen/`: `ListenMenu`, `ListenSetScreen`,
`ListenTask` (`WordCells`, `SentenceStep`), `ListenResult`, `OwnListCard`. Адрес
`?screen=listen[&set=A1]` — `set` открывает уровень или направление сразу.

1. **Меню.** Шапка раздела («1. Слово → 2. Предложение → Монеты», «3 подсказки и 3
   показа ответа, включи звук»), карточки A0–B2 с полосой «пройдено уроков» (урок
   пройден, если у любой его части есть лучший результат — как в прототипе), блок
   «Профессиональная лексика» с группами Business / Technology / Health / Science &
   Engineering. Плитки направлений открыты, замок не рисуем. «Свой список слов» —
   только при `isTeacher(token)`.
2. **Набор.** «Тест уровня» / «Тест по направлению» (20); юниты с «Повторить юнит»
   (15) и уроками; урок длиннее 12 слов — кнопки «Часть 1», «Часть 2»…; у кнопок
   лучший результат (монеты, верно из n).
3. **Задание, шаг 1.** Кнопка воспроизведения, «Медленнее», ячейки по числу букв
   (пробел делит группы ячеек), скрытый `input` под ячейками (мобильная клавиатура,
   `autocapitalize/autocorrect/spellcheck` выключены). Все ячейки заполнены — проверка
   сразу; Enter — проверка раньше. Ячейки: жирные фиолетовые буквы, зелёные / жёлтые
   / красные по итогу, мельче при длине > 9 и > 16 букв.
4. **Задание, шаг 2.** Открывается после слова (верного или показанного), предложение
   звучит через 1,5 с. Поле, «Проверить» и Enter, подсказка «не хватает: …», после
   ответа — образец, перевод, «Дальше».
5. **Итог.** Монеты (и сколько зачислено в баланс, если меньше заработанного:
   «+0 — это повторение» / «+5 сверх лучшего»), верно слов / предложений, точность,
   разбор каждого слова с ответом ученика; «Повторить ошибки», «Пройти заново», «К
   темам».

Шапка теста: выход, прогресс, остаток подсказок и показов, монеты теста.

**Стиль** — `src/listen.css` (подключить в `layout.jsx`), классы `.jl-*`: шрифт как у

отказался), акцент `#9047FF`, белые карточки с радиусом 24px,
кнопки-пилюли, монеты вместо XP, тёмная тема на переменных платформы, адаптив до
360px внутри того же файла (кадров «Web Адаптивка» для раздела нет).

**Регистрация раздела**: секция в вкладке «Аудирование» (`practiceTabs.js`, рендер в
`PracticePage.jsx`), ветка и `PERSISTABLE_SCREENS` в `App.jsx`, `sectionBack('listening')`,

### Звук

- `playTts(text, {voice: VOICE.gb, lang: 'en', speed: 0.9, rate})`. «Медленнее» — тот же
  адрес с `rate: 0.75` (темп на устройстве, новый синтез не нужен).
- Автоплей: слово через 0,35 с после открытия задания, предложение через 1,5 с после
  слова. Разрешение iOS — `unlockSpeech()` в тике нажатия «Начать».
- Предзагрузка (`prefetchTts`): при открытии задания — его предложение и слово
  следующего задания.
- `onFail` (сбой, 429 сверх `TTS_SONIOX_PER_MIN`) — `speechSynthesis` en-GB на темпах
  прототипа (0,9; «Медленнее» — 0,55 слово, 0,6 предложение).
- Уход с экрана — `stopTts()`.

### Монеты, прогресс, ошибки

- **Прогресс** — модуль синхронизации `listen`, состояние `{best: {<key>: {ok, n,
  coins}}}`. Слияние на сервере «лучший по ключу» (больше монет, при равенстве —
  больше `ok`), как у `reading`: `src/lib/listenState.js` + ветка в
  `mergeModuleState`. Регистрация в четырёх местах (`practiceKeys.js`,
  `PRACTICE_MODULES`, `OBJECT_MODULES` + `applyHydratedState`, `clearLocalPractice`) и
  в тестах `practice-contract` / `practice-sync-core`. Клиентский стор —
  `createProgressStore`.
- **Монеты** — на экране итога, один раз за тест: `credit = max(0, earned −
  best.coins)` для прогона с ключом; `completeLessonModule(token, credit)` при
  `credit > 0` (монеты + XP + серия). Прогон без ключа («Повторить ошибки», «Свой
  список») — 0. Брошенный тест ничего не начисляет и лучший результат не трогает.
  После зачисления — обновить баланс в сайдбаре тем же путём, что после урока
  грамматики.
- **Ошибки** — слова, где неверно слово или предложение, уходят в
  `recordVocabMisses(token, [{word, ru, kk: ''}])` при показе итога.
- **Навык** — `recordSkill('listening', wordOk && sentOk)` на каждое задание.
- В домашнюю работу и квоту Практики раздел не отчитывается (area `listen` бэкенду
  неизвестна).

### Свой список (преподаватель)

Строка — слово: `english - русский - English sentence - Русское предложение`
(разделитель ` - ` / `–` / `—` или Tab). Список хранится в localStorage устройства
(`jts_listen_own`), на сервер не уходит. Без предложения — шаг 2 «Составь своё
предложение»: минимум 4 английских слова и целевое слово, как в прототипе.

  монеты), `listenState` (слияние), регистрация модуля.
- Playwright `tests/listen.spec.js`: `page.route` подменяет `/mobile/listen*` урезанным
  набором и `/api/tts` тихим mp3; путь меню → урок → слово (верно) → предложение
  (верно) → итог; второе прохождение начисляет только прирост; узкий экран 360px.
- `npm run build`, `npm run lint`, `npm test`; ручной прогон на dev после загрузки
  HTML через админку.

## Риски

- Лимит Soniox общий с голосом тьютора (организация, TTS 3 одновременных): при
  холодном кэше и большой группе часть звуков прочитает голос устройства.
- Русские переводы предложений и слова B2 сделаны автоматически — до прода
  выборочная проверка методистом.
- Монеты начисляются по слову клиента (как у грамматики): защита от фарма —
  правило прироста, а не сервер.
