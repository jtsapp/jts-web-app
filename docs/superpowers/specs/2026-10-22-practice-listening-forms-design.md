# Аудирование в админке — добавить, изменить, удалить задание (этап 2)

Дата: 22.10.2026. Статус: дизайн согласован с владельцем. Продолжение
`2026-10-21-practice-content-to-admin-design.md` (этап 1 — перенос пакетом, сделан и проверен на деве).

## Зачем

Этап 1 перенёс 800 заданий Аудирования в бэкенд, но менять их можно только пакетом (zip) — это технический
инструмент для переноса, а не для работы с материалом. Этап 2 — правка по одному заданию прямо в окне раздела
«Библиотека → Аудирование».

## Решения владельца (22.10.2026)

1. **Правят только админы.** Никакой модерации и черновиков: «добавление значит добавление» — сохранил, и задание
   у учеников. (Сначала обсуждали «преподаватель предлагает — публикующий одобряет», владелец передумал.)
2. **Запись — загрузкой готового mp3.** Озвучки синтезом и записи микрофоном в формах нет.
3. Удаление — с отметкой «удалено», а не стиранием строки (см. ниже); порядок заданий в уровне не меняется руками.

## Поведение

### Окно раздела

- Над списком — кнопка **«Добавить задание»**; у строки — **«Изменить»**, **«Удалить»** и прежнее «Показано/Скрыто».
  «Перенос между стендами» (пакет) остаётся второстепенной кнопкой.
- Форма — отдельный экран (как у шэдоуинга и караоке): `/system/library/listening/create` и
  `/system/library/listening/{id}/edit`.

### Форма

| Поле | Создание | Правка |
|---|---|---|
| Уровень (A1…C1) | выбирается | показан, не меняется |
| Тип | «Выбор ответа» / «Собери фразу» / «Впиши услышанное» | меняется |
| Запись | «Загрузить mp3» + ▶ | ▶ текущая, «Заменить» |
| Разбор | текст, подсказка «можно `<b>` и `<i>`» | то же |

Поля типа:
- **Выбор ответа:** вопрос; варианты — строки с «+ добавить» / «×» (2–6); правильный ответ — отметкой у варианта, а
  не отдельным полем (опечатка в ответе невозможна).
- **Собери фразу:** текст записи (что звучит); плитки — строки в верном порядке (1–40); лишние плитки (0–20).
- **Впиши услышанное:** эталон.

«Сохранить» шлёт задание на бэкенд; нарушения правил приходят списком (до 10) и показываются над кнопкой. После
сохранения — назад к списку уровня. Ученики видят изменение с учётом кэша публичной ручки (до 5 минут).

### Правила

- **id нового задания выдаёт сервер:** `<уровень>_<NNN>`, NNN = наибольший номер на уровне (включая удалённые) + 1,
  не меньше трёх знаков (`a1_125`). Задание встаёт в конец уровня (`order_index` = наибольший на уровне + 1).
  Новое задание сразу показано (`is_active = true`).
- **Уровень существующего задания не меняется:** префикс id = уровень, по нему считается «пройдено на уровне».
  Перенести задание на другой уровень = удалить и завести заново.
- **Удалить** — с подтверждением. Строка остаётся с `deleted_at`: так номер не достанется новому заданию (на id висит
  прогресс учеников). Удалённое не отдаётся ученикам, не считается в счётчиках и не показывается в админке.
- **Пакет и удалённое:**
  - выгрузка отдаёт удалённое как скрытое (`active: false`) — удаление на деве переносится на прод тем же пакетом
    (там задание станет скрытым);
  - заливка пакета удалённое не воскрешает (как и скрытое) и в сверке показывает его отдельной группой «удалены на
    этом стенде»;
- Валидация — те же `ListeningRules`, что у пакета (разметка только в разборе, ответ среди вариантов и т. д.).

## Бэкенд

- Миграция: `ALTER TABLE practice_listening_tasks ADD COLUMN deleted_at TIMESTAMP` (номер — свободный на момент мержа).
- Ручки (ADMIN, `/admin/practice/listening`):
  - `GET /tasks/{key}` — одно задание (для экрана правки);
  - `POST /tasks` — создать; тело как задание пакета без `id` (`level`, `type`, `audio: media/<sha24>.mp3`,
    `explanation`, поля типа); ответ — `AdminTask` с выданным id;
  - `PUT /tasks/{key}` — изменить; тело то же, `level` обязан совпасть с текущим (иначе 400);
  - `DELETE /tasks/{key}` — отметить удалённым (204); повторно — 404.
- Запись грузится прежней `POST /admin/practice/media/listening` (multipart `file` + `expected`), форма подставляет
  `media/<имя>` из ответа.
- `DiffResult` получает поле `deletedHere: string[]`; `added`/`changed`/`unchanged` удалённых не включают.
- Публичные ручки, `adminList`, счётчики — `deleted_at IS NULL`. Гонка двух админов при выдаче id упирается в
  `UNIQUE(task_key)`: при конфликте сервер пересчитывает номер и повторяет один раз.

## Админка

- `practice-listening/listening-form/` — экран формы (reactive forms), `practice-listening.routes.ts` — маршруты
  `create` и `:key/edit`; сервис — `create`, `update`, `get`, `remove`.
- Экран списка: кнопки «Добавить задание», «Изменить», «Удалить» (подтверждение `DialogService`).
- Экран пакета: в сверке строка «удалены на этом стенде: N (не вернутся)».

Сайт не меняется: задания он уже читает с бэкенда.

## Тесты

- **backend:** создание (id `<уровень>_<NNN>` после удалённых, конец уровня, сразу показано), правка (тип и поля
  меняются, уровень — 400), удаление (не отдаётся, номер не переиспользуется, повторно 404), выгрузка удалённого
  как `active: false`, заливка не воскрешает удалённое и кладёт его в `deletedHere`; доступ — только ADMIN.
- **web-admin:** форма каждого типа собирает верное тело; правильный ответ выбирается отметкой; уровень не
  редактируется в правке; ошибки бэкенда показываются списком; удаление спрашивает подтверждение.

Практики (каждый — свой дизайн по шаблону этапов 1–2); релиз в прод (после этапа 2, общим develop → main).
