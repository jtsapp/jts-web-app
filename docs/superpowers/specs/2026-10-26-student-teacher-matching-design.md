## 1. Что уже есть и что меняем

26.10.2026 в develop выкачен подбор по ТЗ менеджера v1.0 (автор karakozhaev_zh):

- бэкенд `modules/matching` (`docs/manager-matching.md` бэкенда, миграция V427): карточка подбора
  `matching_cases` со статусами `tariff → self → sent → confirm → done` и боковыми `ask`, `help`, `change`;
  заявки до трёх учителей (`match_requests`), резерв часов на 24 ч, создание уроков при подтверждении,
  смена учителя (`teacher_change_requests`), отпуск учителя через `request_handoffs`, уведомления с тихими
  часами (колокольчик + Telegram/WhatsApp-очередь);
- ручки ученика `/student/matching` (= `/mobile/matching`): карточка, preferences, ask-manager, candidates,
  requests, confirm, change, handoffs;
- на сайте — панель `src/matching/TeacherMatchingPanel.jsx` в «Уроках» и компактно на «Главной».

ТЗ 08 перерисовывает сторону ученика целиком. Панель коллеги **заменяется**: с «Главной» блок уходит
(ТЗ: «Главная не меняется»), в «Уроках» вместо неё — короткая ссылка-карточка на «Мой учитель», пока учитель
не назначен. Файлы панели удаляются вместе с её тестом.

Два пути заявки (Ульдана, 26.10): (1) ученик выбирает сам — заявки уходят учителям, **и менеджеру приходит
сообщение**; (2) «Пусть менеджер подберёт» — заявка в доску менеджера, он подбирает через платформу. Путь (2)
в бэкенде уже есть; в (1) не хватает сообщения менеджеру — добавляем (§3.3).

## 3. Бэкенд (`feat/student-matching-v2`)

Модуль тот же — `modules/matching`. Номер миграции сверить с develop и открытыми PR **перед мержем** (на 26.10
последняя — V430; память flyway-number-race).

### 3.1 Миграция `V4xx__Student_matching_v2.sql`

```sql
ALTER TABLE matching_cases ADD COLUMN format varchar(16) CHECK (format IN ('platform','books','own'));
ALTER TABLE matching_cases ADD COLUMN format_changed_at timestamp;
ALTER TABLE matching_cases ADD COLUMN asked_at timestamp;
ALTER TABLE matching_cases ADD COLUMN reason_code varchar(32);
ALTER TABLE teacher_matching_profiles
  ADD COLUMN formats jsonb NOT NULL DEFAULT '["platform","books","own"]';
```

Часовой пояс ученика — уже существующее `users.timezone` (IANA), своей колонки не заводим.
Форматы учителя по умолчанию — все три: редактировать их будет сторона учителя (ТЗ 06), до этого фильтр
по формату ничего не отсекает. `TeacherPreferences` получает необязательное поле `formats` (старые клиенты
его не шлют → не трогаем сохранённое).

### 3.2 Ручки ученика (добавляются в `StudentMatchingController`, оба префикса)

| Ручка | Тело / ответ | Правила |
|---|---|---|
| `GET /` | `StudentCard` (см. ниже) | как сейчас, но без чужого: `history` пустая, у заявок нет `comment` |
| `PUT /preferences` | `+ format` | формат пишется в карточку; для гарантии/IELTS/SAT принудительно `platform` |
| `POST /ask-manager` | как сейчас | ставит `asked_at`; второй открытый запрос → 409 `already_asked`; разрешён и из `sent` — тогда активные заявки учителям отменяются (сайт до этого спросил подтверждение) |
| `PATCH /ask-manager` | `{wish}` | правка пожелания открытого запроса |
| `GET /grid?format=` | `{lessonDuration, lessonsPerWeek, formats:{platform,books,own}, slots:[{weekday,start,teacherIds[]}]}` | см. §3.4 |
| `GET /candidates` | `StudentCandidate[]` | только подходящие; после одобренной смены текущий учитель исключён; фильтр по формату |
| `GET /teachers/{id}` | `StudentTeacherProfile` | только учитель из подбора этого ученика (кандидат, заявка, предложение, назначенный) — иначе 404 |
| `GET /teachers/{id}/photo` | jpeg | то же правило доступа |
| `PUT /interests` | `{interests ≤ 5}` | в любом статусе; >5 → 400 |
| `PUT /timezone` | `{timezone}` | `ZoneId.of` проверяет; пишет `users.timezone` |
| `POST /counter` | `{slots}` | «Выбрать другое время», §3.5 |
| `POST /reconfirm` | — | «Подтвердить снова» после истечения: если часы ещё свободны — снова резерв 24 ч, иначе 409 `slot_taken` |
| `POST /format` | `{format}` | смена формата у назначенного, §3.6 |
| `POST /change` | как сейчас | + лимит: две одобренные смены за 90 дней → 409 `limit_reached` |

`StudentCard` = прежний `Card` плюс `format`, `timezone`, `askedAt`, `reasonCode`, `excludedTeacherId`,
`limits {formatChangeAvailableAt, teacherChangesLeft}`. Отдельный record, чтобы менеджерский `Card` не менялся.

`StudentCandidate`: `id, name, hasPhoto, yearsExperience, specializations (теги шапки резюме), about,
interests, formats, sinceYear (users.created_at), isNew (< 3 мес. в школе), ageGroup ('20–25' | '26–35' | '35+' |
null, из birthDate), languages, levels, matchPercent, slots (совпавшие), suggestedSlots`.
Числа учеников, лимита, последнего входа и пунктуальности ученику не отдаём (ТЗ §2.4).

`StudentTeacherProfile`: всё из `StudentCandidate` + опыт (таймлайн), образование, сертификаты (только название
и балл — без файлов), языки с уровнем, фокус, методы. **Телефона нет**, ссылки на публичное резюме нет: PDF
резюме бэкенда печатает телефон в блоке Contact, поэтому студенческий PDF собирает сайт (§4.6).

Ошибки — `409` с машинным кодом в теле (`code`) и русским `message` для показа: `tariff_pending`,
`not_enough_days`, `slot_taken`, `limit_reached`, `already_asked`, `guarantee`, `teacher_format`.

### 3.3 Изменения в существующем поведении

- `select()` — **сообщение менеджеру** в колокольчик админки: «Отправил(а) заявки: 1. … · 2. … · 3. …»
  (без внешних каналов).
- `help(...)` принимает код причины; тексты причин остаются прежними (доска менеджера их показывает).
- `reply()` учителя принимает ответ на заявку `student_counter`, пока карточка в `confirm` (§3.5).
- `expire()` гасит просроченные `student_counter`, не трогая основной резерв.
- Кандидаты: учитель с форматом не из `formats` → причина «Не ведёт выбранный формат».

### 3.4 Сетка времени

Для каждого учителя, прошедшего проверки без времени (роль, направление тарифа, 30 мин, резюме, лимит, перерыв
и отстранение — те же, что в `MatchingCandidateService.candidate`), берём его слоты из профиля и отбрасываем
занятые: уроки учителя в окне ближайших недель и чужие резервы читаются **одним запросом на учителя**, пересечение
считается в памяти (`MatchingSlots.overlaps`). Ответ — `teacherIds` по каждому слоту: по ним сайт сам считает
цифру в ячейке и «Показать учителей (n)» без новых запросов (ТЗ: ≤ 300 мс). `formats` — сколько учителей
доступно по каждому формату (карточки шага «Формат»).

Сетка — подсказка. Точная проверка остаётся в `select()`/`validate`: если время заняли, ответ 409 `slot_taken`,
сайт показывает «Это время уже заняли, выберите другое» и перечитывает сетку.

### 3.5 «Выбрать другое время»

`POST /counter {slots}` при статусе `confirm`: ровно `lessonsPerWeek` слотов в разных днях школы, каждый — из
общего времени (`availableSlots` ученика ∩ слоты учителя) и свободен. Создаётся заявка тому же учителю,
`source = student_counter`, срок 12 ч; **прежний резерв не снимается** до ответа. Учитель отвечает в своём
текущем окне (`/system/teacher-matching` видит заявку с выбранными слотами) — правок в админке нет.

- учитель принял **ровно эти слоты** → расписание подтверждается само (решение открытого вопроса 2 ТЗ), ученику
  «🎉 Ваш учитель — …»;
- принял с другими слотами → новый резерв 24 ч, ученик подтверждает;
- отклонил или истёк срок → прежний резерв остаётся, ученику «Учитель не может в это время. Прежнее время
  держится до {deadline}».

### 3.6 Смена формата

`POST /format` при `done`: гарантия → 409 `guarantee`; меньше 30 дней с прошлой смены → 409 `limit_reached`
(`availableAt` в теле); назначенный учитель формат не ведёт → 409 `teacher_format` (сайт уводит в смену учителя с
причиной «Хочу другой формат обучения»); иначе формат меняется, учителю уведомление, в историю — событие.

### 3.7 Тесты бэкенда

`MatchingStudentV2Test` (Mockito, как `MatchingServiceTest`): сетка (исключение занятых, 30-мин тариф,
формат), исключение текущего учителя, доступ к профилю учителя, интересы ≤ 5, counter (принял те же → done,
другие → confirm, отказ → прежний резерв), reconfirm, формат (гарантия, 30 дней, учитель не ведёт), лимит смен,
сообщение менеджеру в `select()`, санитизация карточки ученика. `MatchingSecurityTest` — новые ручки только
`STUDENT`.

## 4. Сайт (`feat/student-teacher-matching`)

Код раздела — `src/matching/`, стили — `src/matching.css` (префикс `mt-`), тексты — `src/matching/texts.js`
(ru / kk / en, как `src/feedback/labels.js`; в общий `i18n.jsx` идёт только `nav.myTeacher`).

### 4.1 Данные

- `src/api.js`: функции под все ручки §3.2 (прежние `getMatchingCase…` остаются).
- `src/matching/matchingStore.js` — одна карточка на вкладку: кэш по токену, опрос раз в 30 с (ТЗ 2.1.1:
  тариф подтвердили, пока ученик на экране), `refresh()` после действий, подписка через `useSyncExternalStore`.
  Его читают меню (бейдж), экран, профиль и окна — без повторных запросов.
- Ручки нет (старый бэкенд, 404 без нашего текста, сеть) → `unavailable`: пункта меню нет, экран говорит
  «Раздел скоро появится». Так прод со старым бэкендом ничего не покажет.

### 4.2 Время и слоты — `src/matching/slots.js` (расширяем файл коллеги)

Пояс ученика: `card.timezone` → иначе пояс устройства. Слот — `{weekday 1–7, start 'HH:MM:SS'}` в UTC. Строки
сетки — старты в поясе ученика 07:00–22:00 (тариф 60 — каждый час, 30 — каждые полчаса), каждая ячейка
переводится в UTC с днём вместе (смещение пояса считает `Intl` на текущую неделю). «Разные дни» считаются по
дню школы (Алматы) — тем же правилом, что `MatchingSlots.validate` на сервере, иначе кнопка разрешала бы то, что
сервер отвергнет. Чистые функции: `gridRows`, `toUtcSlot`, `slotLabel(slot, tz, lang)`, `schoolDays`,
`teachersFitting`, `bestCells`.

## 5. Решения по открытым вопросам ТЗ (§7.4)

## 6. Не делаем в этой итерации

- Выбор конкретного временного учителя учеником: «Временный учитель» записывает выбор, учителя подбирает
  менеджер (бэкенд не отдаёт ученику свободных учителей на период).
- Привязка Telegram/WhatsApp из настроек, push (приложения нет).
- Видео-знакомство, галерея результатов, посещаемость — до стороны учителя (ТЗ 06).
- Фичефлаги сайта: роль флагов играет бэкенд (`matching.features.*`) и наличие ручек; своих флагов нет.
