# «Грамматика · игры» и «Скорочтение» — два новых раздела «Практики»

Дата: 25.10.2026. Источники:

- ТЗ «Грамматика, игры по грамматике и Скорочтение в кабинете студента», v1.1 от 24.10.2026
  (автор — Тилек Жаркенов, Sunekesh), PDF прислан в чате 25.10.2026;
- прототипы `jts-grammar-games.html` (3,9 МБ) и `jts-student-cabinet.html` (4 МБ), присланы 25.10.2026;
- ответы заказчика на вопросы по ТЗ (25.10.2026).

ТЗ писалось под прототип кабинета, а не под наш сайт, поэтому ниже оно переложено на стек
и правила этого репозитория. Где ТЗ расходится с решениями заказчика, действуют решения. Где
ответа нет, действует допущение из раздела «Допущения»: каждое помечено кодом **Д1…Д17**,
и на этот код ссылаются места спеки, которые от допущения зависят.

## Что это

**«Грамматика · игры»** — отдельный модуль «Практики»: 125 тем на 5 уровнях (L1 «0 → A1» …
L5 «B2 → C1»). Тема открывается с правила: 3D-карточки формул из цветных «кирпичиков»,
таблицы, типичные ошибки. Дальше идёт сетка из 11–13 игр, последняя из них всегда «Финальный
бой» Декстера со Спарком. Любое английское слово на экране кликабельно: перевод RU/KZ,
озвучка слова и предложения, «В словарь». У каждой игры есть звёзды 0–3, монеты начисляются
за улучшение результата.

**«Скорочтение»** — тренажёр во вкладке «Аудирование». Ученик выбирает текст и скорость
0,5x–3x и слушает образец с подсветкой слов. Потом читает вслух текст, который сам едет
вверх (телесуфлёр), и получает результат: процент прочитанного, звёзды, свой темп и свою
запись.

## Решения заказчика (25.10.2026)

1. **Старая «Грамматика» остаётся как есть.** 507 юнитов A0–C1 и выданные по ним домашние
   задания не трогаем. Новый модуль с ними не связан. Плитка называется **«Грамматика ·
   игры»**.
2. **Ошибки игр нигде не сохраняются и никуда не отправляются.** Хранится только лучший
   результат (звёзды). Раздела ошибок нет. Тропу курса «Повторение» модуль не затрагивает.
   Страница «Повторение» из прототипа в работу не входит.
3. **Токены = наши монеты**, та же валюта, что во всём кабинете. Лимит 40 из прототипа на
   проде не делаем. Отдельного лимита для двух модулей нет: начисления идут в общий лимит
   Практики. Сколько монет за какую игру, задаёт контент-менеджер.

## Прототипы: что в них

Оба файла — один `<script>`, данные лежат JS-литералами, внешних адресов нет, кроме Google
Fonts. Грамматика в обоих файлах одна и та же: `TOPICS`, `GLOSS`, `IMG` и `EMO` совпадают байт
в байт, у кабинета переименованы только функции шапки (`gTopbar`, `gSetLang`, `gRender`).
Поэтому источник для Грамматики — `jts-grammar-games.html`, а из кабинета берём только
Скорочтение (`SR_*`, `pSpeed`, `sr*`) и таблицу монет `GT_PTS`.

| Блок | Объём | Что |
|---|---|---|
| `const LEVELS=[…]` | ~1 КБ | 5 уровней: id, диапазон, название, наклейки, градиент — JSON |
| `const PROGRAM=[…]` | ~10 КБ | 125 строк программы `JTS_Grammar_Topics` — JSON |
| `const TOPICS=[…]` | 2 МБ | 125 тем (L1 26, L2 25, L3 25, L4 24, L5 25) — JSON, форма ниже |
| `const GLOSS={…}` | 85 КБ | общий словарь кликабельных слов: 2163 слова, `[ru, kk]` |
| `const IMG={…}` | 300 КБ | 7 картинок маскотов webp: dexter, spark, cheer, read, run, sleep, fly |
| `const EMO={…}` | 1,2 МБ | 563 эмодзи Apple webp, ключ — сам символ |
| `const GAMES={…}` | ~3 КБ | 13 игр: эмодзи, название и описание ru/kk/en |
| движок | ~66 КБ JS + 35 КБ CSS | хаб, правило, окно слова, 13 игр, звуки Web Audio, конфетти |
| `SR_TEXTS` (кабинет) | ~8 КБ | 8 текстов скорочтения: id, уровень, эмодзи, название ru/kk/en, текст |
| `sr*`, `pSpeed` (кабинет) | ~12 КБ | экран Скорочтения: выбор, образец, запись, выравнивание, итог |

Тема (`TOPICS[i]`): `id, lv, n, icon, color, title/sub/intro {ru,kk,en}`, `cards[4–5]
{h, f:[[код, текст]], more, ex[]}`, `tables[1–2] {cap, head, rows}`, `mistakes[4–5] {bad, good,
why}`, `gap[12–16] {s, a, o[2], pic}`, `order[10–12] {s, x, pic}`, `fix[8–11] {s, w, c, o[3]}`,
`pairs {task, list[6–8]}`, `trans[8–10] {from, task, to, o[2]}`, `dialog {title, lines[8–12]
{who, t, a?, o?}}`, `catch {task, right[], wrong[]}` — у всех тем; `sort {task, cats[2–4],
items[[слово, индекс]]}` — у 124 (нет у L2-22); `place[] {item, s, z}` — у двух (L1-10, L2-13).
Своего словаря у тем нет (поле `gloss` из ТЗ необязательно), общий — `GLOSS`.

У «Впиши сам», «Слушай и выбирай», «Гонки» и «Финального боя» своих данных нет: движок
собирает их из `gap`. Набор игр темы (`stagesOf`): `pick, match, [sort], build, trans, fix,
[place], type, dialog, listen, race, [catch], boss`. Так выходит 12 игр у 122 тем, 13 — у
L1-10 и L2-13, 11 — у L2-22.

Крючки движка для сайта уже есть: `HOOK.finish(topic, stage, stars)`, `HOOK.mist({tid, p, o,
a})`, `HOOK.popBtn(word, key, tr)`. Таймеры и анимации гасит счётчик поколений `stopLoops()`.

## Общая схема

Обе части устроены, как Prepositions World и «Чтение»: материал и прогресс лежат на
**бэкенде**, правит их **web-admin**, а **сайт** рисует движок прототипа почти дословно в Shadow
DOM. Монеты начисляет только бэкенд — по своим настройкам и своему прогрессу; клиент присылает
только звёзды. Порядок мержа — бэкенд → web-admin → сайт. Без загруженного материала сайт
показывает «Раздел готовится», поэтому мерж сайта ничего не ломает.

## Часть A. «Грамматика · игры»

### A1. Бэкенд — модуль `grammargames`

Образцы — модули `prepositions` (заливка прототипа), `practice-reading` (строки с телом JSON,
правка по одной) и `listen` (прогресс, монеты).

**Таблицы** (одна миграция, номер — следующий свободный; на 25.10 последняя в develop — V410,
значит **V411**; сверить с develop перед мержем):

- `grammar_game_topics` — `id varchar(8) pk` (`L1-01`), `level varchar(2)`, `n int`, `title_ru
  text` (для списка админки), `hidden boolean default false`, `body text` (тема JSON целиком,
  как `body` у «Чтения»), `updated_at`, `updated_by → users ON DELETE SET NULL`; индекс
  `(level, n)`.
- `grammar_game_meta` — одна строка (`id integer pk check (id = 1)`): `levels text`, `program
  text`, `gloss text` (JSON), `updated_at`, `updated_by`.
- `grammar_game_progress` — `id bigserial pk`, `user_id → users ON DELETE CASCADE`, `topic_id
  varchar(8)` (без внешнего ключа: перезаливка темы не должна стирать прогресс), `game
  varchar(8)`, `best_stars integer`, `attempts integer`, `last_played_at`; уникальный ключ
  `(user_id, topic_id, game)`.
- `practice_coin_rules` — `rule_key varchar(48) pk`, `coins integer check (coins between 0 and
  10)` (Д1), `updated_at`, `updated_by`. В миграции заводятся строки `grammar-games.pick … .boss`
  со значениями `GT_PTS` прототипа (Д3). Таблица общая: в неё же пишет Скорочтение (Часть B),
  а в будущем — любой раздел с настраиваемой наградой.

**Заливка** `POST /admin/grammar-games/upload` (multipart `file`; роли ADMIN, CONTENT_MANAGER):

1. Разбор. Файл `.html` — строки `const LEVELS=`, `const PROGRAM=`, `const TOPICS=`, `const
   GLOSS=` читаются Jackson'ом (все четыре — валидный JSON) через `shared/util/JsLiterals`. Файл
   `.zip` — `levels.json`, `program.json`, `gloss.json`, `L<n>/<NN>.json` (формат ТЗ §5.1). Чего
   нет — ошибка «в файле нет …».
2. Проверка (`GrammarTopicValidator`): любая ошибка отклоняет всю заливку, ответ — список
   «тема · поле · что не так», в базу ничего не пишется. Правила (Д17):
   - `id` — `^L[1-5]-\d{2}$`, `lv` совпадает с префиксом `id`, `n` — номер из `id`, `id` не
     повторяются;
   - `title`, `sub`, `intro` — непустые `ru`, `kk`, `en`;
   - `cards` ≥ 1: `h{ru,kk,en}`, `f` — пары `[код, текст]`, код ∈ `s v a n q o`, `ex` ≥ 1;
   - `tables`: длина каждой строки = длине `head`; `mistakes` ≥ 1: `bad`, `good`, `why{ru,kk,en}`;
   - `gap` ≥ 12: в `s` ровно один `___`, `o` — две строки, `a` нет среди `o`;
   - `order` ≥ 10: `x` не слово из `s`; `fix` ≥ 8: `w` — индекс слова `s`, `o` — три строки,
     `c` среди `o`;
   - `pairs.list` — от 6 до 8 пар; `trans` ≥ 8: `o` — две строки, `to` нет среди `o`;
   - `dialog.lines` ≥ 8, из них ≥ 5 с `a`; у реплики с `a` в `t` есть `___`, `a` нет среди
     `o`; `who` ∈ `A B`;
   - `catch.right` и `catch.wrong` непустые; `sort` (если есть): индекс категории < числа
     `cats`; `place` (если есть): `z` ∈ `on in under next between front behind`.

   Предупреждения (заливка проходит, список — в ответе): тема из `PROGRAM` без темы в
   `TOPICS`; эмодзи `icon`/`pic` без картинки в наборе сайта не проверяются — у сайта для них
   есть запасной путь (Д8).
3. Запись в одной транзакции (это сотня строк, без медиа): темы — upsert; у существующей темы
   флаг `hidden` не трогаем, новая берёт его из поля `hidden` файла (оно есть в выгрузке), иначе
   видима; поле `hidden` в тело темы не попадает; темы, которых нет в файле, остаются как есть
   (заливка ничего не удаляет); `meta` — заменяется. Затем сбрасывается кэш. Ответ: `{topics, created, updated, unchanged, warnings}`.

**Правка из админки:**

- `GET /admin/grammar-games/topics?level=L1` — `[{id, n, icon, titleRu, hidden, games,
  updatedAt}]`;
- `GET /admin/grammar-games/topics/{id}` — тело темы;
- `PUT /admin/grammar-games/topics/{id}` — тело темы, та же проверка, `id` в теле = `id` в
  адресе;
- `PATCH /admin/grammar-games/topics/{id}` — `{hidden}`;
- `GET /admin/grammar-games/export` — zip того же формата, что принимает заливка (скрытые темы
  входят, с полем `"hidden": true`);
- `GET /admin/practice/coin-rules`, `PUT /admin/practice/coin-rules` — `{key: coins}`, значения
  0–10.

**Ученику** (Bearer):

- `GET /mobile/grammar-games` → `{levels, program, topics: [{id, lv, n, icon, color, title,
  sub, games}]}`, только видимые темы. До первой заливки — `404`;
- `GET /mobile/grammar-games/topics/{id}` → тело темы; скрытая или несуществующая тема —
  `404`;
- `GET /mobile/grammar-games/gloss` → `GLOSS`;
- `GET /mobile/grammar-games/progress` → `{stars: {<topicId>: {<game>: 0–3}}}`;
- `POST /mobile/grammar-games/result` — `{topicId, game, stars}`. Сервер проверяет, что тема
  видима, `game` входит в её набор игр (то же правило `stagesOf`, что у движка) и `stars` ∈
  0–3. Затем: `best = max(старое, stars)`, `attempts + 1`, `last_played_at = now`;
  `coins = coinsFor(game, best) − coinsFor(game, старое best)` (Д2, Д3). Если `coins > 0` —
  `CoinsService.credit(user, coins, EARN_ACTIVITY, "Грамматика · игры: <title.ru> · <игра
  ru>")` и столько же XP (`XpService.awardXp`): так начисляет вся остальная «Практика» через
  `completeLessonModule`. Если `stars > 0` — `mobileStreakService.registerActivity(user)`:
  стрик держит любая доигранная игра, а не только улучшение. Ответ — `{best, coins, balance}`.
  Первую запись двух одновременных сдач ловит уникальный ключ: вторая получает `409` и
  повторяется сайтом, монеты дважды не приходят.

Список, тема и словарь кэшируются в памяти до следующей записи из админки.

**Тесты** — на Mockito, без WebMvc-срезов (они красные из-за `IeltsAccessInterceptor`).
Html-фикстуру собирает сам тест. Проверяются: парсер html и zip, каждое правило проверки,
upsert без удаления и без смены `hidden`, `coinsDelta` (первая игра, улучшение, повтор без
улучшения, бой), набор игр темы с `sort`/`place` и без них, отказ в чужой игре и в скрытой
теме, ограничение 0–10 у правил монет. Настоящий прототип — необязательным тестом по
переменной `GRAMMAR_GAMES_HTML` (125 тем проходят проверку).

### A2. web-admin — «Практика и тесты» → «Грамматика · игры»

По образцу `feature/system/listen` и `feature/system/practice-reading`:

- маршрут и карточка во вкладке «Практика и тесты»; роли ADMIN, CONTENT_MANAGER;
- «Загрузить» (`.html` или `.zip`), итог заливки (счётчики, ошибки списком, предупреждения);

## Часть B. «Скорочтение»

### B1. Бэкенд — модуль `speedreading`

**Таблицы** (своя миграция, номер — следующий после Части A):

- `speed_reading_texts` — `id varchar(48) pk` (8 текстов прототипа — их id: `hello`, `weather`…;
  новые — slug от названия со случайным хвостом, как у «Чтения»), `level varchar(2)`, `icon
  varchar(16)`, `title text` (JSON `{ru,kk,en}`), `body text`, `voice varchar(16)` (`uk-female`
  | `uk-male`), `hidden boolean`, `sort int`, `sample_hash varchar(64)`, `sample_url text`,
  `sample_words text` (JSON `[[слово, начало, конец], …]` в секундах), `sample_wpm int`,
  `sample_claimed_at`, `updated_at`, `updated_by`. Текст — до 225 слов: на 0,5x (75 сл/мин) это
  ровно 3 минуты, потолок записи (Д15). Тексты прототипа — от 80 до 117 слов.
- `speed_reading_attempts` — `id bigserial`, `user_id → users ON DELETE CASCADE`, `text_id`,
  `speed numeric(2,1)` (0.5–3.0), `duration_sec int`, `words_total int`, `words_read int`,
  `percent smallint null`, `stars smallint`, `wpm int null`, `scored_by varchar(8)` (`server` |
  `browser` | `none`), `coins smallint`, `created_at`; индекс `(user_id, created_at desc)`.
  Аудио нет (Д6).
- строка `speed-reading` = 4 в `practice_coin_rules` (Д16).

`sample_hash` — sha256 от `voice + "\n" + body`. Образец считается готовым, если хэш в строке
совпадает с текущим текстом. Правка текста делает образец устаревшим, но не удаляет его.

**Ученику** (Bearer):

- `GET /mobile/speed-reading/texts` → `[{id, level, icon, title, words, sample: {url, words,
  wpm} | null}]`; до первого текста — `[]`;
- `POST /mobile/speed-reading/attempts` — `{textId, speed, durationSec, wordsTotal, wordsRead,
  percent, stars, wpm, scoredBy}`. Проверка: текст есть, `speed` ∈ {0.5, 0.7, 1, 1.5, 2, 2.5, 3},
  `0 ≤ wordsRead ≤ wordsTotal`, `durationSec` ≤ 200, `stars` ∈ 0–3. Монеты — если `stars ≥ 1`
  и у ученика сегодня (по его часовому поясу, как `daily_xp`) ещё нет попытки этого текста с
  монетами (Д16). Ответ — `{attempt, coins, balance}`;
- `GET /mobile/speed-reading/attempts?limit=20` → свои попытки, новые сверху.

**Образцы — от сайта** (ключи синтеза есть только у сайта). Служебный ключ
`speedreading.integration-key` — заголовок `x-integration-key`, по образцу
`/integrations/web/ge-activity`:

- `POST /integrations/web/speed-reading/{id}/sample-claim` → `200 {ready: true, sample}`, если
  образец актуален; `200 {ready: false, voice, body, hash}` с отметкой `sample_claimed_at = now`,
  если его нет или он устарел; `409`, если его уже готовит другой запрос (отметка моложе 90 с);
- `PUT /integrations/web/speed-reading/{id}/sample` — multipart `audio` (mp3) + `words` (JSON) +
  `hash` + `wpm`. Файл ложится в `practice/speed-reading/<sha24>.mp3` через
  `PracticeMediaStorage` (`SECTIONS += "speed-reading"`, immutable). Строка обновляется, только
  если `hash` всё ещё совпадает с текстом (текст могли поправить за время синтеза). Ответ —
  `{sample}`.

**Админке:**

- `GET /admin/speed-reading/texts`, `POST`, `PUT /{id}`, `PATCH /{id}` (`hidden`, `sort`) — роли
  ADMIN, CONTENT_MANAGER; новый текст создаётся скрытым (как у «Чтения»);
- `POST /admin/speed-reading/texts/import` — JSON-массив в форме `SR_TEXTS` прототипа (`{id, lv,
  ic, t:{ru,kk,en}, x}`): существующие id обновляются, новые создаются;
- `GET /admin/students/{id}/practice-summary` — роли TEACHER (только свои ученики, через
  `teacherstudent`), CURATOR, MANAGER, ADMIN → `{speedReading: [последние 20 попыток с
  названием текста], grammarGames: [{level, stars, maxStars, topicsStarted}]}`.

**Тесты** (Mockito): проверка попытки, монеты раз в день на текст, часовой пояс, `sample-claim`
(готов / устарел / занят), `PUT sample` при сменившемся хэше, импорт, права на сводку
(чужой ученик → 403).

### B3. Сайт

**Экран и движок.**

- `?screen=speed-reading[&text=<id>]` — `src/screens/SpeedReadingPage.jsx`, ветка в `App.jsx`.
- Движок — `src/practice/speed-reading/engine.js`: экран Скорочтения кабинета почти дословно

- Чистые правила — `src/practice/speed-reading/rules.js`: `srNorm`, `srAlign` (жадное

  прокрутки (`слова ÷ (base × множитель)` мин, `base` = `sample.wpm` или 150), подпись «1x —
  темп носителя · N сл/мин · ≈ N секунд». Скорости — ровно `0.5, 0.7, 1, 1.5, 2, 2.5, 3`.

Отступления от прототипа:

| Прототип | Порт | Почему |
|---|---|---|
| `SR_TEXTS` в коде | `cfg.texts` с бэкенда | тексты из админки |
| образец — `speechSynthesis` (лучший голос браузера), подсветка — `onboundary` | запись ElevenLabs + `words`; `cfg.playSample(url, rate, onTime)` на общем `<audio>` через `playUrl` (`preservesPitch` там уже стоит); `playUrl` получает новую опцию `onTime(currentTime)` (кадры `requestAnimationFrame`, пока звук идёт), подсветка — по ней | ТЗ §4.2 и Д9 |

сервер.

При уходе с экрана `destroy` останавливает образец, запись, распознавание и таймеры, отпускает
дорожки микрофона и отзывает blob-адреса.

**Образец на сервере** — `src/app/api/practice/speed-reading/sample/route.js` (POST `{id}`,

3. `PUT sample` на бэкенд, ответ — `{url, words, wpm}`.
