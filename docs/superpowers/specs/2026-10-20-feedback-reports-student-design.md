# Отчёты о прогрессе: сторона ученика и контракт API

Раздел Feedback: раз в 30 дней преподаватель пишет каждому студенту личный
отчёт, координатор его проверяет, после одобрения отчёт уходит родителю
(WhatsApp/Telegram) и в кабинет студента. Этот документ — про то, что видят
**ученик и родитель**, и про ручки бэкенда, на которых это держится.

**Статус на 20.10.2026: веб сделан (ветка `feat/feedback-reports-student`),
бэкенд этапов 1–3 сделан** (backend, ветка `feat/feedback-reports`: §3 плюс
задачи, форма преподавателя и проверка координатора — спека
`docs/superpowers/specs/2026-10-20-feedback-reports-teacher-coordinator-design.md`
там же), web-admin — ветка `feat/feedback-reports`. Выкат: бэкенд первым, затем
web-admin и этот веб. Доставка родителю — этап 4, не начат.

Источники:

- ТЗ «Feedback раздел» (Notion, «ТЗ: раздел Feedback студенту»);
- прототип `data/jts-progress-report.html` (снят с артефакта «JTS Progress
  Report»): кабинет преподавателя и координатора, ученику достаётся правая
  колонка — «живое превью отчёта» (`render()` прототипа);
- решение руководства (20.10.2026): отчёт каждые 30 дней от первого урока,
  12 в год; 48 ч на написание → проверка координатором → автоматически
  родителю и в кабинет студента.

Вне этого документа: форма преподавателя, очередь и дедлайны, проверка
координатором, сводка, контакты в карточке студента (web-admin); задачи раз
в 30 дней, рассылка в мессенджеры, статусы доставки (бэкенд).

## 1. Что видит ученик и родитель

1. **Отчёт по ссылке** из WhatsApp/Telegram — `/report/<token>`, без входа в
   аккаунт. Отдельный маршрут Next, как `trial/[token]`: без сайдбара, входа и
   остального приложения.
2. **Вкладка «Отчёты» в «Уроках»** — рядом с «Онлайн» и «Самостоятельно».
   Список отчётов, новые помечены; клик открывает отчёт тем же видом.
3. **Сигнал о новом отчёте:** уведомление в колокольчике (ведёт во вкладку,
   сразу в отчёт) и карточка на «Главной», пока есть непросмотренный отчёт.

Вид отчёта один на обе точки входа и совпадает с превью у преподавателя:

| Блок | Содержимое |
|---|---|
| Шапка | «Отчёт о прогрессе · 2-й месяц (дни 31–60)», имя, формат · «Пройдено: Unit 2 — Lessons 1–6», бейдж уровня (A1) |
| Мотивация | фиолетовая плашка: фраза преподавателя + бейджи (§4); нет ни фразы, ни бейджей — блока нет |
| Цифры | две плитки: «8/9 · Посещаемость · 89%» и «85% · Домашние задания» |
| Навыки | 6 полос (Говорение, Аудирование, Чтение, Письмо, Грамматика, Лексика), «4/5» и динамика ↑1 / ↓1 к прошлому отчёту |
| Сильные стороны, над чем работаем | списки |
| Цели прошлого отчёта | цветная точка + статус (Достигнута / Частично / Не достигнута); в первом отчёте блока нет |
| Цели на следующие 30 дней | список |
| План | текст |
| Подпись | «Преподаватель: …» |

Подписи — на **языке отчёта** (`lang`: ru/kk/en), а не интерфейса: отчёт
пишется для родителя на его языке, и ссылку он открывает без аккаунта.
Таблицы подписей берём из прототипа (`T`, `GT`, `GSTL`, `SNAME`). Свободный
текст преподавателя не переводится.

### Решения там, где ТЗ и прототип расходятся

ТЗ местами осталось от правила «отчёт каждые 7 уроков», которое руководство
заменило на 30 дней. Берём прототип:

- шапка — «N-й месяц (дни …)», а не «Уроки 8–14»;
- посещаемость — «проведено / запланировано», а не «X/7»;
- последний бейдж — «🏅 N мес. с JTS» (со 2-го отчёта), а не «N уроков позади».

---

## 2. Когда отчёт виден ученику

Отчёт появляется в кабинете и по ссылке **только после одобрения
координатором** — независимо от того, дошло ли сообщение в мессенджер
(контакта может не быть, канал может упасть). Черновики, отчёты на проверке
и возвращённые ученику не отдаются никогда.

## 3. Контракт API

### 3.1. Ручки

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /mobile/feedback-reports` | ученик (Bearer) | список его опубликованных отчётов, новые сверху |
| `GET /mobile/feedback-reports/{id}` | ученик (Bearer) | один отчёт; чужой — 404 |
| `POST /mobile/feedback-reports/{id}/seen` | ученик (Bearer) | ученик открыл отчёт в кабинете → `seenAt` (и `openedAt`, если пусто); 204, повтор — no-op |
| `GET /feedback-reports/link/{token}` | без входа (`permitAll`) | отчёт по ссылке из мессенджера |
| `POST /feedback-reports/link/{token}/opened` | без входа (`permitAll`) | ссылку открыли → `openedAt`, если пусто; 204, повтор — no-op |

Публичные ручки устроены как `/trial/link/{token}`: секрет ссылки и есть
авторизация. Отметка «открыт» — отдельным POST, а не побочным эффектом GET:
мессенджеры и антивирусы ходят по ссылкам сами (предпросмотр, проверка), и
GET с записью ставил бы «открыт» без родителя. Веб шлёт POST только после
того, как отчёт показан на экране.

Неизвестный, отозванный и неопубликованный токен — одинаково `404`: ответ не
должен подсказывать, что такой отчёт существует.

### 3.2. Отчёт (`GET …/{id}` и `GET …/link/{token}`)

```json
{
  "id": 123,
  "periodNo": 2,
  "periodStart": "2026-10-01",
  "periodEnd": "2026-10-30",
  "lang": "ru",
  "studentName": "Адэля Курманали",
  "teacherName": "Sunekesh Nurseitqyzy",
  "level": "A1",
  "format": "individual",
  "groupName": null,
  "unitsText": "Unit 2 — Lessons 1–6",
  "attendance": { "done": 8, "planned": 9 },
  "homeworkPct": 85,
  "skills": [
    { "key": "speaking",   "score": 4, "prev": 3 },
    { "key": "listening",  "score": 3, "prev": 3 },
    { "key": "reading",    "score": 4, "prev": 3 },
    { "key": "writing",    "score": 3, "prev": 2 },
    { "key": "grammar",    "score": 3, "prev": 3 },
    { "key": "vocabulary", "score": 4, "prev": 3 }
  ],
  "strengths": ["Активен на уроке", "Хорошо запоминает новые слова и уверенно использует их в диалогах."],
  "improvements": ["Времена глаголов", "Окончание -s в Present Simple (he works, she likes)."],
  "motivation": "Ты делаешь огромные шаги — так держать!",
  "badges": [
    { "type": "skills_growth", "n": 4 },
    { "type": "goals_achieved", "n": 2 },
    { "type": "months_with_jts", "n": 2 }
  ],
  "pastGoals": [
    { "text": "Выучить числа до 100", "result": "achieved" },
    { "text": "Рассказать о себе 5 предложениями", "result": "achieved" },
    { "text": "Домашка каждый урок", "result": "partly" }
  ],
  "nextGoals": ["Без ошибок в -s (he works)", "Выучить 30 новых слов"],
  "plan": "Unit 3: Present Simple — вопросы и отрицания, лексика «Daily routine».",
  "publishedAt": "2026-10-16T09:40:00+05:00"
}
```

- `lang` — `ru` | `kk` | `en`; неизвестное значение веб читает как `ru`.
- `format` — `individual` | `group`; у группы `groupName` — название группы.
  Отчёт всё равно личный: оценки, посещаемость, цели — этого студента.
- `level` — CEFR-код (`A0`…`C1`), как в остальном API.
- `skills` — ровно шесть ключей: `speaking`, `listening`, `reading`,
  `writing`, `grammar`, `vocabulary`; `score` 1–5. `prev` — оценка в прошлом
  отчёте, `null` в первом. Стрелку динамики веб рисует сам из `score − prev`.
- `strengths` / `improvements` — уже склеенные чипы и свой текст
  преподавателя, по пункту на строку.
- `motivation` — своя фраза преподавателя или выбранная из справочника,
  уже на языке отчёта; `null` — фразы нет.
- `pastGoals[].result` — `achieved` | `partly` | `not`; в первом отчёте массив
  пустой.
- `publishedAt` — момент одобрения координатором.

В ответе **нет** контактов, телефонов, каналов, статусов доставки,
комментариев координатора и истории правок: ссылку может переслать кто угодно.

Ответ кабинетной ручки (`/mobile/feedback-reports/{id}`) дополнительно несёт
`seenAt` (или `null`).

### 3.3. Список (`GET /mobile/feedback-reports`)

```json
[
  {
    "id": 123,
    "periodNo": 2,
    "periodStart": "2026-10-01",
    "periodEnd": "2026-10-30",
    "level": "A1",
    "teacherName": "Sunekesh Nurseitqyzy",
    "publishedAt": "2026-10-16T09:40:00+05:00",
    "seenAt": null
  }
]
```

Без пагинации: 12 отчётов в год на студента. Сортировка — `publishedAt` по
убыванию. «Новый» для ученика = `seenAt == null`.

### 3.4. Бейджи считает бэкенд

Бейдж виден в трёх местах: в отчёте у ученика, в превью у преподавателя
(web-admin) и в тексте сообщения WhatsApp/Telegram. Правило в одном месте —
на бэкенде; клиенты получают `type` и `n` и только подписывают их на языке
отчёта. Правила (прототип, `badges()`):

| `type` | Условие | Подпись ru / kk / en |
|---|---|---|
| `perfect_attendance` | `done > 0` и `done ≥ planned` | 🔥 Ни одного пропуска / Бірде-бір сабақ жібермеді / Perfect attendance |
| `homework_hero` | `homeworkPct ≥ 90` | 📚 Герой домашки / Үй тапсырмасының чемпионы / Homework hero |
| `skills_growth` | со 2-го отчёта выросли ≥ 2 навыка; `n` — сколько | 📈 Рост в N навыках / N дағдыда өсті / Grew in N skills |
| `goals_achieved` | ≥ 2 прошлых целей `achieved`; `n` — сколько | 🎯 N цели достигнуто / N мақсат орындалды / N goals achieved |
| `months_with_jts` | `periodNo ≥ 2`; `n = periodNo` | 🏅 N мес. с JTS / JTS-пен N ай / N months with JTS |

Порядок в массиве = порядок показа. Неизвестный `type` веб пропускает молча:
бэкенд может добавить бейдж раньше, чем выйдет веб.

### 3.5. Уведомление

При публикации отчёта бэкенд кладёт ученику уведомление (`app_notifications`):

- `type`: `FEEDBACK_REPORT` (новое значение `NotificationType`;
  `app_notifications.type` — VARCHAR без справочника, миграция не нужна);
- `title` / `message`: «Новый отчёт о прогрессе» / «Преподаватель <имя>
  подготовил отчёт за 2-й месяц»;
- `deepLink`: `feedback-reports/<id>`.

Мобильное приложение читает те же уведомления; незнакомый ему `deepLink`
оно должно просто не открывать.

### 3.6. Для бэкенда — что ещё решить

- Токен ссылки — случайный, не короче 128 бит, URL-safe; выдаётся при
  одобрении и не меняется при повторной отправке. Ссылку собирает бэкенд из
  адреса веба стенда: `<APP_PUBLIC_URL>/report/<token>`.
- Срок жизни ссылки в ТЗ не задан. Предложение: бессрочная, пока отчёт не
  отозван (родитель возвращается к прошлым отчётам).

## 4. Веб: как устроено

```
src/feedback/
  reportShape.js      разбор ответа API → объект отчёта (терпим к пропускам)
  labels.js           подписи ru/kk/en: блоки, навыки, статусы целей, бейджи, период
  sample.js           образец отчёта из прототипа (для ?reportSample=1 и /report/sample)
  ReportView.jsx      вид отчёта (один на ссылку и кабинет)
  ReportsTab.jsx      вкладка «Отчёты» в «Уроках»: список + открытый отчёт
  NewReportCard.jsx   карточка на «Главной»
src/app/report/[token]/page.jsx + ReportLinkClient.jsx   публичный маршрут
src/feedback.css                  стили раздела, вместе с правилами ≤560px (подключить в layout.jsx)
```

Мобильные правила — в `feedback.css`, а не в `src/mobile/`: тот слой — по
кадру Figma «Web Адаптивка» на секцию, а у раздела кадра нет.

- `api.js`: `getFeedbackReports`, `getFeedbackReport`, `markFeedbackReportSeen`
  (Bearer) и `getFeedbackReportByToken`, `markFeedbackReportOpened` (без
  токена).
- `reportShape.js` по образцу `comicsShape.js`: пустые массивы вместо
  отсутствующих, навыки в фиксированном порядке, `score` вне 1–5 — навык без
  полосы, а не падение.
- `LessonsPage`: вкладка `reports` в `TABS`, подпись в том же словаре, что и
  у «Онлайн»/«Самостоятельно». Вкладка видна ученикам, у аккаунта
  преподавателя её нет (у него своя вкладка «Домашние»); пустой список —
  «Отчётов пока нет» с объяснением «Преподаватель присылает отчёт раз в
  месяц».
- `studentDeepLink.notificationTarget`: ветка `feedback-reports/<id>` →
  `{ screen: 'lessons', payload: { tab: 'reports', reportId } }` — **до**
  ветки `includes('lesson')`, иначе её перехватит общий переход в «Уроки».
- Отметка: кабинет шлёт `seen`, публичная страница — `opened`, один раз за
  показ, после рендера отчёта. Ошибка отметки ученику не показывается.
- Публичная страница: `robots: noindex, nofollow`, `Referrer-Policy:
  no-referrer` (токен не должен утечь в заголовке Referer по ссылкам со
  страницы). Без входа, без загрузки остального приложения.
- Шрифт и цвета — по правилам приложения (Manrope на десктопе, PT Root UI в
  мобильном слое); фиолетовый `#9047ff` и раскладка блоков — из прототипа.

### Если ручек нет (стенд со старым бэкендом)

- Веб выкатывается после бэкенда, но стенд может отстать: список отвечает 404 →
  вкладка показывает «Отчётов пока нет», а не сбой; ссылка → «Ссылка
  недействительна».
- `?screen=lessons&tab=reports&reportSample=1` и `/report/sample` рисуют
  `sample.js` без сети — посмотреть вид, пока живых отчётов нет. Только на
  локалке и дев-стендах (тот же признак адреса, что у `?ieltsSample=1`): на
  проде ученик, дописав параметр, увидел бы выдуманный отчёт как свой.
- Список спрашивает и карточка «Главной» на каждом заходе, поэтому 404 веб
  помнит 10 минут на токен (как `getIeltsMe`) — бэкенд не получает ошибку со
  стеком на каждый заход ученика.

### Ошибки

| Ситуация | Что видно |
|---|---|
| Ссылка: 404 | «Ссылка недействительна. Попросите школу прислать отчёт ещё раз.» |
| Ссылка: сеть/5xx | «Не удалось загрузить отчёт» + «Повторить» |
| Кабинет: список — 404 (ручки ещё нет) | «Отчётов пока нет», как при пустом списке |
| Кабинет: список — сеть/5xx | «Не удалось загрузить отчёты» + «Повторить» |
| Отметка `seen`/`opened` упала | ничего; повторится при следующем открытии |
