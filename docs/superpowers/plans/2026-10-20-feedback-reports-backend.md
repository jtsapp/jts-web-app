## Что в бэкенде уже есть и на что опереться

| Нужно | Где есть образец |
|---|---|
| Модуль «таблица + сервис + mobile/admin-контроллеры» | `modules/karaoke` + `presentation/{mobile,admin}/karaoke` |

| Посещаемость | `lesson/model/ParticipantStatus`: SCHEDULED, ATTENDED, CANCELLED_FREE, CANCELLED_BURNED, NO_SHOW_BURNED; урок `LessonStatus.COMPLETED` |

**Чего нет:** контактов родителя (телефон, канал, chat_id, отписка) — ни
полей, ни таблицы; WhatsApp — никакой интеграции.

## Решения, уже принятые (не пересматривать без причины)

- Ученику и по ссылке отдаётся только отчёт, ОДОБРЕННЫЙ координатором.
- Форма ответа — §3.2/§3.3 спеки; в ответе нет контактов, телефонов,
  каналов, комментариев координатора.
- Бейджи считает бэкенд (§3.4: правила и `type`), клиенты только подписывают.
  Они же нужны превью web-admin и тексту WhatsApp — правило в одном месте.
- Токен ссылки — случайный ≥128 бит, URL-safe, выдаётся при одобрении, не
  меняется при повторной отправке. Неизвестный/отозванный/неопубликованный —
  одинаковый 404.
- «Открыт» и «просмотрен» — отдельные POST (`…/opened`, `…/{id}/seen`), не
  побочный эффект GET: мессенджеры сами ходят по ссылкам.
- Уведомление: `FEEDBACK_REPORT`, `deepLink: feedback-reports/<id>` (веб уже
  разбирает).
- Ссылку строит бэкенд: `<APP_PUBLIC_URL стенда>/report/<token>`.

## Этапы

### Этап 1 — разблокировать веб (делать первым)

Цель: веб без правок показывает живые отчёты на dev-стенде.

- Миграция: `feedback_report` (поля — спека ТЗ «Сущности» + §3.2: период,
  lang, attendance done/planned, homework_pct, units_text, skills jsonb
  {key, score}, strengths/improvements, motivation, plan, status
  draft/in_review/returned/approved/ready_no_contact/sent, public_token,
  published_at, opened_at, seen_at, student_id, teacher_id, group_id?) и
  `feedback_goal` (report_id, text, result). `prev` у навыков — из прошлого
  отчёта этого студента, а не хранится.
- Ручки ученика по §3.1: `GET /mobile/feedback-reports`,
  `GET /mobile/feedback-reports/{id}` (чужой — 404),
  `POST /mobile/feedback-reports/{id}/seen`,
  `GET /feedback-reports/link/{token}`, `POST /feedback-reports/link/{token}/opened`
  (две последние — `permitAll`).
- Сервис бейджей по §3.4 с юнит-тестом на таблицу правил.
- При переходе в `approved` — уведомление `FEEDBACK_REPORT`.
- Способ завести отчёт до появления формы: временная админ-ручка или сид на
  dev (одобренный отчёт на тестового ученика) — чтобы проверить веб вживую.
- Готово, когда: e2e веба проходит против dev-бэкенда без моков ручек;
  `/report/<token>` открывает реальный отчёт; 404 для чужого id и токена.

### Этап 2 — преподаватель (бэкенд + web-admin)

- Задачи на отчёт (`feedback_task`): каждые 30 дней от первого урока
  ученика; у группы — от старта группы, отчёт на каждого; присоединившийся
  позже — с группой, если ≥4 уроков, иначе в следующий период; цикл не
  сбрасывается; при смене преподавателя пишет текущий. Нет уроков за период —
  отчёта нет, задача менеджеру; уроков < половины — отчёт + уведомление
  менеджеру. Часовой пояс Asia/Almaty.
- Дедлайн 48 ч (настраивается), напоминание за 24 ч, статусы очереди (не
  наступил / в работе / срочно / просрочен / сдан вовремя / с опозданием).
- Автополя формы: посещаемость «проведено из запланированного» по
  `ParticipantStatus` (отменённые не считаются), домашки % из Homework,
  пройденное.
- Черновик на сервере, «Отправить на проверку», «Готов, ждёт контакта».
- web-admin: очередь «Пора написать feedback», форма с живым превью (вид —
  тот же, что у ученика; бейджи — от бэкенда), панель группы «N/M написано».

### Этап 3 — координатор

- Очередь «На проверку» (старые сверху), одобрить / исправить и одобрить
  (правки в истории, видны преподавателю) / вернуть с обязательным
  комментарием (24 ч на исправление); «Одобрить выбранные» для группы.
- Срок проверки 24 ч, счётчик «Ждут проверки».
- Сводка по преподавателям: вовремя / в работе / просрочено, дисциплина %
  (≥90 зелёный, 70–89 оранжевый, <70 красный), недоставленные, «Напомнить»
  (платформа + Telegram), экспорт месяца в Excel. Справочники фраз, целей,
  чипов (RU/KK/EN).

### Этап 4 — доставка родителю

- Контакты в карточке студента: родитель (имя, телефон +7XXXXXXXXXX, канал),
  студент (необязательно), получатель по умолчанию, язык, «Telegram
  подключён», отписка. Заполняет менеджер; преподаватель видит маскированный
  номер (+7 701 *** 45 67).
- Telegram: родитель жмёт Start по личной ссылке и делится номером → chat_id;
  отписка («СТОП» / кнопка). Сначала решить: расширять бота координатора
  (`modules/coordinator/telegram`, у него уже есть коды привязки, очередь и
  окно отправки) или отдельный бот JTS для родителей.
- WhatsApp Business API через провайдера, шаблоны сообщений на каждый язык,
  вебхуки статусов. Фолбэк на второй канал через 15 мин; не доставлено
  никуда — пометка в карточке и задача менеджеру.
- Сообщение ≤1000 символов: приветствие, фраза, бейджи, посещаемость и
  домашки, цели, ссылка на полный отчёт.
